## Desktop execution lane (required, non-read-only, VM remains sole authority)

This lane turns the existing read-only desktop composition into a bounded, VM-issued, non-read-only remote executor. Follow this order; do not resequence without reporting why.

1. **Settle the lease/attempt integration seam first (first baseline hour).** Reconcile existing RUN-level leases against VM-issued individual attempts. The VM must continue to own the DAG, independent review, gates, and final run status — a lease alone is not an approved attempt payload. If the bridge needs a persistent schema change, or cannot safely reconcile attempts against leases, report that as a critical-path blocker instead of silently widening tonight's scope.
2. **Reuse existing node/placement surfaces; add verified authenticated transport.** Reuse `dashboard/server/api/v1/routes.ts` node routes, `placement/leaseService.ts` and `reportService.ts` ports, `control/placementState.ts`, and the existing store. Production node identity, rate guards, and store bindings were NOT found by review — bind them through a verified authenticated transport. A node identity is bound to its own authenticated host and only its own live leases; it can never claim, renew, or report another host's lease or attempt. The local node-proxy identity model must not become a remotely spoofable header. Never handle credentials as objects.
3. **Add the smallest remote attempt adapter below the VM engine.** Bind the approved model, tool profile, workspace IDs/scopes, instructions, skills, and source context to host, lease, and attempt identity. Do NOT spawn that desktop attempt locally on the VM. The remote payload carries only server-approved recipe, tool-policy, and workspace IDs plus bounded attempt data — never an arbitrary executable, argv, or environment values. VM authority alone does not make arbitrary payload execution safe. Reports advance the correct attempt through canonical integration; only the VM decides a whole run is complete.
4. **Extend the desktop client/reporter/session host, do not replace them.** Reuse `placement/desktopClient.ts`, `desktopReporter.ts`, and `pty/windowsSessionHost.ts`. `runOnce` is currently a single cycle, and the reporter currently retains its original lease revision but does not renew it. Add supervised outbound claiming, renewal using the current revision, local capacity limits, permitted tool calls, and local writes. Claim polling and lease heartbeats are transport maintenance, NOT a second workflow scheduler — no desktop Manager, no desktop ops-queue claimant. The desktop resolves recipe/tool-policy/workspace IDs only through local trusted allowlists and rejects any injected command, argv, or env value even if a caller labels it a recipe.
5. **Upload the artifact desktop → VM through a scoped, bounded, hash-verified path (required build task, not a claim it already works).** The desktop uploads bounded artifact bytes plus the expected digest to a VM-owned staging/store location scoped to the authenticated host, run, and attempt. The VM validates scope, bytes, and digest before accepting an immutable artifact reference; the attempt report names that accepted reference/hash. Canonical integration must not release a dependent/reviewer or mark the producing result usable until the VM has verified those bytes. Authorized browser download reads the VM copy. Reuse a compatible existing transfer/read route if present; otherwise add the narrow transfer endpoint plus the existing scoped download. Never defer artifacts, widen the coordination outbox, or accept arbitrary local paths. Adversarial cases: a report naming absent bytes, hash mismatch, another host/run/attempt's artifact, and oversized or path-traversal payloads.
6. **Persist the minimum reconciliation state in existing owned state, not memory.** In-memory-only holds are inadequate. Expiry/partition must not automatically reassign work whose physical child state is unknown. Cancellation needs physical termination proof; otherwise hold and reconcile. Never promise exactly-once execution under network partitions.
7. **Test the golden path and the adversarial set.** Golden path: real VM assignment → permitted desktop tool/write → canonical dependent/reviewer → verified desktop artifact. Adversarial: forged identity, a node claiming another host's lease/attempt, injected executable/argv/env payloads presented as a recipe (must be rejected), forbidden paths/tools, stale revisions, replay, cancellation, disconnect, lease expiry, desktop restart, and VM restart. Require no duplicate execution while prior work is uncertain.
8. **Do not import card 455's rejected shortcuts.** Existing desktop source components and production gaps were sourced from card 455 (source-only), whose unsafe recommendations were REJECTED in its Result. Do NOT defer artifacts, keep holds only in memory, equate attempt completion with whole-run completion, or assume this is merely a few stubs. Tonight's estimate for this lane remains conditional on step 1's baseline-hour outcome.
