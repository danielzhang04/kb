# Instagram saved-video → kb build ideas

Corpus: 37 recently-saved Instagram reels on AI / agent tooling / dashboards, pulled from `instagram.com/danielzhangg_/saved`. Method: each reel was watched in full (frames + transcript vision), notes captured per video with frame/timestamp citations, then 90 raw candidate ideas were extracted (`candidates-A/B/C.md`) and here deduped, verified against the notes, and ranked for a major kb-platform overhaul. Every idea below traces to an on-screen artifact or verifiable technique — caption-only hype was dropped or marked. 90 candidates collapse to 30 build ideas plus a dashboard/UI reference catalog.

A recurring caveat: many of these reels are lead-magnet or grift content whose *narration* overpromises, but several show a genuinely useful UI or mechanism on screen. Where that is the case the report steals the artifact and ignores the pitch, and says so.

---

## TL;DR — top 5 to build

1. **Autonomy-graduation trust gate** — an agent earns the right to run a card class unsupervised only after a rolling grade record (e.g. 20 passes at ≥95%), and auto-loses it if the grade drops below 90%. Why now: kb already emits grades to `ledgers/` but nothing converts that history into a machine-decidable trust score that gates self-run — it is the missing piece that lets the fleet run wider without lowering the bar. Source: Da6kEv3JMY3 @00:39 (+ SkillTree autonomy ladder DbYh2P-MQnj @00:34).
2. **Git Timeline orchestration dashboard** — a wave-by-wave Gantt with a dependency graph, a live worktree lane that auto-clears on merge, and inline model-routing annotations, over the existing workflow-platform DAG. Why now: it is the single strongest "see what every agent is doing" surface in the whole corpus and maps directly onto kb's workflow platform + worktree-leasing discipline. Source: DXwl0ryhbgV @00:04, 00:23–00:25.
3. **Rubric-in-the-skill + bounded self-verify loop** — co-locate the grading criteria inside the work skill and run a work↔grade loop with a try-limit, so the human only ever sees passing output. Why now: kb's grading lives in inspector prompts and card acceptance, not inside the skill that does the work; embedding it makes every skill self-checking. Source: Dbi4ruODNlK @00:36–00:48 (+ "can success be verified?" gate Dbs0166h9ZB @00:28–00:31).
4. **Human-gate approval inbox/sidecar** — a triage surface that auto-clears routine items inline and escalates only flagged/high-impact ones to a side panel with the draft ready to Approve/Edit. Why now: kb enforces human gates (fyt GATE 1/2/3, T3 approvals) but surfaces them as prose cards; a batched approve/edit inbox operationalizes "human gates one at a time." Source: DcGmHU6NSjB @00:45–00:55 (+ DZErwKSCT2z @00:56–01:01, DbY9KatgSMi @00:08).
5. **Canonical metric-definitions semantic layer** — define every fleet metric (cost, budget, grade, `verified`, card status) exactly once as one source of truth that agents and dashboards cite instead of re-deriving. Why now: metric semantics are spread across `ledgers/`, `governance/`, and many agent prompts today; the reel reports Anthropic's own DS team went 21%→95% accuracy with this move. Source: DbQrgz6haNi @00:00–00:48.

## Ranked build ideas

Ranked by (impact on a major kb overhaul) × (feasibility), with kb-fit as a strong signal. Each idea names the real subsystem it touches and is honest about what kb already has.

### Build now

**1. Autonomy-graduation trust gate**
- mechanism: attach a rolling pass-rate to each (agent × card-class). Promotion rule from the reel: a job must pass its graded check 20 times at ≥95% before the system lets it self-run; if the running grade drops below 90% the privilege is revoked and the owner is notified. Compute the score from existing grade rows; store the trust state alongside `governance/risk-tiers`; the dispatcher consults it before allowing an unsupervised card.
- source: Da6kEv3JMY3 @00:39 (policy narrated); SkillTree 3-tier ladder DbYh2P-MQnj @00:34 (Human-led / Human-assisted / Fully autonomous framing).
- category: harness
- general merit: strong — turns "is this agent trustworthy yet?" into a number, the right antidote to premature autonomy. / kb fit: extends `ledgers/` grades + `governance/risk-tiers`; kb has honest three-state review and grade rows but **no automated promote/demote gate** driven by a rolling record — genuinely new mechanism on existing data. / size M. / honesty: the reel narrates this as an allegory (no product shown) but the rule is fully specified and buildable on kb's existing grade rows; SkillTree (DbYh2P) is a real running app.

**2. Git Timeline orchestration dashboard**
- mechanism: three phase tabs (Planning / Execution / Review&Merge). Planning renders a 4-stage pipeline (Research → PRD → Task Briefs → Dependency Graph) with a color-coded Gantt of stacked waves (green complete / orange waiting). Execution shows a feature-branch lane with per-wave progress bars, a live worktree list with auto-cleanup-after-merge, and an annotations panel documenting gate/merge cadence and model routing (Sonnet=simple, Opus=complex). Build it as a view over the workflow-platform DAG + git/worktree state.
- source: DXwl0ryhbgV @00:04, 00:23–00:25.
- category: ui-ux
- general merit: strong — the exact wave-Gantt + dependency-edges + live-worktree surface a fleet needs. / kb fit: extends the Next.js dashboard + workflow-platform (DAG, governedBy, model resolution); kb renders queue/ledgers/STATE but not a wave-Gantt-with-dependency-graph or a live worktree lane. Directly on top of worktree-leasing discipline the boss already runs by hand. / size L.

**3. Rubric-in-the-skill + bounded self-verify loop**
- mechanism: write the machine-checkable grading standard into the same skill file that does the work; invoke a `/goal`-style loop that runs work ↔ evaluator until goal-met or a try-limit (reel example: "get homepage Lighthouse ≥90, stop after 5 tries"). When output is still weak you fix the verification loop, not re-prompt. Gate every such loop on the "can success be verified?" pre-flight — refuse to start if no test/rubric/human-decision exists.
- source: Dbi4ruODNlK @00:36–00:48 (criteria-in-skill + `/goal` card); Dbs0166h9ZB @00:28–00:31 (can-verify gate); Dbi4ruODNlK @00:13 (Maker/Checker split).
- category: workflow
- general merit: strong and foundational — co-locating rubric with task and handing checking to the model is the most-cited lever for agents that actually finish. / kb fit: extends manager/inspector loops, `loop-design-check`, and the skills system; kb grades to a bar but the rubric lives in inspector prompts / card acceptance, not inside the work skill. Upgrade, not net-new. / size M.

**4. Human-gate approval inbox/sidecar**

Gate only high-impact actions so the inbox never becomes ceremony.
- source: DcGmHU6NSjB @00:45–00:55 (inbox + sidecar); DZErwKSCT2z @00:56–01:01 (Approvals mockup); DbY9KatgSMi @00:08 (human checkpoint on high-impact only).
- category: ui-ux
- general merit: good — the natural UX for human gates over many background runs. / kb fit: extends the dashboard inbox already built + risk-tier T3 gates + fyt GATE 1/2/3; today gates surface as prose cards, not a batched approve/edit inbox. On-doctrine with "human gates one at a time." / size M. / honesty: both source surfaces are UI mockups, not shipped products — the interaction pattern is the reusable asset.

**5. Canonical metric-definitions semantic layer**
- mechanism: one `governance/metrics-definitions` file that defines each fleet metric exactly once (what "cost", "budget", "grade", "verified", "card status" mean); a change propagates from one edit; agents and dashboards cite it instead of re-deriving. - source: DbQrgz6haNi @00:00–00:09 (21%→95%), @00:24, @00:48.
- category: infrastructure
- general merit: strong and sourced — a single-definition metric layer is a proven accuracy/consistency unlock for agent-facing data. / kb fit: clean net-new layer over existing `ledgers/` + `governance/`; metric semantics are currently spread across many files/agents. / size M.

**6. Cheap-model triage sweep before the expensive tier**

- source: Da6kEv3JMY3 @00:00.
- category: workflow
- general merit: simple, high-leverage cost control for any always-on loop. / kb fit: refines the HEARTBEAT cadences + single dispatcher Routine + budget guard; kb wakes the dispatcher on schedule but has no explicit cheap-triage-gate deciding whether to engage the premium tier at all. / size S.

**8. Prompt-cache-ordered prompt construction convention**
- mechanism: a kb-wide rule that every agent/skill prompt puts the stable prefix (instructions, static context) first and per-call dynamic content last, maximizing cache-hit prefix length for a flat cost + latency win ("cache the stable prefix, pay only for what changes").
- source: Daxhbdmk5G9 @00:00–00:09 (cache-node diagram + design rule).
- category: change-to-existing
- general merit: strong, well-established, low-effort. / kb fit: kb runs on subscription billing but still cares about latency (and real cost on the Atlas voice worker's spend-capped key); no explicit cache-ordering convention today. Note kb memory already flags that *proxies* break prompt caching — this is the constructive, proxy-free counterpart. / size S.

### High value

**9. Governed tool-access & permission layer**
- mechanism: four related hardenings of kb governance. (a) Declarative per-tool permission in agent specs — model + system + allowed MCP toolsets + a `permission_policy` per tool, tied to risk-tiers (Claude Managed Agents YAML). (b) Per-agent credential isolation + a pre-computed **blast-radius map** artifact per agent (one compromised sign-in must not hand the browser session + files + CLI creds to every agent). (c) Fail-closed-by-default tool calling + folder-trust boundary + durable JSONL session logs (oh-my-cli primitives). (d) Evaluate a single deterministic policy chokepoint that all tool calls transit (Liman) as prior art for a kb permissions gateway.
- source: DW9JYHYhdnU @00:35 (permission_policy YAML); DcHPKO-gQLs @00:00–00:14 (per-agent isolation + blast-radius, caption + stylized B-roll, no real product); DboaQE_tYbn @00:00–00:04 (fail-closed, folder-trust, JSONL sessions — README bullets in the frame held @00:00–00:04); DbG_xa3y_d6 @00:08 (Liman deterministic policy engine, on the Guardrails&permissions slide).
- category: change-to-existing / infrastructure
- general merit: strong — least-privilege by declared scope + a single deterministic access chokepoint is the right shape for a governed multi-agent fleet. / kb fit: reinforces and extends `never-handle-credentials`, risk-tiers T1–T3, spend law, worktree leasing; the net-new pieces are machine-checked per-tool permissions in the agent spec and a per-agent blast-radius artifact. kb governs via cards + tiers, not a single deterministic chokepoint. / size L.

## Cross-cutting themes

1. **The harness, not the model, decides cost/quality/speed.** The corpus's most-cited thesis (Composio benchmark, Pi Agent split, "one UI any harness"): the orchestration layer — not the raw model — is what finishes tasks optimally and cheaply. Argues for kb investing in the harness benchmark scorecard (#14), harness legibility (#2), and the provider-agnostic seam (#30) over chasing models.
2. **Verification loops are the load-bearing idea, and they recur in five forms.** Rubric-in-the-skill + `/goal` (Dbi4ruODNlK), Maker/Checker split (Dbi4ruODNlK), fresh-eyes manager/inspector (Da6kEv3JMY3), scored accept/reject (Dbs0166h9ZB), and "can success be verified?" as a pre-flight (Dbs0166h9ZB). kb already runs the manager/inspector split; the corpus pushes it *into the skill file* and *toward automation* (#3, #16).
3. **Trust is earned by a number, then gates autonomy.** Autonomy-graduation (20×@≥95%, revoke <90%), the 3-tier autonomy ladder, and selective high-impact gating all say the same thing: convert grade history into a machine-decidable trust score that decides what runs unsupervised (#1) — and surface the gate as an approval inbox (#4).
4. **Orchestration-visibility UIs are the biggest UX gap.** Git Timeline, fleet-grid, projects table, batch live-run table, self-healing error card, approval sidecar — the corpus is saturated with "see what all the agents are doing" surfaces. kb has the execution substrate (workflow platform, ledgers, worktrees) but under-renders it. The single highest-leverage UI investment (#2, #4, #15, #19, #24).
5. **Cost/context discipline is a first-class design concern.** Prompt caching (static-first construction), glob-scoped + progressive-disclosure context loading, accessibility-DOM-over-screenshots, cheap-model triage before the expensive tier, per-unit cost tiles, dry-run cost previews baked into tool contracts. All cheap, all compounding (#6, #7, #8, #13, #22, #29).
6. **Governance = least privilege by declared scope + a single access chokepoint.** Per-tool permission policy in the agent spec, per-agent credential isolation, blast-radius mapping, fail-closed defaults, bounded action space, deterministic policy engine. The corpus independently reinvents kb's `never-handle-credentials` + risk-tiers and points at the net-new pieces: machine-checked per-tool permissions and a blast-radius artifact (#9).
7. **Skills/agents want cross-tool distribution + visible trust vetting.** One source of specs, scoped multi-target installers, per-harness install tables, NL discovery with the trust filter *shown* not hidden, imported marketplaces, and a passive skill-gap observer that evolves the library. Maps onto kb's provenance tiers + the tracked catalog drift (#11, #12, #17).
8. **Structured artifacts beat prose hand-offs.** Semantic metric definitions (one source of truth), typed shared-state blackboards, research agents emitting machine-executable SOPs, PRD/dependency-graph intake. The consistent move: replace re-derived/prose context with a single typed artifact the next node cites (#5, #10, #20, #21).
