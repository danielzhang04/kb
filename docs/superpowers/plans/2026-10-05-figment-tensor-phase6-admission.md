## First implementation cut proposed for release

Only strict closed bounded offline parsing, current-scope/evidence-consistency projection, and an `inspect` report CLI with synthetic tests are in the first code slice. Target new `pipeline/tensor_runtime_admission.py`, new focused tests, and a narrow `figment_train.py` inspect dispatch. Do not implement an admission writer, live smoke launcher, approval adapter, approval consumption or any cross-project change in this cut. All later implementation steps below are gated roadmap, not an instruction to proceed automatically.

Every inspect result MUST include `runtime_admitted: false`, `authority_status: "authority-unavailable"`, and `production_ready: false`, even when `evidence_consistent: true`. Missing/invalid local evidence adds bounded named blockers; it never becomes authority. A fixture marker remains fixture. Do not call any real signed/possession/WebAuthn verifier, import one as an operational dependency, or expose a production verifier injection/selection seam. Tests use synthetic local evidence; no fixture verifier is needed in the production API. Existing launch and acceptance guards remain byte/behavior unchanged.

The CLI `runtime-admission inspect --request <file> --evidence-root <root>` receives the confinement root from its direct caller. This root limits reads but confers no approval trust. `read_request(path, evidence_root)` must use that caller-fixed root: a request's `evidence_root` may only match it exactly after safe normalization, never replace it or widen the permitted tree. Stable references must pass containment/reparse checks; active hostile-writer confinement is not claimed. Approval references are not accepted in this slice. Tests alter the request root while retaining the caller root, including symlink/junction and case variants, and require refusal for stable invalid/out-of-root paths before opening them; this is not a hostile-process race-proof sandbox.

Independent exit for this slice: parser/path/bounds and coherent-mutation negatives pass; import/inspect tests prohibit network, subprocess, model and verifier calls; current graph/pin projection is computed from code-owned current sources, not claimed current values in the evidence; clean CLI remains compatible; no path can set admission true. Do not present completion of this cut as completion of gates A/B or real phase6.

## Approval provenance: existing primitive, missing Figment adapter

The trusted repository mechanisms are `scripts/approvals.py::verify_signed_approval` and `verify_telegram_approval`, plus `scripts/webauthn_verify.py::verify_webauthn_approval`. `dashboard/server/approvals/cardVerifier.ts` invokes their module interfaces and consumes the verifier-returned pinned card, not a second working-tree read. `scripts/stage_approval.py` prepares approval records; staging is not approval. `scripts/dispatch.py` routes supervised cards to approvals and does not turn a blocked T2 into autonomous work.

The signed verifier authenticates the introducing merge against its supplied/local ref and returns committed card/payload bytes. Important: `approvals.py::_resolve_approvals_ref` permits an explicit ref and otherwise falls back from `refs/remotes/origin/approvals` to local `approvals` and then `HEAD`. A future Figment signed adapter MUST NOT inherit those fallbacks: use a code/config-owned protected ref and trusted keyring/fingerprints/human allow-list, reject missing/stale/unverifiable trust roots, and forbid evidence or CLI selection of ref, repository, keys, fingerprints or human identities. A local remote-tracking ref is not independently current merely because of its name. Authenticated cached-ref freshness and remote revocation policy remain unresolved gate-A decisions. Add changed-ref, old-ref replay, absent protected ref and caller-chosen fingerprint negatives before any future adapter is admitted.

Network behavior inspected, not executed: `approvals.py` uses local Git and GPG subprocesses with timeouts and a temporary GNUPGHOME; no explicit HTTP request or Git fetch was found. This is not independently enforced network isolation and cannot prove current remote protection/revocation. `webauthn_verify.py` also uses local Git and stateful nonce/counter stores; the first cut invokes neither verifier and makes no claim of offline authenticated approval. Any future adapter must review subprocess/config behavior and trusted freshness policy separately.

The signed payload binds action, target and Work order; do not assume arbitrary frontmatter is signed. The possession verifier relies on upstream minting/allow-list assurance; its hash/expiry checks alone are not a new standalone Figment trust root. WebAuthn verification has nonce/counter semantics and must not be repeatedly invoked as a read-only freshness predicate. Both existing verifiers enforce a 24-hour age limit; possession requires explicit expiry, while signed checks expiry if present (`require=False`). A future adapter must define any stricter expiry requirement explicitly, not claim the primitive already enforces it. Do not fake the clock or bypass expiry to validate historical smoke.

**Missing mechanism / design gate A:** inspected Figment launch/receipt code has no adapter that consumes one of these verified cards and durably binds its verified payload to the exact smoke manifest, bounded launch attempt, captured runtime evidence and final receipt. A card path, `decided_by`, Git author string, copied `ok: true`, chat transcript, arbitrary queue file or local evidence hash cannot fill this gap. No completed tensor smoke approval record was selected or authenticated during this task.

Before production admission code is enabled, root must approve the authority contract: which existing channel is accepted, where one-shot launch consumption is durably recorded, how a successful smoke result is authenticated, and how historical result evidence is revalidated without replaying an expired or consumed launch authorization. A conservative candidate is a **fresh signed result-admission card**, whose authenticated Work order binds the complete smoke evidence digest and exact compatibility scope, alongside the original authenticated launch/attempt chain. This is a proposal, not an existing mechanism or permission to mint one. It requires an explicit policy for expiry/revocation and trusted capture of the launch chain. Do not modify fleet governance, dashboard approval machinery, or consumption stores under this plan without a separate bounded scope.

Hashes and internally consistent receipts detect mutation, not a malicious replacement of the entire bundle. Without the approved trusted capture/result mechanism, the production validator must report `authority-unavailable`; synthetic tests may exercise an injected verifier only inside tests. A fixture verifier, CLI switch or self-declared record must never be selectable in production.

**Design gate B (bootstrap):** production generation currently refuses until smoke succeeds. Do not remove that refusal merely to run the first smoke. A separately reviewed smoke-only entry point must accept a currently verified T2 card for one exact manifest and bounded attempt, collect evidence, and produce no production approval/delivery. It reuses the same existing harness lifecycle. Building its offline seams is permissible after code-scope approval; invoking it live requires the later card, estimate and operator approval. Admission of a prior runtime does not authorize a later paid run.

## Proposed closed documents and interfaces

Use one new `pipeline/tensor_runtime_admission.py` module for pure parsing/projection/validation. Importing it has no file, process, network or model side effects. Production authority comes from a narrowly constructed trusted adapter, not an arbitrary JSON callback result. Interfaces proposed for review:

- `read_request(path, evidence_root)` parses a closed request and bounded referenced bytes.
- First cut: `inspect_candidate(request, *, current_scope)` returns an evidence-consistency projection or named blockers, always with admission false and authority unavailable. A later gated validator may consume verified run/native proof and trusted approval authority; that adapter is not part of this API slice.
- `require_current_admission(plan, *, purpose)` reconstructs all evidence and authority; no cached Boolean. Initially production raises `authority-unavailable` until gates A/B have an approved implementation.

Versioned proposed documents (new names, not claims about existing records):

1. `figment/tensor-runtime-admission-request@1`: exact keys `schema`, `stage` (initially only `video`), `recipe_profile` (`tensor`), `fixture`, `evidence_root`, `scope`, `sources`, `approval`. `sources` is a closed mapping of binding records `{path, bytes, sha256}` for smoke manifest, run receipt, recovery journals, relevant ledger evidence, installed inventory, object-info capture, submitted graph, history capture and native MP4 evidence. Lists have unique IDs and exact bounded cardinality. Approval contains references for the chosen adapter, never `approved: true` or raw secrets. An absent/unresolved adapter is a blocker.
2. `figment/tensor-installed-runtime@1`: capture producer identity/version and code digest; smoke attempt/pod identity; exact container image digest, ComfyUI repository/commit/tree status, custom-node repository/commit/dirty status, model revision/file size/SHA, relevant package/runtime versions, device class and capture time. Hash installed bytes, not only configured download URLs. Unresolved mutable container tags or unverified installed revisions block admission. Preserve private/redacted safe diagnostics; never capture environment variables, tokens or arbitrary process arguments.
3. `figment/tensor-object-info-capture@1`: attempt/pod identity, capture code digest, endpoint kind, bounded raw JSON binding and canonical projection for every required class/input/output. Validate linked slots, required/optional names and types, enum options, DynamicCombo wire encoding, and output-node registration. A class-name list or HTTP200 is insufficient. Preserve exact raw evidence while comparing the meaningful schema projection; unrelated extra classes do not silently broaden scope.
4. `figment/tensor-runtime-admission@1`: derived receipt with request/evidence digests, exact scope digest, verified approval projection and adapter version, attempt/pod/prompt IDs, verification implementation digests, fixture status and named limitations. Write only after all checks; atomic create/idempotent exact replay, never overwrite a different receipt. It is a revalidation index, not an authority independent of source evidence.

The scope projection includes current source/API export and parity implementation digests; immutable runtime/container/custom-node/model pins; required schema projection; workflow node/link/widget structure; allowed source-declared job fields and their constraints; output contract; native-media policy; transport/capture/validator implementation digests. Start conservatively with one exact effective graph and one exact input/accepted-edit chain. Broader template compatibility is a separate reviewed scope extension; changing prompt/image filenames cannot silently reuse an exact-graph admission. This conservative first scope is not a recommendation to allocate one pod per later scene.

The approval Work order must bind this scope digest, smoke manifest digest, creator/purpose, cell count, max-usd/max-minutes, current arc accounting basis, attempt constraints and intended evidence outputs. These belong inside authenticated payload fields; unauthenticated frontmatter is not authority. Existing budget, queue and ledger checks remain independent and unchanged.

## Implemented first slice (supersedes proposed API/caps above for current code)

Implemented `tensor_runtime_admission.py::{current_scope,inspect_request}` plus only `figment_train.py runtime-admission inspect --request --evidence-root`. Closed input is `figment/tensor-runtime-inspection-request@1`; output is `figment/tensor-runtime-inspection@1`, not an admission receipt. Exact root ownership, fields, nine JSON projection roles and caps are documented in pipeline/README.md and RUNBOOK.md. There is no arbitrary current-scope path, approval field/selector/callback or actual verifier. Always runtime_admitted=false, production_ready=false, authority_status="authority-unavailable"; JSON stdout only and exit2 even when internally consistent.

Actual caps: request1MiB; evidence4MiB/role except object_info/history8MiB; aggregate evidence snapshot24MiB; total actual I/O64MiB including both freshness passes; fixed current sources2MiB/file and8MiB aggregate. Model and native-media records are metadata only. No real installed-byte verification, raw object_info execution/schema compatibility, movie decoding, authenticated approval/capture or termination validation occurs. The object-info input is an explicitly normalized class/input-name/output-count projection; it is not raw ComfyUI API proof. Exact supported node49 output contract and nondefault node6 prompt/source slots are checked structurally against the current export. Scope includes actual code/pin/export file hashes.

Launch, acceptance, canonical approval, lifecycle and spend paths are unchanged. All trusted authority/capture/result writers, validate/admission commands, smoke launcher and cross-project integration remain unimplemented/gated. First-slice focused and consumer results and independent review are recorded separately; completion of this slice cannot complete spec phase6.

Inspection confinement qualification: request and evidence operands must be explicit `.json` metadata files before opening; model/media records contain no followable file path. A hostile file renamed `.json` cannot be identified without bounded reading/parsing, so this is not a claim that arbitrary adversarial bytes are never read. Stable reparse paths and ordinary mutations are rejected; component checks and rereads are not OS-enforced confinement against an actively swapping hostile filesystem writer. A future authenticated adapter needs separately reviewed stronger confinement/capture authority. None is enabled by this inspection slice.
