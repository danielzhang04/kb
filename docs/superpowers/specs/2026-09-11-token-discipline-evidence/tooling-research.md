## (b) Subscription plan mechanics (sources inline)

- **Claude Pro/Max/Team/Enterprise**: every paid plan meters a rolling **5-hour session window** plus a separate **weekly window** across all models; hitting either blocks that surface regardless of which one you hit first. Weekly reset time is fixed per account. — [code.claude.com/docs/en/costs](https://code.claude.com/docs/en/costs)
- Team/Enterprise seats (Standard/Premium) share the allowance with Claude chat and Cowork; usage *inside* the seat allowance is not metered in dollars, only usage-credit spend beyond it is. — same source.
- **Cache reads bill at ~10% of base input price** and count toward the same token pool (they still show in `/usage`'s Session block, e.g. "940.0k cache read"); cache lifetime is 1 hour on subscription plans, drops to 5 minutes once drawing on usage credits (choose-your-own TTL available). — [code.claude.com/docs/en/costs](https://code.claude.com/docs/en/costs)
- Official Anthropic guidance for reducing usage: clear (`/clear`) between unrelated tasks, match model to task (`/model`, Haiku for subagents), use skills instead of a bloated CLAUDE.md (keep CLAUDE.md under ~200 lines), delegate verbose ops (tests, logs, docs fetch) to subagents so only a summary returns, use hooks to pre-filter tool output (their own worked example: filter test output to failures only), and manage extended-thinking effort/budget (`/effort`, `MAX_THINKING_TOKENS`). — same source, "Reduce token usage" section.
- **1M context window**: as of 2026 Opus 4.6 and Sonnet 4.6 include the full 1M-token window at **standard pricing** — Anthropic removed the old long-context 2x surcharge. (Multiple secondary sources agree; I could not independently load Anthropic's own pricing page to confirm the exact date this changed, so treat as high-confidence but not primary-sourced.) — [claudecodecamp.com/p/claude-code-1m-context-window](https://www.claudecodecamp.com/p/claude-code-1m-context-window), [cloudzero.com/blog/claude-pricing](https://www.cloudzero.com/blog/claude-pricing/)
- **ChatGPT/Codex plans**: Plus is the base allowance; Pro 5x/20x and Business scale it by that multiple. Since ~April 2026 usage is metered by **tokens, not messages**. Codex also uses a 5-hour + weekly window (briefly removed the 5-hour window Jul 12–30 2026, then restored). Banked rate-limit resets (from referrals/events) are usable for 30 days. — [extraheadroom.com/codex-usage-limits](https://extraheadroom.com/codex-usage-limits), [simplemetrics.xyz/chatgpt-codex-limits-2026](https://simplemetrics.xyz/chatgpt-codex-limits-2026/)

## (c) Ranked shortlist for kb (effect / effort)

1. **Add a ccstatusline-style context-% bar to the Claude Code statusline.** Effect: high (earliest, cheapest signal to `/compact` or hand off before auto-compact eats 100-200k tokens); Effort: low (statusline script edit, no new dependency beyond optionally installing ccstatusline). Source: [code.claude.com/docs/en/statusline](https://code.claude.com/docs/en/statusline), [github.com/sirmalloc/ccstatusline](https://github.com/sirmalloc/ccstatusline).
2. **Route codex-worker JSONL usage into the existing `ledgers/cost/*.tsv` pipeline**, same shape as the Atlas ledger, by parsing `.usage` fields out of `~/.codex/sessions/**/rollout-*.jsonl` after each dispatch-codex run — closes the blind spot where `governance/budget.yaml` only sees API-dollar Claude steps. Effect: high (unifies budget guard across both fleets); Effort: medium (small parser script + a preamble.py check addition). **Never let a codex worker read its own rollout files directly** — openai/codex#27131 shows that pattern causing runaway self-ingestion.
3. **Confirm/pin `disableAllHooks` is NOT set anywhere in kb's settings**, since the tracker/budget/read-cache/context-shield hooks in `scripts/hooks/` are load-bearing for the cco pipeline and for `preamble.py`'s guard; a stray `disableAllHooks: true` in local settings would silently disable them (it does *not* override managed-settings hooks, but does override project/user ones). Effect: medium (prevents a silent budget-guard bypass); Effort: trivial (one grep across `.claude/settings*.json`).
4. **Adopt `/effort`/thinking-budget discipline for grunt-work subagents** (haiku/sonnet routing already exists via `governance/model-routing.yaml`; add explicit lower `model_reasoning_effort` for codex grunt dispatches in `dispatch-codex`, mirroring the sonnet/haiku split on the Claude side). Effect: medium (thinking tokens bill as output tokens on both platforms); Effort: low (config default change).
5. **Skip standing up OTel/Grafana or ccflare.** kb's TSV ledger + `preamble.py` + cco already cover budget enforcement and reporting for a single-operator machine; OTel's main incremental value (per-MCP-server attribution, live dashboards) is already substantially covered by `/usage`'s built-in attribution breakdown and `/cco-report`. Revisit only if kb becomes multi-seat.
