# Exact-subject persona still review workbench

Status: implementation in progress, September 14. Root adopted the four clarifications from the completed Opus rereview in `MAIN/_private/figment-claude-overnight-20260913/still-review-opus-design-rereview-v1/`. The earlier native review and original probe versions remain retained. The optional gen-only seam is under regression testing; the dedicated reader is being authored. Neither is accepted yet. Real routed quota/equivalence checks and independent code review precede adapter, HTTP and UI acceptance.

## One useful product slice

An authenticated operator opens one already-generated, already-graded persona gen plan, views its exact references and original images, records every required observation and deliberately applies one complete keep/cull ruling through existing authority. They can leave unfinished review without applying anything. Success reports **“Review applied: N kept, M culled”**; all-cull reports **“Review applied: all images culled.”** Neither implies checkpoint, batch, final-delivery or publication approval.

Support one server-configured published `creator-001` gen plan/revision, one gen run and at most 16 graded PNGs, on local Windows CPython. Exceeding capacity is an explicit unavailable state, not truncation. No actual eligible media gives an honest empty state. Synthetic implementation testing can proceed before media is eligible. No generation, grading/model invocation, checkpoint selection, video, renderer, assignment action or publication belongs in this slice; retain existing separate navigation links only.

Missing grade says **“These images are not ready for review. Prepare a current grade, then refresh.”** A documentation link may explain the existing grading CLI; opening this screen never runs it. Do not serve `board.html` as executable web content.

The normalized `figment/rulings@1` document contains fixed creator/stage, exact `evaluation_subject_sha256`, server-derived `decided_by` from the verified session subject, a frozen server UTC `decided_at`, and exactly one row per grading image in its original order. HTTP accepts a strict, bounded projection, rejecting unknown/duplicate keys and rows; it does not accept arbitrary CLI JSON, timestamps, author names or authority flags.

| `decision` | `keep` or `cull`, no default. |
| `identity`, `realism`, `hands`, `lighting` | Each `pass`, `soft-fail` or `hard-fail`. |

Every row, including cull, requires all seven genuine observations. Null is an unfinished in-memory form state, never submitted. No bulk pass/keep or automatic failure-filling. Still rulings have no terminal parked decision: show QA parked honestly and permit deferral without applying a ruling. Kept quality/safety must pass existing rules; numeric-gate overrides cannot waive ambiguous age, garment failure, resemblance flag or failed QA. Session attribution proves who submitted, not that the person looked or that the judgment is true.

The **entire serialized HTTP body**, including IDs/digests/rows and JSON escaping, must be at most 65,536 UTF-8 bytes. UI measures exactly `TextEncoder(JSON.stringify(body)).length` before enabling Apply; server measures original received bytes before parsing and normalized UTF-8 bytes again. Per-field validity is insufficient. Show **“Review notes exceed the submission limit; shorten them before applying”** and the remaining byte budget. Test multibyte and escaped characters at the actual wire boundary.

## Screen and one global opened handle

Discovery starts no child or write. Explicit **Review generated images** opens a fresh subject through a gated POST. Show captured references, one original image with fit/100%-zoom controls, position/count, seven observations, keep/cull, and existing gate reasons as context. Never substitute a crop/thumbnail or auto-promote a numeric pass. Primary UI has no filesystem paths, argv or long digest lists; a review-details drawer may show revision identity.

Exactly **one server-wide active opened handle** exists, bound to verified session subject/request scope, parent owner generation and exact plan/review binding. Lifetime is fixed at 30 minutes from successful open, not extended by clicks or polling. Another owner gets busy; they cannot evict or borrow the map. The owner may explicitly Close, discarding observations/object URLs; reopening performs a fresh inspection. Expiry invalidates draft/submission and requires reopen. Expiry/Close never releases a started writer claim or stops its child. Server restart drops open handles, not durable operation evidence.

Drafts live only in component memory. Leave/refresh warns that unapplied observations are discarded. **No localStorage/sessionStorage/pending-pointer schema** in this slice. Reload recovers operation identity/status from authenticated server inventory, never from browser-stored rulings. Owner/revision change, including A→B→A, clears forms/results before paint; check ownership after response and body decode and revoke image object URLs. Late responses never revive an old draft or badge.

Apply requires every row complete, actual image/reference fetches successful, nonexpired handle and total wire budget valid. Show a compact kept/culled count and explicit gate overrides before the deliberate action. Stale image/subject says **“The review evidence changed. Reopen the review to continue.”** Unknown response says the outcome is not known and offers **Check submission outcome**, never automatic writer retry.

## Fixed code closure and fresh processes

Every adapter invocation is a fresh fixed `python -I -B <pinned adapter>` through the existing contained runner with `requireEmptyStderr: true`, 120-second timeout, 256 KiB combined output cap and a single ASCII/LF JSON result at most 128 KiB. Runtime/adapter pins are caller configuration; source pins do not themselves bound input I/O.

The routed production closure is the new adapter, its purpose-specific read policy, `observed_reads.py` and **five** legacy sources: `figment_train.py`, `training_config.py`, `persona.py`, `lineage.py`, `qa_stamp.py`. The earlier unthreaded probe loaded `gates.py`; the reads-aware persona path does not. The actual routed child must prove the five-source closure and absence of gates, pod, build-set and scoring modules. Preload the verified sources under their exact existing aliases and verify driver ROOT/HERE bindings; `_load_module` returns cached aliases before loading from disk.

Bootstrap must verify bounded regular/non-reparse bytes of the complete configured closure before compiling under the existing aliases, reject preloaded project modules/alias collisions, and recheck exact module identities and code hashes before emitting success. Standard-library/runtime integrity is trusted. No scorer, judge, provider/harness, grading or training module/function is imported/called in production adapter modes. The producer probe's larger 28-file copy/fixture preparation closure is test preparation only, not the executed application closure.

Metadata-only references and optional absences count as admitted members; textual provenance fields that the legacy code does not dereference do not authorize additional reads.

## Concrete bounded-reuse prerequisite — implementation pending acceptance

Empirical success cannot turn unbounded legacy reads into bounded ones. `_load_plan` and `_current_review_subject` already support `reads`; the two public entry points are now being threaded. Direct default-None `_read_json` and lineage hashing remain unbounded for existing CLI callers. Preflight estimates cannot replace charging actual streaming through the supplied reader.

Smallest proposed seam for root/independent review: add optional keyword-only `reads=None` to those two public functions and thread it through their existing `_load_plan`, `_read_json`, `_sha256`, `_current_review_subject`, `_load_current_approval`, and all consulted `file/resolve`/absence checks. Existing lower-level helpers already accept it. Default `None` keeps CLI behavior. Preserve every normalize/stamp/keep/cull/override/lineage/write rule; no validator monkeypatch, new approval result or transactional writer rewrite. The selected-image checks in `validate_approved_gen_still` also need the supplied reader, not a final direct `stat/hash` escape. Writer output probes/reads route to the exact output policy, not an arbitrary filesystem fallback.

The adapter's purpose-specific `StillReviewReads` router enforces the A/B/C/D allowlist and actual stream counter, retains original immutable observations across intentional output changes, and implements the existing helper read interface. It is a standalone reader importing pinned unchanged observation primitives; it neither subclasses/rebases `ObservedReads` nor changes generic defaults. Supplying reads to apply requires stage=gen and checkpoint_step=None before any I/O. The default-None expressions, call signatures and order remain unchanged, including positional helper calls used by existing tests.

Per invocation: ≤64 admitted data files, ≤64 MiB total unique data, ≤32 MiB combined original PNG/reference bytes, each PNG ≤16 MiB/16 MP, and JSON/text total ≤4 MiB. JSON parse caps stay ≤256 KiB/file, depth≤32, ≤256 entries/container, ≤8,192 nodes. Source code has a separate finite ≤512 KiB/file bootstrap cap. Optional absent members are charged to membership/count, never silently added later.

Use exactly one dedicated reader per child, with a **2 GiB actual streamed-byte budget and 20,480-operation ceiling** across that child's preflight, rechecks, writer reads, output verification and all K≤16 kept-validator calls. Generic ObservedReads retains its 1,024-operation default and is unchanged. Charge every stream, including repeated hashes, before returning data. No multireader rebasing or per-validator reset is permitted. Retain at most 256 directory observations and a 128 KiB serialized baseline. Encode large fingerprint integers as strict canonical bounded decimal strings, preserving exact Windows identity/timestamps through JavaScript; never round-trip them through JSON numeric values.

Application has at most three children: P performs read-only preclaim subject admission, normalization, QA projection, keep eligibility and output-size/work reservation; W re-admits P's original baseline after the exclusive durable claim, enables the finite write transition, calls existing apply and verifies all outputs/K kept rows; I runs after verified W teardown, comparing original immutable inputs and W's frozen outputs. Recovery may run I only when durable verified W teardown exists. Baseline and submission are fixed server-private immutable operation files with exact size/hash pins, not browser paths or a new runner stdin API. P cannot admit new final files; W alone permits absent-to-first-published transitions; I cannot publish, reset or unfreeze outputs.

Before a started writer record, reserve conservative work from the fixed admitted sizes: let M be all PNG/reference bytes (≤32 MiB), J all JSON/text including maximum branch-output reservations (≤4 MiB), and K kept rows. Reserve `4*(M+J) + (K+3)*M + (8*K+24)*J` plus 16 MiB fixed bootstrap/receipt allowance. At K=16 this is ≤1,376 MiB. The coefficients cover original pre/final re-streams, two application subjects, whole-subject hashes in each validator, each kept image's additional hash, and repeated JSON evidence reads. They are a design upper reservation requiring a static callsite audit and 16-distinct-image fixture proof after threading; the current 12-image/16-call probe is not that proof. Any callsite exceeding the reservation refuses/needs attention and blocks acceptance; do not raise the cap to pass tests.

Required seam acceptance: an instrumented **real reader**, not patched validators, accounts for every consulted read/absence and stream; 16 distinct kept images fit counters and reservation; an oversized/missing/unadmitted member or code drift fails before writer output; no read escapes when reads is supplied. Until those checks pass, bounded application remains unaccepted, not READY.

## Intentional-write boundary without baseline reset

Let D be the existing selected plan's `grade/gen` directory. Inputs A/B retain original path, regular-file type, named/opened identity, size, mtime/change time/birth time, attributes and SHA-256 from before application; all are rechecked after confirmed teardown. Optional training sidecar absence and original directory membership are retained. An expected outcome write never permits an original plan, marker, grading, evaluation, gate, persona/config/spec, image or reference to change.

| Branch | Only new final names in D | Only transient names in D |
| --- | --- | --- |
| At least one kept row | `rulings.json`, `review-manifest.json`, `approved-list.json`, `approval-lineage.json` | Each listed final name plus `.tmp`. |
| All cull | `rulings.json`, `review-manifest.json`, `rejection-lineage.json` | Each listed final name plus `.tmp`. |

All expected final/tmp names must be absent before dispatch. Member-bearing directories within configured roots retain their full original fingerprints, except D's size/mtime/change-time fields during the exact permitted writes. Shared ancestors above those roots retain identity/type/birth/mode/attributes and non-reparse status without treating unrelated directory timestamps as input content. Admit the finite directory operands traversed by persona's lexical leading-`../` resolution, including ancestors above its root; this grants no file membership, and raw `..` paths remain refused. D must already exist. On every volatile D change, perform a charged inventory of at most 64 entries: preserve original names/non-input metadata and permit only branch final/tmp names. Freeze each final file on its first publication; tmp files are never reader operands. After teardown require exactly original entries plus branch finals, no tmp or deleted originals. Never allow accepted-checkpoint.json as a gen write.

Do not use one strict `ObservedReads` object containing D's full pre-write directory timestamp through the mutation and then label legitimate output stale. Do not discard/recreate the entire original input observer afterward either. The purpose-specific router compares immutable input records against the original baseline and applies only the stated directory-field/name exception. Output files get separate first-published observations and are validated against the exact submitted ruling and existing authorities, never treated as pre-existing trusted inputs.

Store server operation data outside the observed selected/persona/pipeline trees at configured `orgs/figment/_private/figment-studio/still-review-operations/<plan-id>/<operation-id>/`, a **sibling of** gen-plans. Never create an operation directory inside gen-plans. Precreate separate `inputs/` and `control/` directories: inputs contains the immutable submission and is a strict data root; control contains the fixed exactly pinned baseline/control envelopes and subsequent server evidence. Their common ancestor has identity-only observation. P can therefore emit a baseline that the server persists in control after P teardown without changing a strict observed input directory. Control files use separate bounded bootstrap reads under exact configured names/size/hash; they grant no arbitrary reader membership. The whole result envelope, baseline plus subject, must fit 128 KiB before success, not 128 KiB plus unchecked additions. After each child teardown compare original input observations before appending terminal evidence. No journal churn may be excused as writer output in D.

The operating condition is cooperative single-writer use: no unrelated CLI ruling or manual edits during application. The web claim prevents other web writers; it cannot compel an unrelated CLI to obey. File identity/content rechecks detect changes present at comparison, not a malicious fully reverted ABA. Partial writes remain evidence; there is no rollback or atomic multi-file/no-clobber claim.

## One writer operation and truthful recovery

Reserve one live process slot synchronously before await. Persist one exclusive durable started claim across all web instances per configured plan revision; exactly one started writer is allowed. Refused pre-start requests may be corrected, with at most eight immutable refusal records. Exhaustion is maintenance, not deletion. Once started, only status/inspection is offered, even after a clean failure; no in-screen second writer attempt or claim reset.

The immutable submitted record contains exact normalized observations/digest, subject/revision, verified submitter and frozen server timestamp, never credentials. Journal fsync/creation ordering is as above. The existing writer creates several files sequentially via `<name>.tmp`/replace; failure can occur after early files exist. No nonzero exit or browser abort proves nothing was applied.

| Observed condition | Required treatment |
| --- | --- |
| Known pre-start refusal | Fixed stale/invalid; no writer invoked. Preserve refusal record; reopen/correct is possible. |
| Exit 0 and verified owned-tree/pipe teardown | Recheck immutable inputs with D exception; verify exact branch outputs/attribution. For each kept image call existing kept validator through bounded reads. For all-cull reuse normalization/stamp/current-lineage helpers to verify rejection-only application, not a new image approval. Append terminal receipt exclusively afterward. |
| Confirmed failure, partial/mismatched output, quota breach after start | Needs attention, preserve claim and all output/tmp evidence; no overwrite/delete/retry. Clean failure can say not applied only after actual output absence/input checks, while still retaining the one-start limit. |
| Browser timeout/disconnect or uncertain/unclassified teardown | Keep ownership/quarantine; never release on UI expiry or guessed PID absence. Existing contained runner owns cleanup. |
| Lost HTTP response, recorded verified teardown | Authenticated inventory locates the operation. Explicit inspect-application runs a **read-only Python** check of exact same submitted identity/time/digest and current outputs. The **gated server POST**, after successful inspection and verified prior teardown evidence, may exclusively append a missing recovery receipt. Inspection never invokes the writer. |
| Restart with started claim but no durable verified-teardown record | Needs attention even if files appear complete. No completion recovery, receipt append, replay or cleanup by guessed PID. Output consistency cannot establish child death. |
| Pre-existing CLI/different-operation outcome | Already-applied recorded view only when existing authority can be established, otherwise needs attention. Never attribute it to this web operation. |

A durable teardown record must identify the owned invocation and its actual confirmed terminal result; append it only after containment has settled. If writing that record is interrupted, restart recovery remains unavailable. Runtime may offer human-directed existing recovery later; this slice adds no force-unlock or generic retry. Server inventory is the sole reload-recovery mechanism. A prior terminal receipt is historical, with currentness checked only by the explicit inspection; it is not a second accepted-still authority.
