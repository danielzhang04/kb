# Local identity alternatives on the 8 GB laptop

_Research note, 2026-09-08. Scope: local, clothed fictional-adult image and video production on the observed RTX 4070 Laptop GPU (8,188 MiB VRAM), about 30 GB RAM, and about 300 GB free disk. No model was downloaded or run for this note._

## Decision

The best next bounded **research comparator** is OmniGen2 in single-reference in-context generation mode through the installed native ComfyUI core. It is not a primary production recommendation: the inherited Qwen 2.5 VL 3B component's research-only licence leaves commercial deployment uncleared even though the OmniGen2 and Comfy repack cards say Apache-2.0. The probe can still show whether direct multimodal reference conditioning carries more useful identity information than the current SDXL IP-Adapter path. The exact official three-file Comfy payload is 15,779,025,788 bytes (14.69 GiB), and the installed core already contains the needed model, tokenizer, and reference-latent path. The maintainer's below-3-GB sequential-offload result applies to Diffusers and has not been measured through ComfyUI; host RAM and identity quality remain the other main uncertainties. This is a bounded research-feasibility hypothesis, not evidence that it is stronger than the installed SDXL IP-Adapter on g01 or eligible for production. [Concrete native feasibility plan](2026-09-08-local-omnigen2-feasibility.md) [OmniGen2 repository and operating guidance](https://github.com/VectorSpaceLab/OmniGen2) [Official ComfyUI workflow](https://docs.comfy.org/tutorials/image/omnigen/omnigen2)

No public source establishes a clean, 8 GB, one-image face system that is already proven to preserve g01 better. Recent identity benchmarking reaches the same broader conclusion: strong image quality and instruction following do not establish identity fidelity. The local decision therefore has to be a small measured probe, not a model-card promotion. [Persistent Identity Preservation benchmark](https://arxiv.org/abs/2609.04151)

The supplied project evidence supports that choice. The current production design already separates reference, generation, optional repair, and original-resolution review; the installed SDXL path is locally runnable but has only partial historical identity evidence. Earlier surveys favored Qwen-Image-Edit, PuLID, and larger edit models on 4090/L40S hardware, while the new local constraint is 8 GB VRAM. ## Why the obvious alternatives are not first

**PhotoMaker V2** is the most relevant face-specific adapter without a required training run, and its official repository claims improved ID fidelity and Apache-2.0 licensing. Its documented minimum is 11 GB VRAM, so an 8 GB route would depend on an unverified community offload configuration. [PhotoMaker repository](https://github.com/TencentARC/PhotoMaker)

**LongCat-Image-Edit** is Apache-2.0 and reports stronger edit consistency than Qwen-Image-Edit in its own evaluation, but its official CPU-offload example still requires about 18 GB VRAM. **Z-Image** is Apache-2.0 and compact for its class, but its own repository says the released 6B path fits within 16 GB, not 8 GB; the official Tongyi-MAI model list did not expose a separately downloadable Z-Image-Edit checkpoint during this review. [LongCat-Image](https://github.com/meituan-longcat/LongCat-Image) [Z-Image](https://github.com/Tongyi-MAI/Z-Image) [Tongyi-MAI model list](https://huggingface.co/Tongyi-MAI/models)

**Qwen-Image-Edit-2511 GGUF** is locally conceivable but not a clean new answer. The Q2 transformer artifact alone is 7.47 GB before its image/text encoder and VAE, and no primary runtime record was found for the complete stack on an 8 GB card. More decisively, the project already tested the same model family on larger hardware and found identity/age/skin failures; quantization changes memory, not the conditioning mechanism. [Official Qwen editing description](https://github.com/QwenLM/Qwen-Image/blob/main/Qwen-Image-Edit.md) [2511 GGUF artifact sizes](https://huggingface.co/w3ss/Qwen-Image-Edit-2511-GGUF/tree/main)

**PuLID, InstantID, IP-Adapter FaceID, and ConsisID** are technically stronger identity-specific comparisons, but their documented face preprocessing relies on InsightFace pretrained models, whose public weights are noncommercial unless separately licensed. PuLID's documented FLUX path also uses FLUX.1-dev; ConsisID adds a CogVideoX commercial-registration condition. They are research comparators, not the shortest route to a likely deployable pipeline under the current licence posture. [PuLID FLUX notes](https://github.com/ToTheBeginning/PuLID/blob/main/docs/pulid_for_flux.md) [InsightFace licensing](https://www.insightface.ai/solutions/face-recognition-licensing) [ConsisID requirements](https://github.com/PKU-YuanGroup/ConsisID) [CogVideoX licence](https://huggingface.co/zai-org/CogVideoX-5b/blob/main/LICENSE)

## Bounded next probe

Create one new, non-promotable OmniGen2 admission from the [native feasibility plan](2026-09-08-local-omnigen2-feasibility.md). Pin the installed ComfyUI commit and exact three-file revisions, hash every model file, and isolate models/input/output/temp/user directories. Use ComfyUI's native dynamic model management with a VRAM reserve and record physical RAM, commit, private bytes, paging, VRAM, and timing once per second. The plan's numeric stops govern the run; no Diffusers sequential-offload claim is assumed.

If loading is stable, render exactly **two 768×768 images**, one for each existing diagnostic seed, from canonical g01 and one fixed scene/pose prompt. Use the maintainer's in-context guidance range without a prompt sweep. Preserve the source and outputs, then review at original resolution for g01 eyelid, brow, nose, lip, jaw, hair, and jewellery cues; also record pose, background, adult presentation, clothing, realism, and defects separately. Stop after those two images. A pass only authorizes a separately planned 1024 comparison; a miss ends this model path. This keeps the result independent of the new prompt-calibration protocol and does not reopen or alter any earlier stop review.

For deployment planning, keep the existing video stage behind the still-image gate. FramePack is worth a later two-clip comparison only if the current video path visibly drifts from an accepted still and its model licence is acceptable for the intended territories. The immediate research decision is therefore **one bounded OmniGen2 comparator and no new video model until the still identity is solved**. Even a strong visual result cannot promote OmniGen2 into the production path while the Qwen component's commercial rights remain uncleared. OmniGen v1 is a separately designed fallback, never an automatic continuation.

All four supplied local sources were accessible. Public primary sources were accessible through the official GitHub and Hugging Face pages cited above; no paywall or bot wall affected the decision. No verified 8 GB runtime was found for PhotoMaker V2, LongCat-Image-Edit, Z-Image, or the complete Qwen-Image-Edit-2511 GGUF stack.
