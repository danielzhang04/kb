The §10 P3 Out sentence is a hard wall.

Parallel work is staged and unregistered; only W6 changes live shapes, shared composition files, routes, deployment files, or existing UI. Every task first lands a named failing test and finishes green on typecheck plus every focused suite it touches. W6.6 runs the literal gates and proofs.

## 3. Domain/contract deltas

### Spec-fixed contracts

Design §5 Terminal/Run (`:185-197,274-290`), §9 (`:496-535`), §10 P3 (`:575-590`), and §11 (`:655-673`) fix these facts:

- `SessionHost` is the single process port on both platforms. Windows is local `node-pty`; Linux is `/run/kb-shell/broker.sock` and children run as `kb-shell`, never root or `kb-dashboard`.
- Launchers are exactly `shell | claude | codex`. Browser and broker inputs never contain executable, raw command/argv, environment, uid/user, credential/token, or host address.
- Safe root ids are server-owned. Linux `repo` is exactly `/var/lib/kb/ops`; `worktrees` is exactly `/var/lib/kb-shell/worktrees`. Cwd is a normalized relative path whose final realpath remains within its selected root and outside `/var/lib/kb/state`, `/opt/kb-releases`, `/var/lib/kb-activation`.
- One persistent session record carries `name`, `host`, `launcher`, safe root id, cwd-relative path, attached Run ref, and controller browser-session ref. One `createPersistentSessionRegistry` and one `createSessionRunStore` are extended; no second registry, run viewer, or transcript exists.
- A 256-bit opaque ref is minted into a Secure/HttpOnly/SameSite=Strict session cookie. Operator plus that ref is required for session list, attach/control, input, resize, and close. Same-cookie tabs share; another authenticated browser gets not-found and cannot evict.
- Daemon restart changes unrecoverable live children to `abandoned`; it never claims persistence. Only Daniel-authorized deployment code may close exact ids across controller refs, via a registry primitive (P5 supplies UI).

### Plan-owned closed contracts

W0 creates `dashboard/server/pty/contracts.ts` with no decoder or live import:

```ts
type SessionHostKind = 'desktop' | 'vm';
type SessionLauncher = 'shell' | 'claude' | 'codex';
type SafeRootId = 'repo' | 'worktrees';
type SessionState = 'starting' | 'live' | 'exited' | 'closing' | 'abandoned';
type BrowserSessionRef = string & { readonly __browserSessionRef: unique symbol };
interface SessionRecord {
  sessionId: string; name: string; host: SessionHostKind; launcher: SessionLauncher;
  rootId: SafeRootId; cwdRelative: string; attachedRunRef: string | null;
  controllerBrowserSessionRef: BrowserSessionRef | null; state: SessionState;
  createdAt: string; updatedAt: string; exitCode: number | null;
}
type SessionSummary = Omit<SessionRecord, 'controllerBrowserSessionRef'>;
type SessionHostRequest = {
  sessionId?: string; launcher: SessionLauncher; rootId: SafeRootId;
  cwdRelative: string; cols: number; rows: number;
};
interface SessionHost {
  probe(): Promise<PtyCapabilityProbe>;
  create(request: SessionHostRequest): Promise<{ sessionId: string }>;
  attach(sessionId: string, sink: SessionSink): Promise<Detach>;
  input(sessionId: string, data: string): Promise<void>;
  resize(sessionId: string, cols: number, rows: number): Promise<void>;
  close(sessionId: string): Promise<ObservedExit>;
}
```

The browser handshake is a strict union after upgrade; `/api/pty` accepts no query parameters:

```ts
type BrowserPtyHandshake =
  | { type: 'create'; launcher: SessionLauncher; rootId: SafeRootId;
      cwdRelative: string; cols: number; rows: number }
  | { type: 'attach'; sessionId: string; cols: number; rows: number };
type BrowserPtyFrame =
  | { type: 'input'; data: string }
  | { type: 'resize'; cols: number; rows: number }
  | { type: 'close' };
```

Unknown or extra keys are refusals. Browser-supplied `name` and `host` are forbidden with the other raw fields. The registry derives the record name from server-owned facts: manual sessions are `<Launcher> · <safe cwd basename>` and Run sessions are `<Launcher> · <Run display name>`, each bounded to 80 UTF-8 bytes with a short server session-id suffix only on collision; record host comes from the probe. Cwd is POSIX-style relative UTF-8, 0-512 bytes, no NUL, drive, leading slash, empty/dot/dot-dot segment, or encoded separator. Dimensions are integer `cols 2..500`, `rows 1..300`. One input frame is at most 64 KiB UTF-8; the per-session queued-input high-water mark is 1 MiB. The WS server closes oversized frames with code `1009`/reason `input-too-large`; it never truncates.

The Unix broker uses one lifetime connection per dashboard daemon and length-prefixed JSON (`uint32be`, maximum 524,288-byte encoded payload so a worst-case escaped 64 KiB input still fits), version `1`, opaque `requestId`, and this exact request union: `create(SessionHostRequest without name/run/controller)`, `attach(sessionId)`, `input(sessionId,data)`, `resize(sessionId,cols,rows)`, `close(sessionId)`. Replies are `{v:1,requestId,ok:true,...}` or `{v:1,requestId,ok:false,error:{code}}`; stream events are `ready`, `data`, and `exit`. The first frame is closed `ready {effectiveUid,roots:['repo','worktrees'],launchers,policyDigest}` after the broker validates its uid and canonical root table; the client compares it with the configured `kb-shell` uid and expected policy digest before publishing availability. Closed error codes are `invalid-request | not-found | unsafe-root | unsafe-cwd | launcher-unavailable | input-too-large | size-out-of-range | capacity | unavailable | internal`. The dashboard owns name/run/controller metadata; none crosses the socket. Broker children belong to that connection epoch and are killed when it closes; a new daemon cannot attach an old child and marks its durable record `abandoned`.

`PtyCapabilityProbe` is a closed discriminated union placed at `runtimeCapabilities.pty`:

```ts
type PtyProbeReason = 'node-pty-unavailable' | 'shell-unavailable' | 'broker-unavailable'
  | 'broker-identity-mismatch' | 'root-policy-invalid' | 'launcher-unavailable';
type PtyCapabilityProbe =
  | { available: true; host: SessionHostKind; transport: 'local-node-pty' | 'unix-broker';
      launchers: Record<SessionLauncher, true>; roots: SafeRootId[]; checkedAt: string }
  | { available: false; host: SessionHostKind; transport: 'local-node-pty' | 'unix-broker';
      launchers: Partial<Record<SessionLauncher, boolean>>; roots: []; reason: PtyProbeReason; checkedAt: string };
```

`makeSurfaceContext` awaits the probe once, injects the probed `SessionHost`, and publishes that same object. No request re-probes and no OS name can flip `available`. The Terminal host selector contains only the probed local host (`desktop` on Windows, `vm` on Linux); it stores the host on the record but accepts no remote address. Cross-host catalogs/placement remain P6.

Root resolution is exact: Linux uses the two §3 fixed paths; desktop `repo` is the composed `repoRoot` and desktop `worktrees` is `<stateRoot>/control/worktrees`. Composition creates only the desktop worktrees directory, canonicalizes both roots, and passes the closed map into the host. The browser never supplies an absolute root or host.

Launcher profiles are server-owned and fixed: desktop `shell` is the absolute `ComSpec` value after basename/realpath allowlist validation, while `claude` and `codex` resolve those exact executable names once from the credential-stripped server PATH; VM `shell` is `/bin/bash --login`, and VM `claude`/`codex` resolve once from the broker-owned PATH `/var/lib/kb-shell/home/.local/bin:/usr/local/bin:/usr/bin:/bin`. Resolution canonicalizes the executable, refuses group/world-writable files, and stores no browser path. Terminal uses no extra args; a Run adapter feeds only its already-approved prompt over bounded input after creation.

The browser cookie is `kb_browser_session_ref`, exactly 32 random bytes base64url-encoded (43 characters), session-scoped, `Path=/; Secure; HttpOnly; SameSite=Strict`, never returned in JSON or logs. WebAuthn verification appends it as a second `Set-Cookie` header beside `kb_session` (never overwrites or comma-folds either); authenticated tailnet clients call idempotent `POST /api/auth/browser-session`, which sets it only when absent. A missing/malformed ref is not silently reminted by a PTY route.

`controllerBrowserSessionRef` is nullable only for a headless Run-created session. Every `/api/pty` attach is a controller attach: it requires equality, except that an explicit Run-view Reattach may atomically claim a null controller only after the server obtains `attachedRunRef` from the binding and applies the same scoped Run-read authorizer as `/api/control/runs/:runRef`; no browser run ref is accepted. Later control requires equality. List returns only controller-equal sessions. Attached browser sinks are a set under that one controller ref, so a same-cookie tab neither evicts nor is evicted; detach removes only its connection. A different ref always receives the same not-found response whether the id is absent, foreign, or already controlled. A WS detach never ends the session or clears its controller.

`createSessionRunStore` becomes the durable one-to-one binding `{runRef, managedSessionRef, sessionId, transcriptRef, state}`. The adapter writes the binding before the Run projection may publish `streamKind:'pty'`; retries require the identical triple. Run list/detail obtains `sessionId` from that binding, never from `ManagedSession.sessionRef`. W3's persistence seam journals every `SessionRecord`, and one transcript recorder observes every session. A controller WS attach replays the in-memory tail then streams; the existing scoped Run event/replay service exposes the same persisted PTY transcript under Run auth, and `ConsolePane` renders that replay before/without controller attachment. Ended/abandoned Run views therefore remain readable but cannot attach/control. Boot sweeps live bindings/records to `abandoned` before routes register. The registry also exposes internal `closeExactAndWait(authority, exactIds, timeoutMs)`: only a branded Daniel deployment authority can call it; it returns per-id observed/timeout/not-found results and has no HTTP route in P3.
