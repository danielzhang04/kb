## 3. Domain/contract deltas

### Spec-fixed contracts

Design §5 Terminal/Run (`:274-290`), §9 (`:496-535`), §10 P3 (`:575-590`), and §11 (`:655-673`) fix the host, launchers, roots, browser-controller boundary, one registry/transcript, abandoned restart semantics, and Daniel-only deployment termination. Browser and broker inputs never carry an executable, raw argv/command, environment, uid/user, credential/token, or host address.

The Run PTY belongs to an attempt's real worker process. Today `claudeWorkers` and `codexWorkers` are the only production adapters that spawn attempts. The logical manager and `createBrokerManagerAdapter.ensure` spawn nothing. The managed Claude/Codex adapters are constructed but cannot be reached because production has no `broker.start` caller. P3 makes both worker adapters create through `SessionHost` and deletes the two unreachable managed adapters and tests.

One Run may have several attempt sessions. The selected attempt in Run view determines `sessionId`: the active attempt wins; with no active attempt, the newest attempt by control-store attempt order is selected. `attemptSessions` lists every binding in attempt order. Only the active attempt may be live/controller-attachable. Earlier sessions are `exited` or `abandoned` and raw-replay only. A retry always receives a new session id but the same stable attempt operation key resolves to the same receipt.

Linux root ids are exact: `repo=/var/lib/kb/ops` and `worktrees=/var/lib/kb-shell/worktrees`; state, releases, and activation at `/var/lib/kb/state`, `/opt/kb-releases`, and `/var/lib/kb-activation` are denied. Desktop `repo` is composed `repoRoot` and `worktrees=<stateRoot>/control/worktrees`. Composition creates only desktop worktrees, canonicalizes every root, and accepts no browser absolute path or host address.

Launcher profiles are server-owned. Desktop Shell is absolute `ComSpec` after basename/realpath allowlist validation; Claude and Codex resolve those exact names once from the credential-stripped server PATH. VM Shell is `/bin/bash --login`; Claude and Codex resolve once from `/var/lib/kb-shell/home/.local/bin:/usr/local/bin:/usr/bin:/bin`. Resolution pins the executable, refuses the wrong owner or group/world write, and stores no browser path. Terminal adds no argv. A Run sends only its already-approved prompt through bounded input.

Names are server-derived and bounded to 80 UTF-8 bytes: `<Launcher> · <safe cwd basename>` for manual sessions and `<Launcher> · <Run display name>` for Run sessions, with a short server-id suffix only on collision. Host comes from the probe. The browser controller cookie is `kb_browser_session_ref`, exactly 32 random bytes encoded as 43 base64url characters, session-scoped, `Path=/; Secure; HttpOnly; SameSite=Strict`, and never in JSON, URLs, or logs. WebAuthn appends it beside `kb_session` without comma folding; guarded `POST /api/auth/browser-session` mints only when absent. PTY routes never silently remint a missing or malformed ref.

Every manual session has a controller. A headless Run has none until explicit Run-view Reattach applies the existing scoped Run-read authorizer and atomically claims the selected active binding; no browser-supplied Run ref participates. Later control requires exact ref equality. Lists contain only controller-equal sessions; absent, foreign, and mismatched ids share one not-found response. Same-ref sinks are additive, detach removes only its connection, and no disconnect clears the controller or ends the process.

### Lifecycle, persistence, and replay

`kb.pty-session-runs/v2` remains at the production path `<stateRoot>/pty/session-runs.json`. Its strict document contains `sessions`, `runBindings`, retained `terminalHistory`, and idempotency receipts. Before the v2 loader opens, `migratePtySessionRunsV2` acquires the existing document lock, reads the original bytes once, and does one of three things: initialize a validated empty v2; validate an existing v2 and atomically change every live prior-epoch record to `abandoned`; or strictly validate v1, create/fsync a byte-identical `session-runs.json.v1.bak`, transform in memory, validate v2, fsync a same-directory temp, rename once, and fsync the directory.

The v1 transform preserves every terminal record and archive receipt in `terminalHistory`, including transcript path/bytes/truncated metadata and the transcript files themselves. It changes v1 `live` to `abandoned`, supplies a monotonic `endedAt`, and never invents a browser ref or governed Run binding. A matching existing backup is reusable; a different backup, malformed/extra-key v1 or v2, failed backup/fsync/rename, or failed post-publish reopen aborts startup. Pre-rename failure leaves v1 untouched. A post-rename validation failure atomically restores the verified backup and fails startup. Fixtures cover empty, legacy, already-v2, malformed, extra-key, backup mismatch, every injected publish failure, repeat migration, transcript retention, and live-to-abandoned.

Broker connection loss calls `abandonEpoch(epochId)` before killing that epoch's children or accepting a new connection. That one transaction changes all matching `starting|live|closing` records/bindings to `abandoned`. `observeExit` is a compare-and-set from a matching live epoch only, so a later kill exit cannot reclassify `abandoned` as `exited`.

The registry's ordinary returned object has no exact cross-controller close property. `createPersistentSessionRegistry` accepts an installation callback and passes it an unexported closure implementing `closeExactAndWait(exactIds, timeoutMs)`. Composition injects only that closure into the deployment port. Tests prove the public object lacks the property at runtime, `as any`/casts cannot call it, ordinary internal/browser callers cannot obtain it, and only an injected deployment harness can close exact ids.

Raw Run replay is `GET /api/control/runs/:runRef/pty-sessions/:sessionId/transcript?cursor=<opaque>&limit=<1..65536>`. The existing scoped Run-read authorizer first proves the session binding belongs to the run. The cursor pins `sessionId`, transcript revision, and byte offset. The closed response is `{runRef,attemptRef,sessionId,state,encoding:'base64',range:{start,end,total,truncatedBefore},data,nextCursor,complete}`. It supports live, exited, and abandoned sessions; rejects cross-run/session cursors and extra query keys; reads at most 64 KiB; and exposes no input/resize/close. `ConsolePane` changes from a mandatory socket target to `source: {kind:'interactive',target} | {kind:'replay',page,loadNext}`. Replay writes ordered decoded bytes into the same xterm, never opens a socket or input handlers, and is the `RunDetail streamKind:'pty'` branch for terminal attempts. There is no second viewer.

```ts
  | { v: 2; type: 'resize'; requestId: string; sessionId: string; sequence: number; cols: number; rows: number }
  | { v: 2; type: 'close'; requestId: string; sessionId: string; sequence: number };
type BrowserServerFrame =
  | { v: 2; type: 'session'; requestId: string; session: SessionSummary;
      replay: { firstSequence: number; lastSequence: number; complete: boolean } }
  | { v: 2; type: 'data'; sessionId: string; sequence: number; encoding: 'base64'; data: string; replay: boolean }
  | { v: 2; type: 'exit'; sessionId: string; sequence: number; exitCode: number | null;
      signal: number | null; reason: 'exited' | 'closed' | 'abandoned'; observedAt: string }
  | { v: 2; type: 'error'; requestId: string | null; sessionId: string | null;
      code: HostRefusalCode | 'unauthenticated' | 'browser-session-required' | 'invalid-frame'; retryable: boolean };
```

`session` is first. Replayed `data` is strictly ascending, live data starts at the next sequence, and `exit` is last. Unknown, duplicate, missing, or extra fields fail. Browser `name`, `host`, executable/command/args/env/uid/user/token/address, and absolute cwd never enter any union.

The client chunks UTF-8-safe input to at most 16 KiB before base64 encoding, observes WebSocket `bufferedAmount`, never puts a token/ref in URL or payload, and never reconnects by implicitly creating. The server enforces the 64 KiB decoded limit and closes an oversized WebSocket message with `1009/input-too-large` without truncation.

The Unix broker uses uint32be length-prefixed JSON, max 524,288 bytes, one daemon connection epoch, version 1, and these closed unions:

```ts

  | { v: 1; type: 'create'; requestId: string; operationKey: string; launcher: SessionLauncher;
      rootId: SafeRootId; cwdRelative: string; cols: number; rows: number; mode: 'interactive' | 'headless' }
  | { v: 1; type: 'attach'; requestId: string; sessionId: string }
  | { v: 1; type: 'input'; requestId: string; sessionId: string; sequence: number;
      encoding: 'base64'; data: string }
  | { v: 1; type: 'resize'; requestId: string; sessionId: string; sequence: number; cols: number; rows: number }
  | { v: 1; type: 'close'; requestId: string; sessionId: string; sequence: number };
type BrokerSuccess =
  | { operation: 'create'; sessionId: string; epochId: string }
  | { operation: 'attach'; sessionId: string; firstSequence: number }
  | { operation: 'input'; sessionId: string; acceptedBytes: number; queuedBytes: number }
  | { operation: 'resize'; sessionId: string; cols: number; rows: number }
  | { operation: 'close'; sessionId: string; accepted: true };
type BrokerResponse =
  | { v: 1; type: 'response'; requestId: string; ok: true; result: BrokerSuccess }
  | { v: 1; type: 'response'; requestId: string; ok: false;
      error: { code: HostRefusalCode; detail: string | null } };
type BrokerEvent =
  | { v: 1; type: 'ready'; epochId: string; effectiveUid: number; roots: SafeRootId[];
      launchers: SessionLauncher[]; policyDigest: string }
  | { v: 1; type: 'data'; epochId: string; sessionId: string; sequence: number;
      encoding: 'base64'; data: string }
  | { v: 1; type: 'exit'; epochId: string; sessionId: string; sequence: number;
      exitCode: number | null; signal: number | null; reason: 'exited' | 'closed' | 'abandoned'; observedAt: string };
```

The single connection multiplexes by `sessionId`; request/response/event extra keys, unknown ids/versions, mismatched success operations, sequence regressions, and frames after exit are refusals.

Broker startup refuses uid 0 or any uid other than configured `kb-shell`, validates canonical roots, and sends `ready` before accepting requests; the client checks uid, root table, launchers, and policy digest. Under systemd the broker consumes only the inherited socket fd and never unlinks or chmods `/run`; the standalone WSL fixture may replace only an expected fixture-owned stale socket. One dashboard epoch is accepted at a time, a concurrent client is refused, and unknown/truncated frames, disconnect, or identity/policy mismatch make the client unavailable.

Cwd/name grammar uses UTF-8, 0-512 bytes, normalized POSIX relative segments, and rejects NUL, absolute/drive paths, empty/dot/dot-dot segments, encoded separators, C0/C1 controls, bidi controls U+202A-U+202E/U+2066-U+2069, and line separators U+2028/U+2029. Dimensions are integer cols 2..500 and rows 1..300. Input frames are at most 64 KiB decoded bytes and the per-session high-water mark is 1 MiB.

Linux path launch is fd-pinned. The broker opens the configured root, opens the candidate cwd, verifies `/proc/self/fd/<cwdFd>` resolves beneath that root and outside every denied root, and keeps the fd open while `node-pty` receives `/proc/self/fd/<cwdFd>` as cwd. It similarly opens and `fstat`s the fixed executable, refuses group/world-writable or wrong-owner files, and spawns `/proc/self/fd/<execFd>`. No attacker-writable pathname is resolved after validation. An injected barrier and WSL loop swap a symlink between safe and denied targets after validation; the child must use the pinned safe inode or the request must refuse, never reach the denied inode.

Structured operational events remain available from the existing Claude stream-json and Codex JSONL protocol parsers. W6.5 makes those worker engines consume a read-only protocol tap from the same headless `SessionHost` byte stream. The host records raw bytes once before fan-out. The parsers emit current message/tool/lifecycle/result projections and `WorkerExecutionResult`; they do not write a second transcript and do not parse ANSI/terminal escapes.

`ManagedSessionAdapter.start` and `ManagedSessionBroker.start` become async. The awaited `BrokerStartReceipt` contains `sessionId`, `transcriptRef`, binding revision, and `started|duplicate`; no running/started lifecycle is persisted or projected until host create plus durable binding succeeds. Stop during create records intent and closes immediately after bind without publishing started. Failed bind closes the new child, rolls reservation back to inactive, and publishes nothing. An identical retry returns the durable receipt and never creates twice; a changed retry conflicts.
