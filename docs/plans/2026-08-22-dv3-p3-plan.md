# Dashboard v3 P3 implementation plan

## 1. Goal + success condition

Implement only design section 10 P3 (`docs/specs/2026-08-20-dashboard-v3-design.md:575-590`). Replace the Windows-only browser PTY with one probed `SessionHost`, one operator-and-browser-controller registry, and a resident Linux `kb-shell` broker. A governed Run attempt launches its real Claude or Codex worker through the same host, owns one `sessionId`, and produces one raw PTY transcript; Terminal and Run view render that record through the sole `ConsolePane`.

P3 is complete only when every P3 Verify bullet has non-skipping evidence: Windows interactive Shell/Claude/Codex and headless Claude/Codex recipes; WSL broker protocol/race/bounds evidence; the P7 VM proof explicitly assigned in sections 8, 11, and 12; named full-viewport Terminal sessions; active-attempt Run attachment and earlier-attempt replay; exact `{operator,browserSessionRef}` isolation and revisioned Run-controller claim; every section 9 PTY attack refusal; restart/epoch abandonment; and an injected Daniel-only exact-id closer with no P3 UI.

Execution is W0, then width-five W1-W5, then serial W6.1-W6.6: 12 tasks. W0 compiles first. W1-W5 own disjoint new files and depend only on W0 ports. Existing/shared files, package/build declarations, registration roots, UI, styles, and deployment files change only in serial verticals. Each task starts with its named failing test, ends on its literal checkpoint, and does not commit.

## 3. Domain/contract deltas

### Binding rulings

- [C-S1] Remove descendant-wide `RestrictAddressFamilies=AF_UNIX`. `kb-shell-broker.socket` has exactly one `ListenStream=/run/kb-shell/broker.sock`, `SocketUser=kb-dashboard`, `SocketGroup=kb-dashboard`, `SocketMode=0600`, and `DirectoryMode=0750`; `kb-shell-broker.service` runs `User=kb-shell`, `Group=kb-shell` and has no `ListenStream`. Broker construction accepts only that validated Unix path or its inherited Unix fd, calls no TCP/UDP listen overload, and after listen requires `typeof server.address() === 'string'` and exact canonical-path equality. Unit tests parse both units and spy every listen call; PTY children may use outbound `AF_INET`/`AF_INET6` for provider APIs, while tests prove the broker cannot become a network listener.
- [C-S2] `SessionHostRequest` and broker `create` carry a closed `recipe`, composed only server-side from approved declaration/profile fields: `{launcher:'shell'|'claude'|'codex';mode:'interactive'|'headless-json';model;toolPolicyId;sandbox;resumeRef?}`. Browser input can choose a launcher but never a recipe/profile. The broker owns the only recipe-to-argv table: Claude headless is `-p --output-format stream-json --input-format stream-json --verbose [--settings <server JSON>] --model <model> [--resume <ref>] --allowedTools <server CSV> --permission-mode <server mode>`; Codex fresh is `exec - --json --model <model> -s workspace-write` plus the current five pinned `-c` values and `--cd <validated worktree>`; Codex resume is `exec resume <ref> - --json -c model=<model>` plus those same pins and no `--cd/-s`. This mirrors current callers/builders at `claudeWorkerAdapter.ts:749-765` and `codexExecAdapter.ts:186-209`; `headless-json` emits the same JSON streams consumed by the retained parsers. No wire or persisted request accepts argv, command, env, uid, user, executable, host, token, or browser-selected profile. Golden tests round-trip every current model/tool/sandbox/resume case and reject every raw argv/env spelling and extra key.
- [C-S3] A browser principal and every controller-bearing record bind the pair `{operator,browserSessionRef}`. Every browser registry method compares both. `claimRunController` is a revisioned registry port plus `POST /api/control/runs/:runRef/pty-sessions/:sessionId/controller`; it first applies existing scoped Run-read authorization, resolves the binding server-side, atomically performs the first claim, replays the exact same pair, and masks another pair's conflict as `not-found`. Tests cover same browser ref/different operator, same operator/different ref, same-pair replay, revision conflict, and foreign not-found.
- [C-S4] On the VM, execution `worktreeRoot` becomes `/var/lib/kb-shell/worktrees`, never `<stateRoot>/control/worktrees`. Thus setgid propagates the shared gid and other access is always zero. Before the start receipt, provisioning recursively validates/normalizes those modes and rejects special files, symlinks, setuid/setgid, or wrong ownership. W6.5 updates `activation.ts:379-382`, `execution.ts:2121-2124`, worktree ensure/cleanup/integration, sparse-path registry, canonical result lookup/integrator, accounting, and every paid-action builder/provisioner/committer/verifier plus paired tests. `/var/lib/kb/state/control/worktrees` is migration/cleanup-only after cutover: refuse new attempts there, finish/abandon recorded old attempts, then a human-reviewed later cleanup removes it.

### Internal record, binding, and persistence

The closed internal record common shape is exactly `{sessionId,operationKey,requestHash,recipeDigest,launcher,host,rootId,relativeCwd,name,controller,attachmentIds,transcript:{path:string,bytes:number,truncated:boolean,lastSequence:number},startedAt,endedAt,revision,provenance}`; controller is the exact pair/null, attachment ids are unique, and provenance is `{kind:'manual'}|{kind:'run',operator,runRef,attemptRef,managedSessionRef}`. The state union is `{state:'starting',epochId,exit:null}|{state:'live',epochId,exit:null}|{state:'closing',epochId,exit:null}|{state:'exited',epochId,exit:ObservedExit}|{state:'abandoned',epochId,exit:ObservedExit & {reason:'abandoned'},abandonReason:'epoch-lost'|'daemon-restart'|'start-recovery'}`. Impossible combinations do not compile and strict loading rejects them.

Manual create atomically binds the caller pair. Headless create starts controller-null and creates an exact one-to-one binding `{operator:string,runRef:string,attemptRef:string,managedSessionRef:string,sessionId:string,createdAt:string}`. The active attempt wins Run selection; with none active, newest attempt in control-store order is selected. Earlier bindings remain terminal raw-replay rows. A retry has a new session id only for a new operation key; an exact operation retry replays its original receipt.

- [C-M3] The fixed file remains `<stateRoot>/pty/session-runs.json` and v2 is exactly `{schema:'kb.pty-sessions/v2',revision:number,sessions:SessionRecord[],attemptBindings:AttemptBinding[],operationReceipts:OperationReceipt[],legacyRuns:SessionRunRecord[],legacyArchiveKeys:ArchiveKeyEntry[]}` with no extra keys. Sessions are oldest-first and keyed uniquely by `sessionId`; bindings use the exact shape above and unique `attemptRef`, `managedSessionRef`, and `sessionId`; `OperationReceipt` is exactly `{operationKey:string,requestHash:string,status:'pending'|'bound'|'failed'|'cancelled',sessionId:string|null,attemptRef:string|null,refusal:HostRefusalCode|null,createdAt:string,settledAt:string|null}` keyed by `operationKey`; legacy arrays retain the exact strict v1 shapes. Caps are 4,000,000 encoded bytes, 500 sessions, 500 bindings, 1,000 receipts, 500 legacy runs, and 512 legacy archive keys; strings also obey their field bounds. Live/pending entries are never evicted; oldest terminal entries and their unreferenced receipts evict first.
- [C-R5] Under the existing document lock, migration reads only exact v1, copies a byte-for-byte `.v1.bak`, then builds and validates v2 with `revision:0`, empty `sessions/attemptBindings/operationReceipts`, one `legacyRuns` row per v1 `runs` row, and one unchanged `legacyArchiveKeys` row per v1 archive key. Every non-live legacy field maps byte-for-byte; a live row alone maps to `outcome:'abandoned'`, `endedAt=max(migration time,startedAt+1ms)`, and `version+1`, with all transcript path/bytes/truncation, PTY id, priming path, owner, entity refs, exit code, and timestamps otherwise retained. It fsyncs temp and parent then atomically renames. No new session, binding, receipt, id, or controller is invented from incomplete v1 provenance. Malformed, oversize, duplicate, backup, fsync, validation, or rename failure leaves v1 authoritative and restores bytes; retry recognizes the valid v2 document and is idempotent.
- Epoch loss atomically changes every matching `starting/live/closing` record to `abandoned` before killing children; a later exit CAS carrying the old epoch cannot reclassify it. Startup converts persisted `pending` receipts to failed and bound-live records to abandoned before serving reads.
- [C-R6] Raw replay is `{sessionId,fromSequence,nextSequence,complete,frames:[{sequence,encoding:'base64',data}]}` with `1..65_536` requested bytes and at most 256 frames. Cursor/session mismatch, gap, overflow, extra query, or cross-Run binding refuses. `ConsolePane` accepts either its live controller source or this read-only replay source; replay has no input/resize/close callbacks and creates no second xterm.

### Wire and transport bounds

The browser and broker protocols are strict discriminated unions with exact keys. One shared JSON vector corpus supplies every valid/invalid frame to server, broker, and client decoders; the browser client has no permissive fallback.

- Browser first frame: create `{type:'create',requestId,launcher,rootId,relativeCwd,cols,rows}` or attach `{type:'attach',requestId,sessionId}`. Later frames are input `{type:'input',requestId,sessionId,data}`, resize, close, or detach by `attachmentId`. Server frames are `created|attached|data|ack|exit|error`, all request-correlated where applicable.
- Broker frames are length-prefixed strict JSON: `hello/ready`, `create` carrying server-composed `recipe`, `attach`, `input`, `resize`, `close`, `ack`, `data`, `exit`, `error`. Maximum broker frame is 98,304 bytes; decoded input is 65,536 bytes; per-session queued input high-water is 262,144 bytes; output fan-out uses bounded 1 MiB per attachment and detaches a slow sink without killing the process.
- [C-M2] The registered WebSocket sets raw `maxPayload: 90_112` before JSON parsing. Three independently titled tests prove: a 90,113-byte raw message is rejected with 1009 before parse/host; a within-transport base64 input decoding above 65,536 is refused/1008; and valid decoded chunks exceeding the 262,144 queued high-water are refused without loss/reordering of accepted bytes. The WSL broker repeats decoded/high-water tests.
- [C-R7] Shared vectors freeze every identifier boundary, numeric min/max/overflow, recipe combination, extra/missing key, invalid base64, frame-size edge, and output union. Broker and browser tests consume the same vectors and assert parity; production decoders are the only exports.

### Launcher and filesystem policy

- [C-M7] Windows Shell is canonical `%SystemRoot%\System32\cmd.exe`, owned by TrustedInstaller or Administrators SID and not writable by Users, Everyone, or the dashboard identity. Windows Claude/Codex resolve once from the dashboard service identity's approved installation roots; executable, script entry, interpreter, and parent chain are owned by that exact service/user SID, with no write ACE for another non-admin SID. Linux Shell is canonical root:root `/bin/bash` mode `0755` with no group/other write. Linux Claude/Codex are either root:root mode `0755` below `/usr/bin` or `/usr/local/bin`, or `kb-shell:kb-shell` mode `0700|0750` below `/var/lib/kb-shell/home/.local/bin`; every symlink, shebang interpreter, Node binary, and JS entry is canonicalized and independently checked. Any other owner/root, component writable outside its allowed owner class, setuid/setgid bit, special file, or post-check identity change is refused. Per-platform/per-launcher tests cover every allowed class and one refusal for each rule.
- The broker opens root/cwd/executable chain with no-follow handles, validates by fd, and launches against the pinned identity. Barrier tests replace cwd, executable, symlink, interpreter, and parent between validation and spawn; the validated object launches or the request refuses, never the replacement.
- Environment is a server constant: Windows keeps only required system variables plus server-resolved CLI home; Linux sets `HOME=/var/lib/kb-shell/home`, `PATH=/var/lib/kb-shell/home/.local/bin:/usr/local/bin:/usr/bin:/bin`, `LANG=C.UTF-8`, and launcher-required provider variables loaded outside worktrees.
