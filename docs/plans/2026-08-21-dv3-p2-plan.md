### Plan-owned contracts

Design §7 intentionally leaves phase envelopes/DTOs to plans. W0 owns standalone declarations in `entities/contracts.ts`, `schedules/contracts.ts`, `home/contracts.ts`, and `control/p2Contracts.ts`; W1–W5 code only against those declarations. Lists are `{revision,groups,items}`; detail is `{revision,summary,brief,details}`; Home is the exact D13 ordered tuple Running now, three linked counts, Next schedules, version, Recent outcomes. `RunRow`, `ScheduleOccurrence`, `EntityBrief`, `OutputRef`, builder requests, `ScheduleStorePort`, stream pages, attention, and Home section-result types are plan-owned, closed, and revisioned. Compile-only W0 assertions pin those shapes; W6.1 adds their runtime decoders and extra-key rejection before any live registration.

Clients send only an untrusted selector `{type:"agent"|"workflow",id:string}`. The server indexes declarations, rejects unknown/duplicate/type mismatch, and constructs the trusted full `RunnableRef` including server-derived `sourcePath` and Workflow `project`. No client `sourcePath`, project, host, owner, or declaration provenance is trusted. `executeApprovedLaunch` accepts only the resolved trusted ref and server boot `HostKind`; `createRun` persists both in its single transaction before dispatch.

Builder requests contain display/policy choices only. Server catalogs close model/profile/connectors/tools/filesystem roots, derive all paths, realpath under allowed roots, and send generalized assignment/governance amendments through the retained `routeDurable` service with source revision CAS. `OutputRef` is a closed repository-file/artifact/external-PR union; projectors validate roots and construct PR URLs from pinned fields.

Schedule mutation DTOs are plan-owned and closed: `CadenceInput` is words+time or five-field cron; create carries untrusted owner selector, expected collection revision, and idempotency key; item mutation carries expected row version and idempotency key. Seed id is exactly `sha256("schedule\0" + normalizedHeartbeatPath + "\0" + cadenceName)`; operator id is exactly `sha256("schedule\0operator\0" + owner.type + "\0" + owner.id + "\0" + clientIdempotencyKey)` (design §5 line 228). The server normalizes Eastern cadence source/words and rejects unknown owners, extra/source-path fields, and invalid time/words/cron before mutation.

The v3 document envelope adds `scheduleCollectionRevision`; collections add `schedules`, `scheduleTombstones`, `scheduleOccurrenceClaims`, and `scheduleSeedImports`. Private rows carry canonical cadence source, exact seed bytes/digest/authorization, launch payload, operation/emission receipts, mirror metadata revision, and tombstone; none leak through public `Schedule`. The checksummed zlib/base64url `kb.control-plane-v3-down-carrier/v1` preserves all Run identity/outcome and schedule additions, including quarantine, across v3→v2→v3 in both TS and generated Python runners.

`ScheduleStorePort` exposes read snapshots plus atomic one-event `createSchedule`, `setScheduleArmed`, `deleteSchedule`, `claimScheduleOccurrence`, and `completeScheduleOccurrence`. Create/item operations compare collection/row revisions and replay only identical fingerprints; claim binds exact occurrence and phased emission receipt; completion records claim `runRef`, `lastOutcome`, and display-only `nextAt`. Delete excludes immediately and returns a tombstone. Python alone decides due.

### Run migration and publication contract

`StoreDocument` advances v2→v3 through the existing TS/Python registry. `migrateRunIdentityV1` is whole-document and unique: `agentWorkspaceLaunch.{agentId,declarationPath,declarationHash}` resolves Agent; otherwise proposal `{proposalRef,proposalRevision,proposalHash}` plus matching launch audit must resolve exactly one immutable Workflow definition snapshot. Zero/multiple/conflicting provenance emits `run-owner-migration-required` with `{migration,total,migrated,errors:[{runRef,location,candidates,reason}],truncated}`, capped at 100 sorted errors; no synthetic owner. Host is the boot-verified daemon `HostKind`; contradiction aborts.

`migrateRunOutcomeV1` uses only stored fields named above:

1. A row already carrying valid P2 fields is accepted only if recomputation agrees.
2. A non-archived `succeeded|failed|stopped` lifecycle maps to `ok|failed|stopped`; `completedAt=run.updatedAt` only if no later mutation receipt/event exists. An exact `HumanRequest.response.idempotencyKey` beginning `auto-close:terminal:<kind>:` may instead prove the same transition time through its `respondedAt`.
