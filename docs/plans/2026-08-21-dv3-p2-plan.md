The store contract adds these one-writer operations; each is atomic with one event:

- `listSchedules(): {scheduleCollectionRevision,rows}` and `getSchedule(id)` are read-only snapshots.
- `createSchedule(input,expectedCollectionRevision,idempotencyKey)` hashes the operator id, replays only the same fingerprint, and bumps the collection once.
- `setScheduleArmed(id,armed,expectedVersion,idempotencyKey)` bumps row and collection; seed authorization is rechecked on every false→true transition.
- `deleteSchedule(id,expectedVersion,idempotencyKey)` removes the live row and returns a tombstone receipt retained through P2.
- `claimScheduleOccurrence(id,scheduledFor,expectedVersion,idempotencyKey)` records the exact occurrence once; changed replay conflicts. The successful receipt is the only authority for `dispatch.py` to emit the existing claimed card. Queue bridge resolves its pinned schedule/owner and calls `launchRunnable`.
- Completion of a claimed scheduled Run records the claim's `runRef`, updates `lastOutcome`, advances display-only `nextAt`, and bumps row/collection once. TS may preview `nextAt`; Python alone decides whether an occurrence is due.
