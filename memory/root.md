## A confirmed request defect is not automatically the sufficient visual cause

### Context
- The B4 audit found false FIRST/LAST seed-role prose in L28, but also found a weaker last-image mismatch in a passing four-seed L81 request.

### Root Cause / Core Insight
- A literal assembly contradiction is actionable, yet causal attribution still requires checking positive controls and ablations; otherwise a real bug can crowd out the deeper mechanism.

### The Pattern (transferable)
- Next time I find a malformed multimodal request, I will fix and report it as confirmed, then compare failures and passes that share the defect before calling it sufficient cause.
- Signal to recognize: one exact code/request error appears compelling, but a logged success contains the same property or an existing ablation retains the symptom after removing it.

## A declared retry mechanism must change the post-normalization request

### Context
- Surgical seed retries use stable first-wins dedup, so repeating the already-first seed can look like a reorder in the overlay while producing an unchanged provider seed list.

### Root Cause / Core Insight
- Validate mechanism authority after merge and normalization, against the final provider request; validating only the requested operation admits no-op retries.

### The Pattern (transferable)
- For any retry or patch API, compare the normalized before/after artifact and reject equality before execution.
- Signal to recognize: an operation is described as prepend/reorder/replace, but deduplication or canonicalization can erase its effect.
