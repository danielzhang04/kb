# R24 — Identity-transfer bakeoff candidates (single-image → LoRA seed set)

Problem: from one synthetic-woman reference, generate pose/lighting variants at ≥~0.85 identity cosine, same apparent age, real skin — commercially clean, safetensors-only, ComfyUI on one L40S/4090, zero spend. Failed so far: FLUX.2 klein-4B free multi-ref, klein-4B edit-as-canvas, Qwen-Image-Edit-2511+Lightning (3 runs) — all lose age/skin.

## Licence ground truth first (this gates everything below)

- **FLUX.1-dev / FLUX.1-Kontext-dev / FLUX.2-dev / FLUX.2-klein-9B**: all under the **FLUX Non-Commercial License**. Section 1(c)/4 defines "Non-Commercial Purpose" and excludes revenue-generating or end-user-facing use; production deployment requires a paid BFL licence. Confirmed on klein-9B's own LICENSE.md. — [black-forest-labs/FLUX.2-klein-9B LICENSE.md](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B/blob/main/LICENSE.md), [flux2 issue #32](https://github.com/black-forest-labs/flux2/issues/32)
- **FLUX.2-klein-4B** and **FLUX.1-schnell**: **Apache 2.0**, commercial-clean. — [FLUX.2-klein-4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B), [FLUX.1-schnell](https://huggingface.co/black-forest-labs/FLUX.1-schnell)
- **InsightFace pretrained models** (antelopev2, buffalo_l, inswapper_128) are **non-commercial research-only**; the InsightFace *code* is MIT but the *weights* are not, and anything trained on InsightFace embeddings inherits the restriction. Commercial use needs a paid InsightFace licence. — [InsightFace commercial licensing](https://www.insightface.ai/solutions/face-recognition-licensing), [InstantID maintainer discussion](https://huggingface.co/InstantX/InstantID/discussions/2)
- **FaceNet (facenet-pytorch, VGGFace2 weights)** is MIT/commercially clean and is shipped as a drop-in InsightFace replacement in one PuLID-Flux node. — [lldacing/ComfyUI_PuLID_Flux_ll](https://github.com/lldacing/ComfyUI_PuLID_Flux_ll)
- **Qwen-Image / Qwen-Image-Edit (2509, 2511)**: Apache 2.0. — [aimodels.fyi comparison](https://www.aimodels.fyi/models/compare/qwen-image-edit-2509-qwen-vs-qwen-image-edit-2511-qwen)
- **Krea-2 (Raw/Turbo)**: Krea 2 Community License — commercial use permitted only under $1M company-wide annual revenue, else Enterprise licence required; no IP claim on outputs. — [Krea 2 Community License](https://www.krea.ai/krea-2-licensing)
- **Z-Image family (Tongyi-MAI)**: Apache 2.0. — [Tongyi-MAI/Z-Image LICENSE](https://github.com/Tongyi-MAI/Z-Image/blob/main/LICENSE)
- **ai-toolkit (ostris)**: permissive OSS trainer, license file at [ostris/ai-toolkit/LICENSE](https://github.com/ostris/ai-toolkit/blob/main/LICENSE); it only inherits restrictions from whatever base model you point it at.

## Graded method list

**(1) Qwen-Image-Edit-2511 + tlennon-ie/qwen-edit-skin LoRA, no Lightning, higher steps.**
Licence: clean — LoRA is Apache 2.0, trained on 2509 base (5000 steps, RTX 5090, ai-toolkit), recommended weight 1–1.5. — [tlennon-ie/qwen-edit-skin](https://huggingface.co/tlennon-ie/qwen-edit-skin), [aimodels.fyi](https://www.aimodels.fyi/models/huggingFace/qwen-edit-skin-tlennon-ie). Evidence the Lightning LoRA itself is a skin-plastic cause: community reports say Lightning "tends to make skin appear more plastic-like and reddish," and halving steps or dropping Lightning (20 steps, CFG ~1.2–1.5, no Lightning) reduces the effect. — [Patreon BFS LoRA notes](https://www.patreon.com/posts/140789769), [tlennon-ie model card](https://huggingface.co/tlennon-ie/qwen-edit-skin). No published ArcFace/cosine numbers for this specific LoRA combo — anecdotal community consensus only. ComfyUI: native Qwen-Image-Edit nodes, drop skin LoRA at 1.0–1.5 weight, disable Lightning, 20-28 steps, CFG 1.5-4. VRAM: FP8 edit path fits ~16GB. — [blog.comfy.org](https://blog.comfy.org/p/qwen-image-edit-2511-and-qwen-image)

**(2) Qwen-Image-Edit-2509 vs 2511 identity behaviour.**
Documented: 2511 (Dec 26 2025) improves multi-image consistency, adds multi-angle single-reference view synthesis, and "refined face identity preservation across pose and style transformations" versus 2509; both Apache 2.0. — [runcomfy 2511 page](https://www.runcomfy.com/models/qwen/qwen-image/qwen-image-edit-2511), [myaiforce 2511-vs-2509](https://myaiforce.com/qie-2511/). This is the same family already tried (failed 3x) — the untried variable is the Lightning removal + skin LoRA in (1), not the base-model swap.

**(3) PuLID-Flux / PuLID-FLUX.2 — REJECT on stock config, conditional pass with encoder swap.**
- `iFayens/ComfyUI-PuLID-Flux2` explicitly targets FLUX.2 (klein 4B/9B/dev), MIT-licensed node code, but requires InsightFace antelopev2 (non-commercial weights) + EVA-CLIP; no FaceNet alternative documented for this specific FLUX.2 port. — [iFayens/ComfyUI-PuLID-Flux2](https://github.com/iFayens/ComfyUI-PuLID-Flux2)
- `lldacing/ComfyUI_PuLID_Flux_ll` (FLUX.1 line only) ships a documented commercial-clean path: `PulidFluxFaceNetLoader` uses facenet-pytorch/VGGFace2 (MIT, no InsightFace, no extra downloads) instead of antelopev2, explicitly marketed "no ArcFace licensing restrictions." — [lldacing/ComfyUI_PuLID_Flux_ll](https://github.com/lldacing/ComfyUI_PuLID_Flux_ll). But its base model is FLUX.1-dev (non-commercial) in all documented workflows — FLUX.1-schnell (Apache 2.0) is the licence-clean base and PuLID does have schnell-compatible community checkpoints (e.g. flux-pulid on Replicate), so **PuLID + FaceNet loader + FLUX.1-schnell base** is the only fully clean PuLID path, unverified for skin/age on schnell specifically. — [FLUX.1-schnell license](https://huggingface.co/black-forest-labs/FLUX.1-schnell), [flux-pulid model](https://www.aimodels.fyi/models/replicate/flux-pulid-zsxkib)
- Identity strength: PuLID paper reports SOTA ID fidelity vs. IP-Adapter/InstantID baselines via ArcFace/CurricularFace cosine; on FLUX.1-schnell 4-step ArcFace similarity ~0.615 vs 0.587 baseline (paper's own comparison point, not directly our 0.85 target metric). — [PuLID paper](https://arxiv.org/html/2404.16022v2), [training-free acceleration paper](https://arxiv.org/html/2605.09460)
- Also via Nunchaku (mit-han-lab quantized FLUX pipeline) PuLID integration exists but again documented against FLUX.1-dev and InsightFace/FaceXLib. — [nunchaku PuLID docs](https://nunchaku.tech/docs/nunchaku/usage/pulid.html)

**(4) InfiniteYou / InstantCharacter / OmniGen2 / UNO / DreamO — mostly REJECT.**
- **InfiniteYou** (ByteDance): repo code Apache 2.0, but requires **FLUX.1-dev** as base and InsightFace face models for inference — the code licence does not clean the FLUX.1-dev or InsightFace dependency. VRAM 43GB bf16 down to 16GB with offload+8-bit. **REJECT** (base+encoder both non-commercial). — [InfiniteYou LICENSE](https://github.com/bytedance/InfiniteYou/blob/main/LICENSE), [InfiniteYou README](https://github.com/bytedance/InfiniteYou)
- **InstantCharacter** (Tencent-Hunyuan): built on FLUX.1, no explicit licence statement found in README; treat as unresolved/likely inherits FLUX.1-dev restriction — needs direct verification before use. — [InstantCharacter README](https://github.com/Tencent-Hunyuan/InstantCharacter/blob/main/README.md)
- **UNO** (ByteDance): code Apache 2.0 but **model weights are CC BY-NC 4.0**, built on FLUX.1. **REJECT** (weights explicitly non-commercial). — [UNO HF README](https://huggingface.co/bytedance-research/UNO/blob/main/README.md)
- **DreamO** (ByteDance): code Apache 2.0, but backbone is FLUX.1-dev, non-commercial. **REJECT** as configured. — [DreamO GitHub](https://github.com/bytedance/DreamO)
- **OmniGen2**: Apache 2.0, no InsightFace dependency mentioned — licence-clean, but documented as weaker on facial similarity than PuLID-FLUX by the OmniGen2 authors themselves; some quality-instability GitHub reports. Plausible fallback, not a strong identity-cosine bet. — [OmniGen2 HF](https://huggingface.co/OmniGen2/OmniGen2), [GitHub issue re: quality](https://github.com/VectorSpaceLab/OmniGen2/issues/29)

**(5) Z-Image family (Tongyi-MAI).**
Z-Image-Omni-Base (generation+editing) and Z-Image-Edit variants exist, Apache 2.0, marketed for identity/lighting/style consistency under edits. No InsightFace dependency found in search. Worth a fast probe — same licence tier as Qwen, untested on our task so far, real candidate for the bakeoff given zero prior failed attempts on this family. — [Tongyi-MAI/Z-Image GitHub](https://github.com/Tongyi-MAI/Z-Image), [Z-Image LICENSE](https://github.com/Tongyi-MAI/Z-Image/blob/main/LICENSE)

**(6) FLUX.2 klein 9B / klein 4B alternate settings.**
klein-9B is **non-commercial** (FLUX Non-Commercial License, confirmed on LICENSE.md) despite supporting stronger multi-reference editing — **REJECT for our commercial requirement** regardless of quality. — [klein-9B LICENSE.md](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B/blob/main/LICENSE.md). klein-4B (Apache 2.0) is our only licence-clean FLUX.2 tier; no documented identity-cosine numbers found for klein-4B specifically at higher guidance/more-reference settings — this is the "try harder on what we have" branch, not evidenced to fix skin/age, since it already failed twice on the current stack.

**(7) Train-first: tiny Krea-2 LoRA on 3–8 anchor crops (ai-toolkit).**
Krea officially supports LoRA training from as few as 3 images via their own trainer; a third-party `ai-toolkit` extension (`lbouaraba/krea2edit-trainer`) exists specifically for Krea-2 identity-edit LoRAs, geometry-matched to `comfyui-krea2edit` nodes. Krea 2 LoRAs are reported to hold "style, character, and material identity" at a level above FLUX-family LoRAs, per Krea's own training-paper resolutions (256/512/1024, not 768). No independent third-party identity-cosine numbers found — this is Krea's own marketing plus one community trainer, not a benchmarked claim. Licence: Krea 2 Community License (revenue-gated <$1M/yr, else Enterprise licence needed) — flag this explicitly to Daniel since it's a *conditional* commercial licence, not unconditional like Apache. — [Krea 2 LoRA training blog](https://www.krea.ai/blog/krea-2-lora-training), [lbouaraba/krea2edit-trainer](https://github.com/lbouaraba/krea2edit-trainer), [Krea 2 Community License](https://www.krea.ai/krea-2-licensing)

**(8) Face-swap post-pass onto varied generations.**
- **ReActor / inswapper_128**: REJECT — InsightFace pretrained weights non-commercial. — [Gourieff/ComfyUI-ReActor](https://github.com/Gourieff/ComfyUI-ReActor)
- **HyperSwap** (FaceFusion's newer higher-res swapper): model itself is now **ResearchRAIL-MS**, commercial use requires contacting FaceFusion Labs directly. **REJECT** without a paid deal. — [WaveSpeed face-swap roundup](https://wavespeed.ai/blog/posts/open-source-face-swap-software/)
- **FaceFusion** (as of 2025 relicense): code moved MIT → OpenRAIL-AS (still permissive-ish but adds ethical-use clauses); individual models vary — HyperSwap is ResearchRAIL-MS, inswapper_128 is InsightFace non-commercial. Verify per-model, not per-repo. — [FaceFusion licenses page](https://docs.facefusion.io/introduction/licenses), [FaceFusion LICENSE.md](https://github.com/facefusion/facefusion/blob/master/LICENSE.md)
- **Ghost / Ghost 2.0** (ai-forever, formerly SberSwap): older (2022) one-shot face-swap, no explicit Apache/MIT confirmation found on the model weights in this search pass — licence needs direct repo verification before use, and quality is generally regarded as below inswapper_128. Unresolved, do not assume clean. — [ai-forever/ghost](https://github.com/ai-forever/ghost), [ai-forever/ghost-2.0](https://github.com/ai-forever/ghost-2.0)
- Net: **no verified commercially-clean high-quality face-swapper was found** in this pass. This path is currently blocked pending either a paid InsightFace/FaceFusion Labs licence or direct verification of Ghost's licence.

**(9) IP-Adapter FaceID for SDXL — REJECT.**
h94/IP-Adapter-FaceID weights are Apache 2.0 but the pipeline requires InsightFace `buffalo_l` embeddings; the maintainer's own repo states the models are released "exclusively for research purposes" because of the InsightFace dependency. **REJECT** on licence. — [h94/IP-Adapter-FaceID](https://huggingface.co/h94/IP-Adapter-FaceID), ["why non-commercial" discussion](https://huggingface.co/h94/IP-Adapter-FaceID/discussions/18)

**Also checked, not commercially viable:**
- **WithAnyone** (2026 SOTA multi-ID FLUX method, addresses copy-paste artifacts, reports SimGT 0.460 / SimRef 0.578 on MultiID-Bench): licensed **CC BY-NC-SA 4.0**. **REJECT.** — [WithAnyone paper](https://arxiv.org/html/2510.14975v1)
- **Nunchaku**: a quantization/inference *engine* (SVDQuant, 4-bit), not itself an identity method — it just runs PuLID faster on FLUX.1-dev; inherits (3)'s licence problems, doesn't solve them. — [nunchaku PuLID docs](https://nunchaku.tech/docs/ComfyUI-nunchaku/workflows/pulid.html)

## Ranked shortlist for the bakeoff (≤4)

**1. Qwen-Image-Edit-2511, Lightning removed, + tlennon-ie/qwen-edit-skin LoRA (weight 1.0-1.5), 24-28 steps, CFG ~2-3.**
Fully Apache 2.0 chain (Qwen-Image-Edit-2511 + skin LoRA), no InsightFace anywhere, single L40S/4090 fits FP8. Highest-confidence "cheapest fix to what already failed" — the 3 prior 2511 failures all ran through Lightning at 4 steps, which is independently documented to cause the exact plastic-skin symptom. Recipe: `QwenImageEditModelLoader` → LoRA loader (skin LoRA, no Lightning LoRA) → multi-ref conditioning (reference the one source image) → KSampler 24-28 steps, CFG 2-3 → texture-forward prompt language ("visible pores, fine vellus hair, subsurface skin scattering, no airbrushing"). Test identity cosine with a licence-clean embedder (FaceNet/facenet-pytorch, not ArcFace/InsightFace, to stay consistent with the commercial constraint even for internal QA).

**2. Z-Image-Edit / Z-Image-Omni (Tongyi-MAI), Apache 2.0, untried on this task.**
New model family, no InsightFace dependency found, marketed explicitly for identity+lighting+style consistency under edit instructions. Zero prior attempts here means zero confirmed failure mode — worth a same-cost probe before assuming the Qwen/FLUX architecture family is the bottleneck. Recipe: pull Tongyi-MAI/Z-Image-Edit (or Omni variant once role clarified) into ComfyUI via whatever native/community node ships first; single reference image + texture-forward prompt, moderate steps (20-30), no distilled/turbo LoRA on first pass to avoid the same plastic-skin trap as (1).

**3. PuLID (FaceNet loader) on FLUX.1-schnell, licence-clean tuning-free identity injection.**
Only fully commercial-clean PuLID variant: `lldacing/ComfyUI_PuLID_Flux_ll`'s `PulidFluxFaceNetLoader` (MIT, facenet-pytorch/VGGFace2, no InsightFace download) + FLUX.1-schnell (Apache 2.0) instead of the documented-but-non-commercial FLUX.1-dev backbone. Unverified combination (docs assume dev) — the bakeoff run is also the licence-clean feasibility test. Recipe: Load FLUX.1-schnell checkpoint, PuLID node chain from lldacing's repo, swap InsightFace loader for `PulidFluxFaceNetLoader`, few-step schnell sampling (4-8 steps per schnell's design), separate high-step img2img polish pass afterward for skin texture since schnell is a distilled/fast model prone to the same over-smooth failure mode as Lightning.

**4. Train-first Krea-2 LoRA (ai-toolkit / krea2edit-trainer) on 3-8 crops of the single reference.**
Different failure class entirely — instead of asking one-shot edit models to hold identity+age+skin simultaneously, bake identity into weights first, then let plain Krea-2 sampling (with more room for texture/lighting variance) do the seed-set generation. Higher setup cost (needs upscale/crop augmentation from the single source image since 3-8 real anchors don't exist yet), and the Krea 2 Community Licence is revenue-conditional (<$1M/yr) rather than unconditional — flag this explicitly before committing, since it's a different licence *class* than the Apache options above. Recipe: `lbouaraba/krea2edit-trainer` (ai-toolkit fork) at 512-1024 res, LoKr per the community guide, then generate pose/lighting variants directly from the trained LoRA + Krea-2-Raw/Turbo base with texture-forward prompts.

**Not recommended for this bakeoff**: anything touching InsightFace pretrained weights (PuLID-Flux2/klein, InfiniteYou, IP-Adapter-FaceID, ReActor, HyperSwap) — licence-blocked outright; UNO/DreamO/WithAnyone — non-commercial weights; klein-9B — non-commercial base regardless of quality; OmniGen2 and InstantCharacter — licence-ambiguous or self-reported weaker-than-PuLID identity fidelity, keep as tier-2 fallbacks only if all four above underperform.
