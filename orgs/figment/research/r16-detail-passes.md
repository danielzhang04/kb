# R16 — detail passes for the FLUX.2 klein / Z-Image stack

Research date: 2026-09-03. Public, read-only review; no models or package files were downloaded. `accessed 2026-09-03` below is the source date where a publication date is not available. A blank/unknown licence means **do not put it in a production manifest**. “Adds” means observable high-frequency variation is introduced; it does not mean the result is automatically natural.

## 1. Recommended stage-5 pass chain

The ordered default is deliberately short: no second diffusion model, no SDXL refiner, and no “beauty” LoRA. Those commonly replace skin rather than recover it. Every external repository below can be placed in the pod harness `custom_nodes` list as a public HTTPS Git URL and every model in `models` as `{repo_id, filename, destination_dir}`. SHA pins reflect the repository head seen on 2026-09-03; re-check the licence and smoke-test the exact pin before a manifest is promoted.

### De-gloss ranking

| rank | method | conclusion and evidence |
|---:|---|---|
| 1 | Conservative Detail Daemon or Lying Sigma sampler, no negative prompt | Best licence-clean model-side candidate because it manipulates the sampling sigmas rather than adding a “perfect skin” checkpoint; its author says it enhances details and warns that excess yields HDR/oversharpening. Trial at one low setting only and retain only on measured texture increase plus eye-gate. [MIT repo](https://github.com/Jonseed/ComfyUI-Detail-Daemon) |
| 2 | Deterministic fine grain + local tonal/highlight compression, after upscale | Most controllable anti-plastic treatment: it adds noise/texture without generating a new face. It cannot reconstruct true pores; use it as de-gloss only if the human panel says specular highlights no longer read plastic. ProPost is MIT; the tonal operation can remain ComfyUI core. [ProPost](https://github.com/digitaljohn/comfyui-propost) |
| 3 | Same-base low-denoise i2i with a licence-cleared texture LoRA | Plausible, but highest risk of identity/register drift. The only Z skin LoRA located has no displayed licence, and no klein asset was located; do not adopt before licence and 12-cell evidence. [Z asset](https://huggingface.co/lastremorse/z-image-Realistic-Skin-Texture-style-lora) |
| 4 | “Realistic skin” / gloss-reduction community LoRAs | Reject by default: searched public assets are commonly SDXL-targeted or do not expose a licence, so they are neither plug-compatible evidence for Z/klein nor commercially clear. |

### Targeted klein edit (“Flux2Edit” pattern)

Use the official 4B Base edit template, not a separate `Flux2Edit` package: load final image (and mask if local), `UNETLoader(flux-2-klein-base-4b-fp8)` + Qwen3 encoder + VAE/small decoder, encode image as the edit/reference latent, add the corrective text conditioning, sample, decode and composite/save. A second anchor/reference may be chained through `ReferenceLatent`; BFL documents up to four references. For a local defect, crop/mask the smallest viable region, preserve the original image as the main edit reference, use 0.20–0.35 denoise-equivalent/intervention, then re-run identity and QA. This is in-place regeneration, not pixel retouching; do not promise exact preservation. The official template lists its model file locations and ComfyUI documents the Base edit workflow. [template](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_flux2_klein_image_edit_4b_base.json), [guide](https://docs.comfy.org/tutorials/flux/flux-2-klein), [BFL overview](https://docs.bfl.ai/flux_2/flux2_overview).

`SUPIR` is excluded even as a trial: its Comfy wrapper publishes a non-commercial-only condition. `Ultimate SD Upscale` is SD-pipeline-shaped (model + CLIP inputs); it may be adapted for Flux by community graphs but is not the default native klein/Z path. Its source therefore does not establish skin preservation for our bases. [SUPIR wrapper](https://github.com/kijai/ComfyUI-SUPIR), [Ultimate SD Upscale](https://github.com/ssitu/ComfyUI_UltimateSDUpscale).

## 2. QA scorer shortlist and trial thresholds

Thresholds are starting triage thresholds, not universal quality claims. Calibrate on 60 labelled outputs (20 known-good, 20 known-fail, 20 borderline) before a route is automated. None detects a “literal liner” semantic failure reliably alone.

| gate / availability / licence | provisional threshold to trial | catches / limitation |
|---|---|---|
| Existing FaceNet anchor cosine + DINO cohesion; local script; facenet-pytorch MIT, DINOv2 Apache-2.0 | no detected face = fail; anchor cosine below the persona’s held-out 5th percentile = fail; do not copy a generic public cosine threshold | Face swap, mask-like identity drift, missing face. It is the primary identity gate, not an aesthetic score. |
| MagFace quality; external post-run Python, no Comfy node found; Apache-2.0 code | per-persona 10th percentile of good-face embedding magnitude = review/fail; require detector confidence separately | Blur, extreme pose/occlusion and weak face crop. It is a face-recognition utility score, not a beauty score. [MagFace](https://github.com/IrvingMeng/MagFace) |
| Variance of Laplacian + clipped-highlights/shadows + local luminance variance; core Python/OpenCV BSD-3-Clause | Laplacian below 20th percentile of accepted cohort = review; clipped pixel fraction >1% = review; local variance must not fall >15% after “enhancer” | Blur, flat/plastic skin, crushed or blown exposure. Thresholds need resolution-normalisation and same-crop comparisons. |
| LAION aesthetic score; `git-geeky/ComfyUI-QualityGate` has a node but repo licence was not found: hold; LAION predictor licence must also be checked | initially route bottom 15% of accepted baseline to review, not a hard numerical fail | Global low-quality/boring outputs. It can prefer stylised images and will not validate garment rendering. [LAION description](https://projects.laion.ai/laion-datasets/laion-aesthetic.html), [node](https://github.com/git-geeky/ComfyUI-QualityGate) |

## 4. Evaluation plan on our outputs

Use one adult, synthetic/owned Instagram-tier scene set; no explicit-tier data on a pod. Generate the base once per cell seed, retain the unmodified PNG, then run passes deterministically. The build terminal can express the four manifest branches as disabled/enabled workflow groups and retain all intermediate images.

| factor | levels | cells |
|---|---:|---:|
| base arm | klein Base; Z Base | 2 |
| face repair | bypass; conditional FaceDetailer/native klein edit only when detector flags a weak face | 2 |
| detail chain | bypass; Detail Daemon only; Detail Daemon + grain | 3 |
| total | 2 × 2 × 3, same seed/prompt/reference for each six-way family | **12** |

For every cell: record base/candidate FaceNet cosine against anchor, DINO cohesion, face-detection result, crop-local Laplacian variance, crop-local luminance variance, clipped-pixel fraction, OCR result, garment/clothed classifier result, and runtime/VRAM peak if obtainable. Compare each candidate to its own base, not across base arms. A texture pass is eligible only if (a) identity remains above the persona floor, (b) crop texture metric rises without clipping/halo evidence, (c) no QA hard failure occurs, and (d) blinded human eye-gate prefers it for natural pores/sensor character rather than gloss. Keep a rejected-pass contact sheet; it is evidence for the “does not smooth/relight” rule.
