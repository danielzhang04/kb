# RECUT reconciliation plan — poyais-end restoration, minimal fixes, condensation

## Decision law

This plan uses `fa104c60` as the poyais-final working anchor and the per-file E1 snapshots recorded in
`era-map.md`. The execution order is strict:

1. restore the poyais-end text for the section, byte-for-byte;
2. retain post-poyais text or behavior only when the minimal fix set or the drift-ledger keep-list names
   it;
3. delete every indicted addition; and
4. move each rule topic to the single home assigned by `contradiction-map.md`, without rewording the moved
   text.

`KEEP-MODERN` below never means “keep the surrounding current section.” It means only the named passage or
behavior in the modern-survivor budget. Registry data follows the same restoration rule: poyais facts stand,
and a post-poyais row or field survives only when a minimal fix or keep-list commit names the change. Code is
restored by behavior, not by copying obsolete implementation text into current interfaces. Prompt-order
behavior is the one deliberately gated exception: the current suffix-tail arm remains until the same-seed
A/B decides whether the poyais payload-final arm is promoted.

Historical quotations use the file snapshot SHA and one-based line numbers. Where a long section is not
printed in full, its first and last substantive lines and inclusive line count identify the exact range;
the count includes any blank/separator lines inside the cited range.
