## Work order

An agent-owner cadence card can never launch. `queueBridge.ts#cardToWorkflowRequest` (~line 513)
synthesizes the stage target from `card.meta.target`, which `scripts/cards.py#schedule_occurrence_claim`
sets to `agents/<agent>.md`. `workflows/defs.ts:954-956` requires the target to be inside the
definition's org tree, so every claim of an agent-owner cadence fails that check. This blocks
re-arming the nine cadences disarmed in production (p8 snapshot,
`C:\Users\danie\kb-rehearsal\tooling\rehearsal\p8\prod-schedules-before.json`).

Fix belongs in one of two places (pick one, document the choice): (a) the claim renderer — set the
target to the agent's declared cadence output directory under `orgs/kb-ops/` instead of
`agents/<agent>.md`; or (b) the bridge synthesis in `cardToWorkflowRequest` — accept an
agent-owner target shape without requiring it inside the definition's org tree, gated by the
`cadence` execution profile (shipped in PR #204) so authority is not widened.

## Acceptance

- A claimed agent-owner cadence card produces a stage target that `workflows/defs.ts` accepts,
  and the bridge launches it.
- At least one of the nine disarmed cadences re-arms and completes a real dispatch on prod (or in
  rehearsal against a prod-shaped snapshot) without a `defs.ts` target rejection.
- The fix does not widen any cadence's authority beyond its existing risk tier (profile/allowlist
  from PR #204 stays authoritative).
