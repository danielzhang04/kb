## Work order

[HIGH] Two related drain findings D2/D3 (P3 rehearsal):
- D2: an unclean stop can leave `/var/lib/kb/ops/.git/index.lock` behind. Every audit-bearing
  write then fails 500 `*-audit-required` forever (reads stay 200, masking the problem), because
  nothing detects or clears the stale lock at boot.
- D3: if `/var/lib/kb/ops/.git/index` ends up root-owned (e.g. from a root-run recovery step),
  writes fail `outbox-recovery-failed` 503.

Fix: add boot-time detection in `validate_vm_runtime.py` for both conditions — a stale
`.git/index.lock` (with a clear journal line identifying it, not just an opaque 500) and
incorrect ownership on `.git/index` — so both surface immediately at boot instead of silently
failing every subsequent write.

## Acceptance
- `validate_vm_runtime.py` detects a stale `.git/index.lock` at boot and emits a clear,
  greppable journal line.
- `validate_vm_runtime.py` detects wrong ownership on `.git/index` at boot and emits a clear
  journal line (or fixes it, if that's judged safe — document the choice).
- Test/simulation for both conditions (lock file present; index root-owned) against the
  validator.
