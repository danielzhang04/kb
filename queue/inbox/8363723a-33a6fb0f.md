## Work order

`deploy/export_tier0.py` (resident copy at `/usr/local/lib/kb/export_tier0.py` on the VM) stops
`kb-dashboard.service`, archives tier-zero, restarts the service and then REQUIRES `/readyz` to
report `quiescent:true` without `execution-unlocked` ("service did not restart locked"). Under
the tailnet-trust deployment the service re-arms at boot by design (`/readyz` →
`blockers:["execution-unlocked",…]`), so every export now exits 1 AFTER writing a valid archive
(observed 2026-08-20 21:09Z: archive 1.2 GB written, rc=1). `scripts/backup_tier0.py backup`
treats that rc as a failed export, so the desktop backup path is broken on the live VM.

Change the post-restart check so it asserts what tailnet mode actually guarantees (service active,
`ok:true`, readiness within the timeout) and keeps the "locked" requirement only for the WebAuthn
mode where it holds — derive the expectation from `DASHBOARD_AUTH_MODE`, do not add a flag. Update
the tests; then re-install the resident copy (`install -o root -g root -m 0555`) as part of the
next release's resident install.

## Acceptance
- `py -3 -m pytest -q tests/test_export_tier0.py tests/test_backup_tier0.py` green, with a test
  for the tailnet-mode restart expectation.
- On the VM: `sudo python3 /usr/local/lib/kb/export_tier0.py --output /var/tmp/x.tar` exits 0 and
  leaves the service active.
