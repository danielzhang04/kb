## Work order

[MEDIUM] Drain finding D1 (P3 rehearsal): the execution latch that gates drain/reconciliation is
held only in memory — it does not move `documentRevision`, so any process restart silently drops
the lock. A drain that then runs after the restart pushes successfully but dies afterward with
"ops reconciliation requires quiescent runtime", because the runtime no longer looks locked to
the drain tooling even though the intended lock state was "held".

Fix: either persist the latch (so it survives a restart and correctly reports held/not-held), or
make the reconciler tolerate a re-lock across a restart without treating it as a fresh acquire.
Until this ships, the operational rule (stated in the runbook) is: do not restart the control
plane mid-drain.

## Acceptance
- Latch persistence or reconciler re-lock tolerance implemented (pick one; either satisfies this
  card).
- Test: a simulated process restart mid-hold does not cause the subsequent drain to fail with
  "ops reconciliation requires quiescent runtime".
- The runbook rule ("don't restart control plane mid-drain") stays documented until this ships,
  and is removed/updated once it does.
