\## Findings

1. **HIGH — Flattening the parent ACL changes Windows’ canonical ACE order, so valid restores cannot start.**  
   `pilot-recovery.ps1@BFEC`, lines 387–395, compares the manually derived ACE sequence against the envelope’s post-`Set-Acl` sequence byte-for-byte. But lines 542–548 strip `ID` from every parent ACE, collapsing originally explicit and inherited ACEs into one explicit group. Windows then canonicalizes that group.

   Both supplied reports show the result:

   - Expected projection order began `1004, application SID, SY, BA, 1001`.
   - Windows stored `SY, BA, 1001, 1004, application SID`.
   - Both normal and protected cases stopped with exit 4 before creating the payload child: [normal report](C:/Users/danie/Projects/Filesystem-Cleanup/fixtures/atlas-design-selftest/parent-normal-781b1b1b/recovery/report.json:40), [protected report](C:/Users/danie/Projects/Filesystem-Cleanup/fixtures/atlas-design-selftest/parent-protected-6bbfeae6/recovery/report.json:45).

   Do not fix this with an order-insensitive comparison: child ACE order and inherited state are part of the recovery contract. The envelope must preserve the parent’s explicit/inherited provenance, then Windows—not a hand-written ordering rule—must materialize the child ACL.

2. **MEDIUM — `Get-InheritedAces` does not enumerate ACEs individually.**  
   Lines 381–383 pipe the array returned with `Write-Output -NoEnumerate` directly into `Where-Object`. PowerShell 5.1 passes the array as one pipeline object, so the predicate effectively uses the first ACE’s flags for the entire collection.

   Isolated PowerShell 5.1 verification:

   ```text
   assignedType=System.Object[];assignedCount=2
   pipelineCount=1;pipelineValues=System.Object[]
   foreachCount=1;foreachValues=A;ID;x
   ```

   A mixed explicit/inherited source can therefore be treated as all inherited or none inherited. In particular, an explicit-first source with stale inherited ACEs can evade the intended pre-output stale-inheritance check when the current parent derives no ACEs. Use a language-level `foreach` and append only individual ACE strings containing `ID`.

3. **MEDIUM — The protected envelope copies permissions unrelated to child inheritance.**  
   Lines 542–548 copy every parent ACE and merely remove `ID`. A non-inheritable parent-only ACE is therefore converted into a direct ACE on the recovery envelope even though it contributes nothing to the pilot child’s ACL.

   This unnecessarily expands custody and may grant an unrelated principal traversal, listing, or `DELETE_CHILD` authority over the recovery location. Construct the envelope from inheritance-relevant ACEs only, with one narrowly scoped, non-inheritable administrative ACE if required by the owning user.

4. **MEDIUM — Source and parent baselines are not kept consistent through preflight and envelope creation.**  
   The source manifest is captured at line 530, but the independently read source ACL at lines 538–541 is never checked against `A.directory.sddl`. The parent DACL is captured once and never revalidated before the three sensitive envelope creations at lines 596, 629, and 642.

   A persistent source change will eventually be caught by A/B comparison, but only after outputs have been created. A parent change can go undetected entirely, leaving `original-parent.json` and future-inheritance behavior based on stale state. Before any output, require exact equality between manifest A and the separately read source descriptor. Record the parent’s identity and DACL, then revalidate both before every envelope creation.
