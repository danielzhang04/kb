   Runs, stages, attempts, managed sessions, proposals, events, human requests, review state, and quarantine bundles persist together in `DASHBOARD_STATE_ROOT/control/control-plane.json`; its JSON document arrays are defined at `dashboard/server/control/store.ts:267-282`, loaded/saved atomically at `:4367-4397`. On the VM this resolves to `/var/lib/kb/state/control/control-plane.json` via the unit’s `DASHBOARD_STATE_ROOT` (`[cutover] deploy/systemd/kb-dashboard.service:12-14`).

   Managed-session durable fields—including broker steering queues and receipts—are mediated through that same control store (`dashboard/server/control/brokerStore.ts:11-90`).

   Queue-bridge runtime state is memory-only: `running` and interval `timer`; there is no cursor/lease file (`dashboard/server/control/queueBridge.ts:169-209`). Its input truth is the queue-card filesystem scan.

   PTY “persistent sessions” are process-local `Map` entries over live handles, despite the name (`dashboard/server/pty/persistentSessions.ts:118-121,260-267`). 2. On startup, the file control store loads then calls `normalizeCrash()` and re-saves changed state (`dashboard/server/control/store.ts:4395-4397`). It:
   - changes `running`/`recovering`/`stopping` runs to `interrupted`, except an undispatched activation becomes `waiting-human` (`:1937-1942`);
   - changes running stages and starting/running attempts to `interrupted` (`:1952-1964`);
   - changes starting/running/waiting managed sessions to `interrupted` and clears broker stop intent (`:1966-1975`);
   - appends a recovery lifecycle event (`:1294-1321,1977-1980`).

   Therefore today it does not resume in-flight execution. It records interruption; only pending activation has the special waiting-human recovery path. Composer running turns are likewise normalized to interrupted (`dashboard/server/composer/store.ts:366-381`).

3. No child attachment mechanism exists. Managed broker ownership is a process-local `#live: Map<string, LiveSession>` containing the `ManagedChild` handle (`dashboard/server/control/broker.ts:95-118,154-171`); the persisted contract contains logical session data, not PID/handle. \## D. Restart semantics / “armed at boot”

7. The VM systemd unit starts Node directly at `/opt/kb-releases/current/dashboard/server/index.ts`, with repo `/var/lib/kb/ops` and state `/var/lib/kb/state` (`[cutover] deploy/systemd/kb-dashboard.service:9-16,28-31`). Bootstrap installs/enables that unit and seeds the control-plane file (`[cutover] deploy/bootstrap_vm.py:164,178-185`).

   “Armed at boot” is not `DASHBOARD_EXECUTION_ACTIVATED=1`: the unit explicitly sets it to `0` (`[cutover] deploy/systemd/kb-dashboard.service:14,19-23`). Instead `DASHBOARD_AUTH_MODE=tailnet` causes `createExecutionLatch()` to construct an unlocked tailnet-sourced executor at every process boot (`[cutover] dashboard/server/control/activation.ts:729-736`). Its surface callback starts the queue bridge for `tailnet` or passkey arms (`[cutover] dashboard/server/http/surface.ts:320-352`).

   The latch state and constructed executor are only `let` variables in process memory (`[cutover] dashboard/server/control/activation.ts:697-725`); the code explicitly says unlocked state is not persisted (`:690-695`). Thus a restart “re-arms” by recomputing tailnet mode from unit environment, not by reading a lock-state file. In the main checkout, the older behavior is solely `DASHBOARD_EXECUTION_ACTIVATED === '1'` (`dashboard/server/control/activation.ts:106-108`) and PM2 leaves it unset/commented (`dashboard/pm2.config.cjs:81-86`).

Restart-kills-what, hardest resumability first:

- Active worker process plus its live transcript/stdin/timeout/cancel closure; no durable PID or continuation token.
- In-flight run/stage/attempt/session ownership: persisted, but startup deliberately marks it interrupted.
- Managed broker live-child map and current revision/stop handle; durable steering survives, but execution ownership does not.
- Queue-bridge interval and single-flight state; restart recreates it only when tailnet/passkey-arm logic runs.
- Live PTY and Composer/vibe child sessions; their process-local registries die, while Composer metadata remains and running turns are marked interrupted.
