## Result

The design is close, but I would not approve implementation unchanged. Four blockers should be resolved first. “No sanitation” is supportable once the pre-Git byte gate is made explicit.

\## Blockers

1. **`for-each-ref -z` is invalid in Git 2.51.**

   The proposed command at [ait25-git-inspection-design-v2.md](/C:/Users/danie/Projects/Filesystem-Cleanup/plans/ait25-git-inspection-design-v2.md:105) will fail. Git 2.51’s documented options do not include `-z`; NULs are available inside `--format` through `%00`. [Official Git 2.51 `for-each-ref` documentation](https://git-scm.com/docs/git-for-each-ref/2.51.0).

   Use newline-delimited records with tab-delimited fields:

   ```text
   for-each-ref --format=%(refname)%09%(objecttype)%09%(upstream)%09%(upstream:track,nobracket)
   ```

   Git refnames cannot contain tabs or newlines, so this is unambiguous and simpler than mixing NUL fields with Git’s automatic row newline.

2. **The accepted config evidence is not explicitly re-bound before the first Git process.**

   P0’s full-tree comparison would indirectly pin the configs if implemented perfectly, but [P0-5](/C:/Users/danie/Projects/Filesystem-Cleanup/plans/ait25-git-inspection-design-v2.md:89) never defines how it “finds” unexpected config keys. Discovering them with `git config` is too late: Git has already loaded the config.

   Before any Git invocation, require all four copied `.git/config` files to freshly match their corresponding manifest entries on:

   - exact path and regular-file/non-reparse status;
   - length;
   - SHA-256.

   Then rely on the already accepted inspection/adjudication for that exact manifest:

   - no active hooks, includes, credentials, command-bearing or path keys;
   - only safe core keys, SSH GitHub remotes, branch tracking, and the recorded `submodule.active`;
   - no selected external Git-store pointers.

   This makes “no sanitation” defensible. Do not add another general Git-config parser. Bind the accepted config-adjudication and boundary reports—or pin their reviewed hashes—rather than relying on the ambiguous empty `additionalKnownKeys` follow-up alone.

3. **Git identity needs an expected hash, not merely a before/after self-consistency check.**

   I safely observed the exact launcher:

   ```text
   path:    C:\Program Files\Git\cmd\git.exe
   version: git version 2.51.0.windows.1
   SHA256:  34A408843194BE320D8A87A3C12CD5C7D2E08D03B24567A41DB32E21D12569D2
   size:    46480
   ```

   Thus the version in [the design](/C:/Users/danie/Projects/Filesystem-Cleanup/plans/ait25-git-inspection-design-v2.md:50) happens to be correct, but the design must pin the observed SHA as an independently reviewed input/constant and check:

   ```text
   expected hash == pre-run hash == post-run hash
   expected version == observed version
   ```

   A pre/post equality check alone accepts a consistently wrong launcher. Retain the existing limitation that this pins only the `cmd\git.exe` launcher, not its DLL/helper chain.

4. **Do not implement Phase W in this first stage.**

   The selected runtime is Ubuntu/WSL, and all four repositories contain LX dependency links. Windows `status --untracked-files=all` introduces worktree traversal, normalization ambiguity, and a possible index-refresh path without completing the required Ubuntu acceptance.

   Make v1 strictly G1-only. Defer unstaged, untracked, ignored, executable-bit, link, mount, and editor observations to the reviewed Ubuntu stage. Consequently:

   - remove Phase W;
   - remove `check-ignore`, which was only needed for the Phase W gate;
   - label this result “Git administration/index/object inspection,” not complete repository-state acceptance.

\## Important improvements

- Replace the proposed new full-tree Python pre/post walker with manifest-selected checks. The accepted native copier already performs complete full-fidelity verification. Reimplementing that proof in Python duplicates the recently accepted copier and creates a second metadata interpretation.
- Freshly snapshot only plausible Git mutation/control surfaces before and after: `config`, `HEAD`, `index`, `shallow`, `packed-refs`, manifest-selected `refs/**`, `logs/refs/stash`, and the relevant `.git` directory child-name sets. Include byte hash, length, attributes, and `mtime_ns`.
- Narrow the claim accordingly: “selected Git state and control surfaces unchanged,” not “every byte in the entire analysis copy unchanged.” If whole-tree post-Git equality is mandatory, invoke the accepted native verifier rather than authoring another validator.
- Treat any `*.lock`, `MERGE_*`, rebase or sequencer state in this fresh analysis copy as a refusal or explicit repository deferral, not merely an informational field. It otherwise weakens the stable-snapshot premise.
- Replace “network use is shut off” with “no expected Git transport path remains.” `protocol.allow=never` controls Git transports, and `GIT_NO_LAZY_FETCH=1` disables promisor lazy fetch, but there is no OS network boundary. [Git protocol policy](https://git-scm.com/docs/git-config/2.51.0), [Git environment documentation](https://git-scm.com/docs/git/2.53.0.html).
- Keep `credential.helper=`; an empty helper value resets the helper list. [Official credential documentation](https://git-scm.com/docs/gitcredentials).
- `stash list --format=%H -z` may remain: `stash list` accepts log options, and Git log documents `-z` as the commit separator. [Git stash](https://git-scm.com/docs/git-stash), [Git log 2.51](https://git-scm.com/docs/git-log/2.51.0).

\### 2. Environment and prefix


Use this fixed prefix:

```text
git.exe --no-pager --no-optional-locks --no-replace-objects
  -C <exact-repo>
  -c core.hooksPath=<empty-hooks>
  -c init.templateDir=<empty-template>
  -c core.fsmonitor=false
  -c core.untrackedCache=false
  -c core.autocrlf=false
  -c commit.gpgSign=false
  -c protocol.allow=never
  -c gc.auto=0
  -c maintenance.auto=false
  -c core.attributesFile=<empty-attributes>
  -c credential.helper=
  -c core.askPass=
  -c submodule.recurse=false
  -c core.pager=cat
```

`--no-optional-locks` and `--no-replace-objects` are supported global options. [Official Git documentation](https://git-scm.com/docs/git/2.34.0).

`core.sshCommand=false` is unnecessary and gives a misleading impression of an OS network boundary; omit it.
