\## 3. Preserving `localhost` for WebAuthn

Use an **SSH local port forward over Tailscale**, for example:

```powershell
ssh.exe -N -L localhost:5317:127.0.0.1:5317 user@vm-name
```

Then browse exactly `http://localhost:5317`.

This is transparent TCP forwarding: the browser still generates `Origin: http://localhost:5317` and `Host: localhost:5317`, leaving WebAuthn RP-ID `localhost` unchanged. Tailscale supplies the private path to SSH. [SSH over Tailscale](https://tailscale.com/docs/reference/ssh-over-tailscale), [WebAuthn RP-ID rules](https://www.w3.org/TR/webauthn-3/#relying-party-identifier)

Do **not** use:

- `tailscale serve`: browser URL becomes `https://node.tailnet.ts.net`.
- Funnel: also uses `*.ts.net` and makes the service public.

Both silently change the origin and break the existing passkey binding. [Serve example](https://tailscale.com/docs/reference/examples/serve), [Funnel documentation](https://tailscale.com/docs/reference/tailscale-cli/funnel)

“Zero local compute” therefore means zero workload compute; the desktop still runs tiny Tailscale and SSH tunnel processes.
