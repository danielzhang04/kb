\## Findings

**HIGH — first visible wake frame can expose stale bands.**  
[worker/wakeword.py:360](/C:/Users/danie/Atlas-worktrees/u3/worker/wakeword.py:360), [worker/app.py:605](/C:/Users/danie/Atlas-worktrees/u3/worker/app.py:605), [tests/test_wakeword.py:228](/C:/Users/danie/Atlas-worktrees/u3/tests/test_wakeword.py:228)

The band gate is evaluated before `model.predict()` and the wake event. While asleep, the wake-triggering frame therefore skips band computation. `on_wake()` then asynchronously queues `_engage`, which changes the publisher to `LISTENING`; that makes `StatePublisher.audio_bands` expose the retained pre-sleep `_audio_bands` until the next 80 ms frame.

The new test does not model this ordering: its predicate changes after three arbitrary predictions, its model never fires a wake event, and it never exercises the asynchronously queued engagement. It also cannot detect that `smoothed_bands` retains pre-sleep values.

Minimal fix: when a sleeping frame fires `"wake"`, compute bands from a reset/zero prior and schedule the signal before scheduling engagement, so the stored bands are fresh before `ASLEEP` is cleared. Replace or extend the test with a real wake-score transition that asserts:

- no asleep-frame FFT calls;
- one FFT call on the wake-triggering frame;
- the first computation does not use pre-sleep smoothing state;
- signal publication is ordered before engagement becomes visible;
- inference still runs on every frame.

**MEDIUM — audio-follow restart handling silently changed from restart to no-op.**  
[worker/devicewatch.py:464](/C:/Users/danie/Atlas-worktrees/u3/worker/devicewatch.py:464)

The moved `start_audio_follow` changed `request_restart` from `_restart_worker` to `lambda _reason: None`. The production app passes `restart_coalescer.request`, so its present wiring is safe, but direct callers that omit the argument now silently suppress required restarts. The repointed tests omit it and never invoke the captured follower-failure path, so they do not detect the changed default.

Minimal fix: make `request_restart` a required keyword-only argument and pass explicit stubs in tests, adding one wiring assertion that invokes the follower failure callback and observes the restart request.
