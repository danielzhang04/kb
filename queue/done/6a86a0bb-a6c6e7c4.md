\## Part B — lean proposal

1. **High value / low-medium effort: extend the existing dashboard Panels surface with one Fleet panel and `GET /api/panels/fleet`.**  
   It should show one row per instance: role, host, start mechanism, URL/pipe, observed state and age, code SHA, and probe result. Reuse the existing panel route/UI pattern, not `dashboards/system-map.md` as a live surface. Preserve explicit states: `healthy`, `degraded`, `stopped`, `stale-report`, `unknown`—never equate “no report” with stopped.

2. **Make that API the single entry point; add a CLI that prints it.**  
   `scripts/fleet_status.py` should request the Fleet API and render the exact same rows for a terminal/bookmark workflow. The VM row must consume the movement design’s authoritative loaded-release status and `/readyz`; it must not reimplement deploy/release detection.

3. **Use existing processes as reporters—no new daemon.**  
   - Refactor the existing desktop watchdog into a read-only desktop snapshot reporter (PM2/task/Atlas/local-port checks), and remove its legacy “restart `kb-dashboard`” behavior after the rollback window.  
   - Have the existing display dashboard heartbeat its own `{port:4630, mode:display-only, loaded SHA}` to the Fleet endpoint; expire it quickly if heartbeats stop.  
   - Have `codex_dispatch.py` report its already-existing marker lifecycle. This makes current background dispatch visible without inventing another worker.

4. **Retire rather than decorate.**  
   - After the documented cold-standby window: delete the stopped `kb-dashboard` PM2 registration and its resurrection/watchdog path; retire the legacy VM user-unit/`~/kb*` stack as specified in the cutover end-state document.  
   - Do **not** delete `dashboard-prod`, `dashboard-ops`, display `:4630`, or `%LOCALAPPDATA%\kb-codex-dispatch` yet: they are rollback/live assets.  
   - Prune the one explicitly prunable nonexistent worktree, then inventory the remaining 40 before any cleanup. Keep disabled scheduler tasks labeled “disabled/standby” until their owners decide their replacement.

Scope boundary: release SHA/activator/watchdog semantics and retirement timing belong in `docs/specs/2026-08-20-desk-vm-movement-design.md`; this proposal only consumes and presents them. Inbox, assets/memory/credentials, and Atlas API/product work remain with the sibling design.
