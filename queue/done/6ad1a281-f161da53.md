\## Minimal operation flow

1. `Prepare`

   - Fixed roots only:
     - `C:\Users\danie\source\repos\ait25`
     - `C:\Users\danie\Projects\NYU\ait25`
   - Validate pinned capture/restore scripts and accepted recovery generation.
   - Confirm destination is absent; Win32 errors other than 2/3 are unknown, not absent.
   - Compare source root volume serial with destination-parent volume serial.
   - Take a fresh full AIT25 snapshot and compare it to the accepted recovery manifest.
   - Create a durable checkpoint and initial journal record outside both project paths.
   - Store the class-18 root identity, full snapshot digest, exact helper hashes, parent identities/security evidence, window, and declared exceptions.

2. `Apply`

   - Require the explicit approval packet and active writer-pause window.
   - Re-read the checkpoint and helper pins.
   - Take another full source snapshot and require exact equality with the prepared snapshot.
   - Recheck destination absence and parent identities.
   - Flush `rename:intent` before mutation.
   - Call `TryMove(source,destination)`.
   - Regardless of return code, inspect both names using the pinned class-18 root identity:
     - old absent + new pinned root → renamed;
     - old pinned root + new not pinned root → source-in-place;
     - anything else → unknown, stop and preserve.
   - Take a full destination snapshot and compare it with the pre-rename snapshot.

3. `Resolve`

   - Strictly read-only.
   - Ignore optimistic journal labels when path/identity observations disagree.
   - Recognize `not-started`, `source-in-place`, `renamed`, and `renamed-unjournaled`; otherwise return `STOP-PRESERVE`.
   - Never repair or append to the journal.

4. `Rollback`

   - Separate approval and fresh pause.
   - Require old path absent, destination holding the pinned root identity, and a fresh full destination snapshot equal to the accepted post-move snapshot.
   - Refuse any source collision.
   - Flush reverse-rename intent, perform the same no-replace rename, resolve both paths afterward, and verify the full source snapshot.
   - Any addition, deletion, byte change, metadata change, identity change, malformed journal, or unobservable path stops rollback.
