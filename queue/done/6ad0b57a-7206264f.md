\## Capture record

For every entry, record the smallest metadata sufficient to detect unsupported state and reproduce the observed tree:

- Exact UTF-16 relative path, kind and attributes.
- Creation and last-write times.
- File length and SHA-256.
- 128-bit file ID, volume serial and link count for source-drift detection only.
- `EaSize` and query status.
- Stream names, sizes and allocation sizes.
- Owner/group/DACL security descriptor bytes, SDDL and DACL protection state. SACL remains explicitly `UNKNOWN`.
- Directory `FileCaseSensitiveInfo`.
- For LX leaves: tag, complete raw reparse buffer, buffer SHA-256/base64, version and strictly decoded UTF-8 target.
- For Git administration: bytes are preserved opaquely; configuration contents are neither interpreted nor emitted.

Use the same APIs already exercised by the reviewed work:

- `CreateFileW` with `FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_BACKUP_SEMANTICS`.
- `GetFileInformationByHandle` and `GetFileInformationByHandleEx`:
  - class 18, `FileIdInfo`
  - class 7, `FileStreamInfo`
  - class 23, `FileCaseSensitiveInfo`
  - classes 11/10 for no-follow directory enumeration
- `NtQueryInformationFile(FileEaInformation)` for EA size.
- `GetKernelObjectSecurity` for owner/group/DACL.
- `DeviceIoControl(FSCTL_GET_REPARSE_POINT)` for exact LX bytes.

No path-based read may replace these handle-based probes, and reparse entries are always terminal leaves.

\## Conditional feature route

The metadata reader is still under review, so its results must not be invented or treated as accepted evidence.

Proceed with the minimal native route only if the fresh AIT25 observations establish:

- All non-LX entries have `EaSize == 0`.
- Files have only the unnamed `::$DATA` stream and directories have no streams.
- Every regular file has link count one.
- Directory case flags are zero, or nonzero flags have a separately proven `SetFileInformationByHandle(FileCaseSensitiveInfo)` restore path.
- Every reparse entry is an expected `0xA000001D` LX object with a valid version-2 raw buffer.
- Owner/group are compatible with the non-elevated restore envelope and every DACL has a supported form.

If any EA, named stream, unexpected reparse tag, hardlink, unsupported owner/group or unproven case flag is observed, stop without omission. Extending support would require a reviewed implementation—such as `NtQueryEaFile`/`NtSetEaFile` for EAs—not a fallback that flattens metadata.

A known credential-store name also stops the attempt before its contents are opened. It must never be silently skipped, because skipping would make the “full capture” claim false.

\## Capture and reconciliation sequence

1. Pin all three program hashes and verify source, recovery parent and ancestors are non-reparse directories.
2. Refuse elevated execution, occupied generation paths, unexpected source roots, or insufficient free space.
3. Take fresh full observation S0. Do not enforce historical counts.
4. Refuse unsupported metadata or credential-store names.
5. Create the recovery parent envelope and reproduce its reviewed DACL inheritance behavior.
6. Copy every directory and regular file create-new. Before copying each file, reopen it and require its S0 identity and metadata to match.
7. Create every LX leaf create-new and apply its exact captured buffer with `FSCTL_SET_REPARSE_POINT`.
8. Apply metadata through no-follow handles:
   - owner/group/DACL with `SetKernelObjectSecurity`, subject to the supported identity policy;
   - creation/write times and attributes with `SetFileInformationByHandle(FileBasicInfo)`;
   - case flag only if observed and its setter has passed review;
   - directory times bottom-up.
9. Rewalk recovery as R and compare it to S0, excluding expected new file IDs.
10. Rewalk source as S1 and compare path set, kind, identity, bytes, metadata and raw reparses.
11. If S1 differs, retain the attempt as incomplete, report exact additions/removals/changes, and start a fresh generation. Do not patch or overwrite the old attempt.
12. Require two matching full observations around a complete copy before writing `manifest.json` last and its external digest afterward.
13. Bound automatic retries to two. Repeated drift is a writer-activity finding, not permission to ignore new files.

This accommodates files arriving during preparation while preserving immutable evidence.

\## Cold restore

Run `ait25-cold-restore.ps1` in a fresh hidden PowerShell 5.1 process. Pass only:

- generation path,
- absent output path,
- expected manifest digest,
- expected restorer digest.

The restorer must contain no AIT25 source-path literal and must:

1. Validate program and manifest pins.
2. Validate schema, bounds, path containment, case collisions and entry uniqueness before creating output.
3. Rehash the complete retained recovery against the manifest.
4. Refuse occupied output, missing/tampered payload, unsupported metadata or malformed LX buffers before output creation.
5. Restore directories, files and raw LX objects create-new.
6. Restore handle-based security/basic metadata and directory times.
7. Rewalk and compare the result to the manifest.
8. Verify recovery bytes and metadata remain unchanged.

Because originals cannot be renamed or ACL-restricted in this preparation phase, this proves source-independent restoration by construction, but not physical source unavailability. A genuinely source-withheld cold proof remains a final-cutover-window check.

\## Git validation isolation

Create `analysis/ait25` as a completely independent copy of the cold restore:

- No hardlinks, junctions or shared file IDs.
- Require link count one and different file IDs from both recovery and cold restore.
- Do not copy live `.git/config` into the analysis tree. Write a minimal allow-listed config at analysis-copy construction time; the opaque original remains preserved only in recovery and cold restore.
- Scan `.git` files directly for external `gitdir`, `commondir`, worktree and alternates pointers. Refuse analysis if any escapes the captured scope.
- Run only the already proven bounded commands: `ls-files --stage`, the two `ls-files --others` classifications, and `fsck`.
- Use fixed `git.exe`, explicit `-C`, `GIT_DIR`, `GIT_WORK_TREE`, isolated global/system config, empty hooks, disabled credentials/prompts/protocols, disabled maintenance/gc/fsmonitor, fixed working directory and a hard process-tree watchdog.
- Record refs, HEAD, index, reflogs, stash, shallow markers and tracked/staged/modified/untracked/ignored partitions.

Hash the retained recovery immediately before and after Git analysis. Git never receives a path into recovery or the primary restore. Even if Git rewrites an index, only the disposable analysis copy can change. The lack of an OS-level network/child-process sandbox remains an explicit `UNKNOWN`, not a preservation failure.

\## Adversarial checks

Required negative cases:

- Traversal, rooted path, ADS syntax, duplicate path and case collision.
- Missing, added or changed source entry between S0 and S1.
- Manifest or payload tampering.
- Occupied restore output.
- Unexpected reparse tag/version, malformed length, invalid UTF-8 or missing raw buffer.
- LX flattened to a regular file or omitted despite a successful copy exit.
- Reparse ancestor or attempted link traversal.
- Nonzero EA, named stream, hardlink or unsupported case flag.
- External Git pointer.
- Recovery/analysis shared identity.
- Hook/filter marker creation, prompt, network-capable protocol, timeout or output-bound breach.
- Any difference in `.git` bytes between source observation, recovery and primary restore.
- Read-only loss across all 1,413 currently observed read-only files.
- Final entry count derived from current source, never forced to 19,952.
