\## The review (verbatim)

\# A. Money leaks (pod keeps billing)

\### A1 — `create_pod` raising after RunPod has already created the pod → orphan, no atexit, no id
`runpod_run.py:187-210`. `atexit.register` is at line 207, after the whole id-resolution block. Everything before it is unprotected:
- `RunPodAPI._request` (line 99) uses `timeout=REQUEST_TIMEOUT` (30 s). A `POST /pods` that takes >30 s raises `requests.exceptions.Timeout` after RunPod has provisioned and started billing. `__enter__` propagates, so `__exit__` is never called, no atexit is registered, and `result["pod_id"]` (line 885) is never assigned — `run.json` records `pod_id: null`, no ledger row, nothing names the pod.
- Same for a 5xx/502 from a proxy that already forwarded the create, `response.json()` raising `ValueError` (line 114), and the "create response was not an object" guard (line 120).
- The `list_pods()` recovery at 196-206 only runs on the 2xx-with-no-id branch, and if `list_pods()` itself raises that exception also escapes before line 207.
Fix: register the atexit sweep before the create call, keyed on `payload["name"]`; on any exception after create, recover by name via list_pods → set pod_id → close(); raise the HarnessError on the exception path too.

\### A2 — `main()` prints "termination was attempted and verified" unconditionally on KeyboardInterrupt
`runpod_run.py:1065-1067`. KeyboardInterrupt reaches main from any point, including before the lease exists, and from inside `lease.close()` (second Ctrl-C in `self.sleep` at 242 or between delete and verify). Then the pod is alive and the operator is told it is verified gone. Same class at 1068-1070: `RunCancelled` exits 128 with no termination status.
Fix: thread `_verified_absent` into the message; print `POD STILL RUNNING <id> — run: terminate --pod-id <id>` whenever a lease exists and was not verified.

\### A3 — `_close_at_exit` swallows the failure and the loud line
`runpod_run.py:212-217`. If close is interrupted mid-loop (KeyboardInterrupt during atexit teardown, RunCancelled from a signal, MemoryError) the `except BaseException: pass` discards it and the process exits silently with a live pod.
Fix: in `_close_at_exit`, `except BaseException:` emits `POD STILL RUNNING <id>` via logger.critical AND directly to sys.stderr (logging may be torn down at atexit).

\### A4 — Post-create price backstop falls open to the manifest number
`runpod_run.py:887`: `actual_hourly = float(created.get("adjustedCostPerHr") or created.get("costPerHr") or actual_hourly)` where `actual_hourly` came from `manifest["price_usd_per_hour"]` (882). If the create response omits cost fields or returns 0.0 (falsy), the check re-validates the manifest against itself. Preflight at `estimate_cost:476` is also purely manifest-driven. A manifest with `price_usd_per_hour: 0.01` defeats both gates. `wait_ready` returns the ready pod (where cost IS populated) and line 894 discards it as `_pod`.
Fix: capture the ready pod, read its cost field, fail closed if absent or non-positive (terminate + raise).

\### A5 — `--max-usd` optional → no spend ceiling anywhere
`runpod_run.py:1050` no `required`; 473-481 `if max_usd is not None`; 888 `else float("inf")`. Only bound is manifest `max_minutes` (993, author-controlled). Nothing consults `governance/budget.yaml` `daily_usd_limit: 5.00` or sums `ledgers/cost/*.tsv`.
Fix: `--max-usd` required for non-dry-run; `max_minutes = min(cli, manifest, DEFAULT_MAX_MINUTES)`.

\### A6 — Watchdog clock starts after create, not at create
`started` set at 864, watchdog constructed at 891 after create/recovery/price check. Exposure = create latency + max_minutes.
Fix: `Watchdog(max(1.0, max_minutes*60 - (time.monotonic() - started)), ...)`.

\### A7 — `watchdog.stop()` joins 2 s, then run.json records a stale verdict
286-289 and 948-950. Watchdog close() can run minutes; stop() gives up after join(2); 950 reads `lease._verified_absent` unlocked, almost certainly still False; ledger row (963-967) uses premature elapsed.
Fix: in finally, join for the full teardown budget (attempts × 2×REQUEST_TIMEOUT + backoff) before sampling `_verified_absent`, under `lease._lock`.

\### A8 — Signal inside `close()`'s sleep aborts the retry loop
296-298 + 241-242. close() guards API calls (229, 239) but not `self.sleep` nor the loop. SIGTERM there raises RunCancelled out of close() with `_verified_absent` False and budget unspent; atexit re-enters but see A3.
Fix: mask SIGINT/SIGTERM (flag-only handler) for the duration of close(), restore in finally.

\# B. Key leaks

\### B1 — Non-HarnessError exceptions escape main() and print an unredacted traceback
1061-1073 catches only KeyboardInterrupt, RunCancelled, HarnessError. requests exceptions (ConnectionError, Timeout, SSLError), ValueError from int(job["seed"]), subprocess.TimeoutExpired, IndexError from parse_simple_yaml:370 propagate to the interpreter → full traceback to stderr bypassing ApiKeyRedactionFilter (handler-only).
