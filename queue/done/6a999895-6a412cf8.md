\## Design (binding)
1. Manifest resolution: `--phase P1` → `scripts/prospecting/gate_manifest.json` (unchanged);
   `--phase Pn` (n≥2) → `scripts/prospecting/gate_manifest_p{n}.json`. All manifests share ONE
   schema: `{phase, artifacts, fixtures, tests, criteria, artifact_hashes}` (the manifest file itself
   excluded from `artifact_hashes`). Unknown phase or missing manifest → `{"status":"failed","code":"unknown_phase"}`.
2. Criteria are data-driven: `criteria` is a mapping `name → required` where built-ins are
   `minimum_enumerated_tests`, `failures`, `skips`, `xfails`, `warnings`, `external_network_calls`,
   `child_processes_without_guard`, `inspector_minimum` (boss-supplied `--inspector-score`), and any
   other name is compared to the summed `record_property` measurement of that name (missing
   measurement = failure with a clear error). Remove P1-specific criterion code paths; P1's manifest
   already lists its names.
3. Allowlist: `--strict-allowlist` checks `git ls-files` under `.githooks/pre-commit`, `orgs/prospecting`,
   `scripts/prospecting` against the UNION of artifacts+fixtures of every `gate_manifest*.json` present,
   plus `orgs/prospecting/gate-results/*.json`; non-strict runs only require the current phase's
   artifacts present + hash-matching.
4. `--record` → `orgs/prospecting/gate-results/P{n}.json`; `--verify-recorded --phase Pn` verifies
   that phase's file. Keep the P1 recorded file format.
5. Tests (`test_gate.py`): make `test_46`/`test_47` (and any other live-tree assertion) hermetic by
   building a temporary git repo with copied artifacts; add: P2-style manifest loads; unknown phase;
   custom criterion measured via `record_property`; missing measurement fails; strict union allowlist
   with two manifests; record/verify for P3.
6. Update `gate_manifest.json`'s `tests` list if new node ids appear; keep P1's recorded result valid
   (re-record is the boss's step).
