\## Proposed amendment

**Family-first placement**

When an item belongs to an established project family, place it within that family rather than creating another top-level project folder. Current approved family shapes are:

- `Projects/NYU/<project>` — including `nyu`, `ai`, `ait25`, `ait26`, and `cs202`.
- `Projects/Fantasy/<project>`.
- `Projects/Interview-Prep/<project>`.

Repositories remain separate siblings unless a repository already owns the material. Preserve existing names during migration. Existing KB-internal projects remain inside the canonical KB tree unless Daniel separately approves an extraction.

**Supported home locations**

Standard Windows folders, conventional dot folders, application configuration, authentication material, caches, and runtime-owned state remain in their existing supported locations. A dot-prefixed or home-level path is not clutter merely because of its name. Do not invent environment variables, redirect credentials, or relocate tool state without verifying that the installed tool supports the proposed setting.

**MCP separation**

Treat every MCP as up to three independent layers:

1. Server source or installation: owning project, `tools/mcp/<server>`, or the package manager’s supported location.
2. Client registration: the intended client’s supported project or user configuration, at the narrowest required scope.
3. Authentication, cache, and persistent state: the tool’s existing supported location.

The number of registered MCP servers must not determine the number of home-level folders. A server gets a source directory only when local source actually exists or is being developed.
