\## Findings

\### HIGH

- [worker/desktop.py:102](/C:/Users/danie/Atlas-worktrees/v3/worker/desktop.py:102) — `GetWindowRect` is declared with a `wintypes.HWND` argument, but the hook passes the managed `System.IntPtr` object directly. The surrounding implementation and pywebview both convert handles numerically before calling `user32`. The first `WM_NCHITTEST` can therefore raise a ctypes argument error, preventing edge resize. Minimal fix: capture/pass `native.Handle.ToInt64()` to `GetWindowRect`, then add a hook-level test that exercises an actual hit-test message.

- [worker/desktop.py:210](/C:/Users/danie/Atlas-worktrees/v3/worker/desktop.py:210) — `toggle_maximize` now reads and writes a WinForms control property directly from the pywebview JS API path. Exposed API calls are not guaranteed to run on the WinForms UI thread. Pywebview’s own maximize/restore implementation explicitly uses `Form.Invoke`; the replacement test uses a `SimpleNamespace`, so it cannot detect this regression. The UI also silently catches the rejected promise, making the button appear to do nothing. Minimal fix: perform the state read and write inside an `Action` dispatched through `native.Invoke` when `InvokeRequired`, with a test covering that path.

\### MEDIUM

- [worker/desktop.py:97](/C:/Users/danie/Atlas-worktrees/v3/worker/desktop.py:97) — `WM_NCCALCSIZE` returns the entire thick-frame window rectangle as client space in every state. A maximized thick-frame window extends by the resize-border width beyond the monitor work area, so custom chrome can be clipped or overlap the taskbar; snapped edges can similarly be mis-sized. Minimal fix: when maximized, adjust the proposed client rectangle to the monitor work area before returning zero, and test the rectangle calculation.

- [worker/desktop.py:136](/C:/Users/danie/Atlas-worktrees/v3/worker/desktop.py:136) — neither `GetWindowLongW` nor `SetWindowLongW` is checked for failure. A failed get returns zero and is transformed into a style containing only the three added bits; a failed set is silently followed by a successful frame refresh and retained hook. Minimal fix: clear/read `ctypes` last-error around both calls and reject zero results only when last-error is nonzero.

\### LOW

- [worker/desktop.py:53](/C:/Users/danie/Atlas-worktrees/v3/worker/desktop.py:53) — `_native_window_hooks` grows permanently and hooks are never released or removed. Repeated configuration or repeated `run()` calls retain every native window. Minimal fix: retain one hook per live HWND and remove/release it on `WM_NCDESTROY`.
