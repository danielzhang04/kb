\## Findings

\### HIGH — T1 still cannot complete end-to-end

`approve-batch` always stages locally with `opener=None`; the supplied `approval_pr_opener` is unused. The resulting `.approval-staging` card is uncommitted, while the real verifier requires the card committed/pinned on the approved ref and identical to the worktree. So `materialize` fails closed after dashboard approval; there is no reviewed stage → dashboard → pinned-card return path.

Evidence: `scripts/prospecting/approval/cli.py:81-91,118`; `scripts/prospecting/approval/batch.py:155-158`; `scripts/webauthn_verify.py:673-688`.

\### HIGH — An uncertain send does not consume cap capacity

If Gmail accepts a send but the adapter raises, delivery becomes `uncertain`. Daily, hourly, and firm calculations count only `claimed` and `sent`, so a later request can exceed a real cap while the uncertain message may already have been delivered.

Evidence: `scripts/prospecting/approval/release_t1.py:406-410` versus `:320-341`.

\### HIGH — The “2 per firm per day” cap is campaign-local, not firm-global

Both scheduling and send-time checks filter by `campaign_id`. Two active campaigns targeting the same firm can each send two messages on the same day, totaling four.

Evidence: `scripts/prospecting/approval/schedule_t1.py:123-126,135-139`; `scripts/prospecting/approval/release_t1.py:321-335`.

\### MEDIUM — Inbox observation is still not atomic with the Gmail send

The mailbox scan completes before the new transaction and before `backend.send`. A reply/OOO/bounce/warning that arrives immediately after `messages_list("in:inbox")` returns is not seen, and the send proceeds. The test injects an event during the scan, not after it.

Evidence: `scripts/prospecting/approval/release_t1.py:359-405`; `scripts/prospecting/tests/test_t1_release.py:303-315`.

\### MEDIUM — Materializing a later batch reschedules earlier approved batches

`stagger_deliveries` treats every reserved delivery from the campaign whose recorded batch differs as pending. Materializing batch B therefore changes batch A’s deterministic schedule and rewrites its batch binding.

Evidence: `scripts/prospecting/approval/schedule_t1.py:116-129,171-173`.

\### LOW — Deployment runbook still lacks an executable preflight argv

The runbook says to run preflight with a “store path,” but `deploy_preflight.py` accepts only `--desktop-host`, `--expected-merge-sha`, and `--root`. It gives Daniel no exact command and implies an unsupported input.

Evidence: `orgs/prospecting/runbook.md:5`; `scripts/prospecting/deploy_preflight.py:161-167`.
