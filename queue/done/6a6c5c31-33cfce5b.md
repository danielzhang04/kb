\## PART A (the rearchitecture — closes finding 2, marker forgery, structurally)

Today completion is signalled by the agent PRINTING `FYT-STAGE-DONE <stage> <token> <summary>` to
its terminal, and the daemon SCANS the pty text for it (`MARKER`, `matchCompletionMarker`, the
marker loop in `scan` ~line 1421, `orderMarkdown`'s "print ONE line" instruction ~line 1272). Because
the terminal is agent-controlled and the token is legitimately known to the agent (it reads the
order file), a marker embedded in prose/quotes is accepted as a real completion (reproduced:
`> FYT-STAGE-DONE story <token> not done` → accepted DONE).

Replace the terminal-parsed completion with a **server-owned status file**:

1. Per delivery, designate `statusPath = <runDir>/<agentId>/status/<stageId>.json`
   (`runDir` helper line 1160; `fs.ensureDir` the `status/` dir like `orders/`).
2. At delivery time, BEFORE writing the order file, DELETE any pre-existing `statusPath`
   (snapshot-and-clear) so a prior attempt's file can never satisfy this delivery.
3. `orderMarkdown` (and the binding's "How work reaches you" section): replace the print-a-marker
   instruction with: "When the stage is finished, write EXACTLY this JSON (and nothing else) to
   `<statusPath>`: `{\"token\":\"<token>\",\"verdict\":\"DONE|BLOCKED|FAILED\",\"summary\":\"<one
   line>\"}`. Do NOT print any completion marker to the terminal; the control plane reads that file,
   not your terminal." Keep the token in the order file (unchanged mint).
4. Grant the agent Edit on exactly `statusPath` in `buildRosterPermissionSettings` (mirror the order
   channel Read grant ~line 902; scope to the status file/dir only, absolute-rule-pathed).
5. Resolution: after engagement is confirmed (Part B keeps that pty logic), POLL `statusPath` on the
   existing cadence, bounded by the SAME marker/delivery deadline (`timeoutMs`). Parse via
   `fs.readFile`. Accept ONLY when: valid JSON, `token` === this delivery's token, `verdict` ∈
   {DONE,BLOCKED,FAILED}. On accept → `resolvePending` with that verdict (DONE→succeeded etc.),
   THEN the EXISTING server-side artifact-delta verification (line ~1762) still runs and can still
   downgrade DONE to a park if declared artifacts are unsatisfied — keep that gate exactly. Malformed
   / wrong-token / missing file → keep waiting. Timeout → the existing "delivery abandoned" park,
   reworded away from "printed no completion marker" to "wrote no completion status".
6. REMOVE the pty completion path: `MARKER` regex, `matchCompletionMarker` (and its export/tests) as
   the COMPLETION mechanism, and the marker loop in `scan`. `scan` still maintains `entry.screen`
   (readiness) — keep that. Drop `entry.buffer`/pending-buffer only if it served solely marker scan
   (verify: it does). `VERDICT_PLACEHOLDER` and the anti-smuggling MARKER comment block go with it.
7. Poll mechanism: a simple bounded poll loop off the delivery deadline is fine (no fs.watch needed);
   reuse the SUBMIT/verify poll cadence constants or add one named constant. It MUST unref any timer
   so the daemon can exit (see the existing `timer.unref()` at ~1668).

\## PART B (harden the pty readiness/engagement path — findings 1,3,4,5,6,7)

The pty stream is STILL used to know when to type (readiness) and whether the turn started
(engagement). Fix, each with a reproduction test:

- **F1 (MCP disable is inert):** `disabledMcpjsonServers` was emitted under `permissions`; CLI 2.1.220
  reads it at settings ROOT. Move it to the settings root AND additionally launch roster sessions
  with `--strict-mcp-config` (in `defaultLaunchLine`) plus an explicit empty per-run MCP config so
  ancestor `.mcp.json` files (e.g. `orgs/faceless-youtube/.mcp.json`) cannot re-enable a server. Fix
  the test to assert the CLI's actual schema shape (root key), not the current generated shape.
- **F4 (CUF-positioned modal glued → false ready):** `stripForScreenWindow` deletes CUF, so a modal
  rendered `Do\x1b[1Cyou\x1b[1Cwant...` glues to `Doyouwant...` and no MODAL_MARKER matches → the
  gate returns `ready` and swallows the order into an open menu (the exact bug the gate exists to
  prevent; boss-reproduced). Map CUF→SPACE in `stripForScreenWindow` (keep CUP DELETED — that is
  what prevents the 20-line-window flooding from finding 4's original fix). Regression test: the
  exact CUF modal frame must classify NOT-ready (modal).
- **F3 (stale spinner + fresh timestamp → false engaged):** `detectTurnEngaged` treats retained busy
  text as live because `entry.lastChunkAt` is freshened by ANY chunk incl. the composer echo. Track a
  busy-observation generation that advances ONLY when newly-decoded post-Enter bytes contain a busy
  TRANSITION; engagement requires a busy signal observed AFTER this delivery's Enter, not merely a
  busy frame present in the rolling window with a recent global timestamp. Test: stale spinner +
  composer echo alone → engaged=false; a real fresh busy transition after Enter → engaged=true.
- **F5 (no recheck after synchronous snapshot):** between the readiness check and the pty write, the
  synchronous `snapshotDeclaredArtifacts` hash can block Node while a modal/turn starts. After
  snapshotting, yield (await a microtask/drain) and RE-CHECK settled readiness immediately before the
  first write; if no longer ready, take the same park path. Test the ordering.
- **F6 (continuous benign repaints → permanently undeliverable):** cursor-visibility/status repaints
  (`\x1b[?25h` once/sec) strip to nothing but still reset `lastChunkAt`, so quiet never reaches the
  threshold and every delivery parks `settling` forever. Base "settled" on how long the terminal has
  continuously CLASSIFIED ready (reset only on a non-ready semantic frame), not on raw-chunk quiet.
  Test: idle frame + periodic no-op repaints → becomes deliverable.
- **F7 (CSI split across pty chunks):** now COMPLETION no longer depends on it, but a CSI split across
  two chunks still corrupts readiness frame classification. Retain an incomplete trailing CSI/OSC
  suffix per session and prepend it to the next chunk before stripping. Test a split at a mid-CSI
  boundary classifies the same as the unsplit bytes.
