\## Daniel's 2026-08-12 ruling (binding, verbatim)

> "Manager should be providing feedback and judging against actual results. Note that I don't
> just want 'manager' to iterate. Two agents should also be able to work with each other. Or
> three. For instance, maybe I want two agents to engage in a debate of sorts to come to a
> consensus about the best path forward for US politics. In that case, they would probably go
> back and forth, each with a perspective, and connect to a third, mediator agent who has its
> own mandate. Make sense?"

Plus his standing constraint from the same session: **no infinite iterations** between a
managing agent and a worker agent — every loop is bounded and observable.

So the design space is N-participant iteration groups with declared roles, at minimum
covering these three topologies:
1. **Pairwise rework** — A⇄B artifact ping-pong (the spec's original IterationLoop).
2. **Manager/judge loop** — a manager judges the worker's ACTUAL RESULT (artifact), returns
   structured feedback, worker reworks; manager judges against acceptance criteria, not vibes.
3. **Debate + mediator** — 2+ peers each with a declared perspective exchange positions; a
   mediator with its OWN mandate drives to consensus or calls it.

All bounded: termination by verdict/consensus OR def-declared cycle cap; cap exhaustion parks
to the normal human-gate surface (as `ReviewLoop` already does).
