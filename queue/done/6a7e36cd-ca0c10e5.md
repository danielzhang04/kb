\## Process finding

The image-generation skill documents the intended gates: Pass 1 asset inventory and human approval; approved/verified STEP-1 cards; then Pass 2 scene generation using place plates and in-chain parents. It also says later in-place shots seed the place’s first approved frame.

Two qualifications matter:

1. `forge.py` can construct one ordered batch where a later shot references an earlier pending `_staging/L28` output. It rejects a known `parked` existing parent, but a same-batch parent is not yet human-approved at assembly time.
2. I did not find a separate file using the literal labels “W1 asset-base” / “W2 seed-cards”; the equivalent doctrine is in `SKILL.md` Pass 1 / Pass 2 and review sections.

P8 skips the production workflow’s final enforcement after it changes the slate. It derives through Forge, but then:

- removes Forge’s cast-free `scene-style-tile`;
- trims the place reference before adding the accepted-baseline style anchor;
- uses an anchor that production’s `seed_role_violations()` would not accept as `style-anchor` (only `scene-style-tile` may have that role);
- does not re-run production `preflight_batch()` on that altered final list;
- does not create/review/approve a P8 L28 plate before L33, because L33 no longer uses it.

\## What Gemini gets that Codex doesn’t

1. **L33’s actual L28 place continuity frame** — **likely-helps-match**. Same-room geometry, lighting, benches, sign, and aisle composition arrive in pixels; P8 explicitly drops it.

2. **Production’s final ordered-slate validation after all seed decisions** — **likely-helps-match**. It prevents role/path semantics from diverging after cap handling.

3. **The dedicated cast-free scene-style tile, only where doctrine intends it** — **likely-helps-match**. It is content-thin and does not inject another narrative scene’s layout.

4. **Style-bible head descriptor plus the production tail suffix** — **likely-helps-match**. This is the actual production prompt shape being matched, including tail-recency behavior the code documents.

5. **Production’s approved-asset / STEP-1 review workflow** — **likely-helps-match**. It blocks reuse of a figure card without a current all-pass review record.

\## What Codex sends that Gemini never does

1. **A selected Gemini-baseline frame as a style anchor on every P8 target** — **likely-hurts-match**. It may help generic register resemblance, but it replaces or competes with production continuity; L33 loses L28 specifically.

2. **Large P8 per-shot contract blocks: surfaces, hexes, counts, negative inventory, orientation** — **neutral to likely-helps-match** for a tightly measured single-frame baseline, but they are not production-equivalent.

3. **~45–50% prompt-only novel machinery and 68–91% longer prompts** — **likely-hurts-match**. It can overwhelm the simple production hierarchy and makes “same shot” comparison confounded by many interventions.

4. **Hard color allowlists and exact material hex bindings** — **likely-helps-match** for P8’s palette defects, but **not** a production-path match; Gemini only receives color prose and style pixels.

5. **A Codex-agent envelope that reads a prompt file, then dynamically invokes image generation** — **neutral visually, likely-hurts auditability**. The seed lists are recorded, but the engine marks exact prompt delivery `unverifiable`.
