\## 2. Cross-task seams

High-impact defects:

1. **Send requests can never survive executor validation.**  
   [store.py:920](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/store.py:920)-951 consumes `approval.consumed_at` while inserting the request. The executor later calls [validate_exec_request at executor.py:92](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/executor.py:92), which rejects consumed approvals at `store.py:880-881`. An in-memory probe produced:

   ```text
   approval_after_insert 2026-09-03T12:00:00Z
   send_after_executor ('rejected', 'validation_or_hook_rejected')
   ```

2. **Credit reservations are not bound to their request’s campaign or provider.**  
   [store.py:375](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/store.py:375)-400 checks only that the request is queued, then trusts `reservation.campaign_id`. A request under a zero-budget policy successfully reserved one credit from an unrelated campaign.

3. **Campaign activation uses a send-content approval as a policy approval.**  
   [schema.sql:205](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/schema.sql:205)-207 and [cli.py:92](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/cli.py:92)-102 require any unconsumed approval, but do not check expiry, tier, content kind, or a campaign-policy approval assertion. An expired send approval successfully activated a campaign. Conversely, T0 has no approval rows by design, so normal T0 activation is impossible.

4. **Repository/view drift.**  
   `schema.sql:188-193` selects the latest fit score per campaign; [get_person_tranche at store.py:535](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/store.py:535)-549 returns every historical score, duplicating people.

5. **Role-change identity is not atomic.**  
   [store.py:317](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/store.py:317)-329 closes the old employment without checking that it belongs to `new_employment.person_id`. A malformed call can close person A’s job, add person B’s job, and stale B’s contacts.

6. **Eligibility overrides lose most of their binding.**  
   [store.py:766](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/store.py:766)-773 checks only override ID, campaign, predicate, and non-agent actor. It omits `policy_hash`, lane, and capability version, despite `data-contracts.md:18-21`. `insert_eligibility_decision` also accepts caller-constructed “eligible” rows without revalidation.

7. **Target-policy validation is incomplete.**  
   [store.py:660](/C:/Users/danie/kb-worktrees/prospecting-p1/scripts/prospecting/store.py:660)-684 validates predicate values but not `predicate_id`, `extra_fields`, `lane_plan`, or `scorer_version`. Free-form values can therefore enter the nominally VM-safe policy outside `Predicate.value`.

8. **CLI and request-state contracts drift.**  
   `_opaque_id("per_opaque_1")` succeeds despite `data-contracts.md:5`. `insert_exec_request` accepts `state='succeeded'`, `claimed`, or `uncertain` as an initial caller-supplied state.

Production has no writer for `sender_profile`, campaign creation, `source_snapshot`, `fit_score`, `evidence`, `revision`, `reply_template`, approval materialization, `finder_run`, `finder_cursor`, `enrollment`, `delivery`, `inbound`, or `reply_revision` (`schema.sql:7-181`). It also has no resolver for `merge_review.decided_*`, suppression release, or most `relationship` columns. Much of this is intentional future-phase scaffold, but it means “typed repository” does not yet cover the full schema.

Correspondingly unreachable through current production APIs are:

- `merge_review=resolved_keep|resolved_merge|resolved_split`;
- base-executor `exec_request=succeeded|uncertain`;
- all finder, enrollment, delivery, inbound, and reply-revision enum states;
- approval invalidation reasons;
- suppression `bounce|google_warning`;
- T0 campaign activation.

The executor/schema operation seam itself is clean: all seven schema operations exactly match the union of `AGENT_CAPABILITIES` and `CALLER_OPERATIONS`.

\## 5. Exact fixes

1. **`store.py:920-951`** — remove approval consumption from request insertion. Consume the nonce only in the enabled send path, transactionally immediately before the external call; add an insert→executor integration test.

2. **`schema.sql:205-207`, `cli.py:92-102`** — replace send-content-approval activation with a dedicated verified campaign-policy approval, or make the audited human transition from `approved` the policy approval. Do not reuse revision/reply approvals.

3. **`store.py:582-590, 375-400`** — add `campaign_id` to `vendor_lookup`, validate operation/provider/policy/campaign together, and derive the reservation campaign from the request rather than trusting the reservation object.

4. **`pii_guard.py:73-137, 151-205`** — normalize JSON Unicode escapes, recognize international phone forms, and require typed sink envelopes/known-name context so untyped names, notes, excerpts, and bodies fail closed. Exercise actual sinks.

5. **`export.py:15-34`** — remove the unrestricted environment destination; use one fixed desktop-local export root and reject repo, UNC, symlinked, and VM-mounted destinations.

6. **`store.py:660-779, 954-965`** — validate every target-policy metadata field; bind eligibility overrides to policy hash, lane, and capability version; revalidate before insertion; make override plus audit one transaction.

7. **`store.py:317-329, 535-549`; `cli.py:20-25`; `store.py:898-908`** — bind role change to the same person, select only the latest campaign score, enforce exact field-specific opaque IDs, and require new requests to be `queued` with no reason.
