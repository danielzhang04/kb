## Result

\# Verdict: REWORK

Core crash/restart and cancellation invariants are not representable by the current in-memory phase state. The passing checkpoint does not exercise those failures.

\## Blockers

1. **A replayed host receipt is incorrectly treated as completed phase 2.**  
   `attemptSessionAdapter.ts:570-581` skips every approved prompt whenever `hostReceipt.replayed` is true. If the process crashes after the host persisted its receipt but before—or midway through—prompt delivery, restart binds the session but never sends the missing prompts. The worker can hang or execute an incomplete declaration.  
   **Required fix:** durably track phase-2 delivery and make each prompt step idempotent; test crashes before the first prompt and between Claude’s two prompts.

2. **Cancellation is neither durable nor guarded across binding.**  
   The sole pre-binding cancellation check is at `attemptSessionAdapter.ts:553`; binding then awaits at `:557-564`. A cancellation during that await closes the session at `:647-656`, but the resumed receipt path still sets `bound`, writes prompts, and returns a successful receipt at `:569-594`. A crash before host receipt also loses the in-memory cancellation flag entirely.  
   **Required fix:** persist an operation-key cancellation tombstone before awaiting creation, recheck it after every phase boundary, and atomically prevent binding/running projection. Add cancel-during-bind and cancel-then-restart tests.

3. **Changed declarations are not rejected after restart.**  
   The complete fingerprint exists only in `attempts`, an in-memory map (`attemptSessionAdapter.ts:367,435-445`). The durable host request contains only recipe/root/cwd/size (`:494-501`). After restart, changing `workOrder`, scopes, assignment, project, or other omitted fields produces the same host request and can replay the old session instead of conflicting.  
   **Required fix:** durably bind the canonical full-declaration hash to `operationKey` and compare it before replay. Test changed requests after constructing a fresh adapter.

\## Majors

- **Thrown bind/write/close failures violate the port contract and leak sessions.** `bindings.bind` and subsequent operations are not caught at `attemptSessionAdapter.ts:557-580`; `result` directly awaits the potentially rejected receipt at `:606-612`. A rejected bind produces rejected promises rather than `PortResult` plus `WorkerExecutionResult`, and no guaranteed rollback occurs. Map exceptions to `internal`, close safely, and test rejected promises—not only refusal values.

- **Exit-before-receipt is masked by an unrealistic fake.** Production code writes prompts after an early exit without checking `attempt.exited` (`attemptSessionAdapter.ts:570-580`). The test host accepts writes to finished sessions unconditionally (`attemptSessionAdapter.test.ts:185-189`), so the race at `:544-558` cannot expose the defect. Make finished-session writes refuse and define the expected receipt/result behavior.

- **`WorkerExecutionResult` parity is false outside happy-path defaults.** The retained adapters use configured timeout/output limits and stderr tails; the new parser reports fixed defaults (`attemptSessionAdapter.ts:188-192`) and always passes `stderrTail: ''` (`:617-628`). Tests compare actual retained adapters only for successful Claude/Codex runs (`attemptSessionAdapter.test.ts:358-360,418-443`). Add error, timeout, cap, cancellation, malformed-output, iteration-failure, and stderr parity cases.

- **Raw authority refusal is incomplete and uses the wrong channel.** `RAW_AUTHORITY_FIELDS` omits `cwd`, `resumeRef`, and `token` (`attemptSessionAdapter.ts:41-43`); rejection throws synchronously (`:264,434`) instead of returning `invalid-request`. The test only proves outer `recipe` and nested `env` rejection (`attemptSessionAdapter.test.ts:507-517`). Add every §3 spelling individually and assert the refusal code.

- **Terminal attempts retain unbounded transcript state.** `attempts` is never evicted (`attemptSessionAdapter.ts:367`), while each entry retains chunks up to—and potentially beyond—the 64 MiB cap (`:454-474,677-679`). Repeated terminal attempts can exhaust process memory. Add bounded terminal eviction compatible with durable replay.

- **Security boundary:** `relativeCwd` and model pass directly from the approved declaration (`attemptSessionAdapter.ts:321-336,494-500`); sandbox is fixed and env is not forwarded. Resume/thread IDs come only from the server resolver at `:292`, not from declaration fields. No explicit secret/env write to the recorder was found; it receives host frames verbatim at `:474`.
