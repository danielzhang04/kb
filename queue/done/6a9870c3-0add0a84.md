\### Schema findings

Current REST `GET /pods/{podId}` and `GET /pods` return top-level `desiredStatus`, `lastStatusChange`, `publicIp`, `portMappings`, `gpu`, and `machineId`. Nested `machine` details require `includeMachine=true`; `includeNetworkVolume` is unnecessary here. Current REST does not document `currentStatus` or `runtime`. [Get Pod](https://docs.runpod.io/api-reference/pods/GET/pods/podId), [List Pods](https://docs.runpod.io/api-reference/pods/GET/pods), [live OpenAPI](https://rest.runpod.io/v1/openapi.json).

RunPod’s GraphQL schema separately documents `runtime.ports[]` with `ip`, `privatePort`, `publicPort`, `type`, and `isIpPublic`. The harness now accepts both shapes and logs `schema=rest` or `schema=runtime`. [GraphQL Pod schema](https://docs.runpod.io/sdks/graphql/manage-pods).

Hypothesis: the first Pod most likely had target `desiredStatus=RUNNING` but never received a public SSH mapping, probably while allocating or pulling/initializing the 9.36 GB image. This cannot be confirmed because the old run captured no poll states. A schema mismatch is less likely against today’s REST schema, but the runtime fallback now covers it.
