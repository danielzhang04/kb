\## The bug (root cause already traced — do not re-investigate from scratch, verify then fix)
`GET /api/agents` returns HTTP 500 `{"error":"project-required"}` and the whole Agents view dies.

Chain:
1. `server/agents/routes.ts:276` registers `GET /api/agents` → `readEntityList(entityListPort, ...)` with NO try/catch.
2. `server/agents/routes.ts:270` — `entityListPort.list = () => agentList(ctx)`.
3. `agentList` (`server/agents/routes.ts:130-136`) → `projectEntityList(...)` from `server/entities/project.ts`.
4. `server/entities/project.ts:118-126` `groupFor(...)`: for any agent NOT in `group: system`, it collects `projects`, and at **line 124** does `if (projects.length === 0) throw new Error('project-required')`.
5. `input.projects` is built in `server/agents/roster.ts:617-621` from the agent `.md` frontmatter `projects:` + `orgs/<name>` paths inferred from the body.

Net: ONE declared non-system agent (`agents/*.md`) with no `projects:` frontmatter and no `orgs/<project>` reference in its body throws, and because the list route has no error boundary, the ENTIRE roster 500s — not just that agent.

- **Preferred:** make the list resilient so a single agent that fails `groupFor` (e.g. `project-required`) is either (a) omitted from the list with a surfaced per-agent "problem" flag, or (b) grouped under a fallback bucket — rather than throwing.
