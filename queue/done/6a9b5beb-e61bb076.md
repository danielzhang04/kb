## Result

\## Findings

**HIGH — Reserve firms are processed eagerly, and `no_confident_email` can be assigned before candidate exhaustion.**  
`fill_campaign` builds its worklist from every company, then appends every reserve; `reserve_index` does not govern selection (`scripts/prospecting/operator/fill.py:163-166`, `208-209`). Each firm receives at most one lookup per round (`177-194`) and is finalized immediately afterward (`204-207`). With defaults, a firm having six candidates and three non-email results is marked `no_confident_email` after only three attempts, despite three untried candidates. It also cannot resume: on the next run all `fill_firm` rows are excluded (`163-164`). This violates substitution and reserve rules.

**HIGH — An unfinished Snov task can stall permanently when resumed through `operator fill`.**  
The Snov adapter records an unfinished task as `uncertain` (`427-444`), and adapter attachment requeues it (`scripts/prospecting/operator/vendors.py:602-612`). But `fill_run` only attaches/processes an executor inside `execute` (`scripts/prospecting/operator/cli.py:367-370`), which is never reached for an already-recorded firm (`fill.py:163-164`). Thus a subsequent `fill` command does not poll the task or replace the person; only a separate executor command could do so.

**HIGH — Fill bypasses the visible Snov account-ceiling guard.**  
The fill path directly calls `queue_vendor_lookup` with `_SnovReservation` (`fill.py:43-49`, `93-100`), while the Snov account-ceiling check exists on `DesktopVendorAdapter.queue` (`vendors.py:202-232`). The fill path never calls that adapter method. Campaign-budget enforcement may be provided by the imported reservation helper, but within the permitted review scope there is no account-ceiling enforcement for fill.

For 30 primary firms plus 12 reserves, the code processes all 42. With static candidates, the lookup-start bound per invocation is:

`42 × min(max_rounds, max_candidates_per_firm)`

At defaults: `42 × min(3, 6) = 126` one-credit searches. With `--max-rounds 6`: `42 × 6 = 252`. Both limits are user-configurable without an upper bound (`cli.py:428-432`), and the account ceiling is bypassed. Fill itself does not multiply vendor searches by discovery pages; it may queue up to one homepage snapshot per met firm (`fill.py:103-122`).

**HIGH — `deliverable_v1` does not use the campaign’s selected confidence threshold.**  
Selection uses caller-provided `min_confidence` (`fill.py:85-89`, `146-148`), but the view hard-codes `0.7` (`scripts/prospecting/schema_p6.sql:179`). For `--min-confidence 0.9`, a selected, non-substituted candidate with a valid `0.8` email can appear in `deliverable_v1`; conversely, a threshold below 0.7 can make a met candidate disappear. This defeats the stated “confident emails only” predicate.

**MEDIUM — A crash between Snov task acceptance and local persistence can restart a billable search.**  
The remote start response is received before the accepted task is written locally (`vendors.py:349-357`, `393-403`). A process crash in that gap leaves no task URL/hash; retrying calls the start URL again (`410-414`). If Snov charges task starts, this can double-buy despite the deterministic local request ID.

**MEDIUM — Homepage enrichment permits LinkedIn and copies person names into blurbs.**  
The adapter allowlists whatever hostname is stored as `website_url`, without rejecting LinkedIn (`vendors.py:564-573`); a company whose “website” is LinkedIn is therefore eligible for a direct LinkedIn GET. It also stores raw meta-description/title text (`574-583`), so “Jane Doe, founder…” becomes a deliverable blurb. The request is correctly routed through a claimed `fetch_snapshot`: it is typed, validated, and inserted in `fill.py:103-121`, then registered in `vendors.py:560-586`. Redirect, response-size, timeout, and HTML-parser safeguards are delegated to the signature-only `fetcher.py` scope and could not be verified here.

**MEDIUM — The test is green even if critical production paths are broken.**  
The sole test injects a fake executor that directly marks requests successful and inserts contacts (`test_operator_fill.py:43-53`). It does not exercise async Snov polling, account ceilings, campaign-budget refusal, crash recovery, reserve gating, homepage requests, LinkedIn rejection, PII stripping, redirects, size caps, or non-default thresholds. Its “reserve” scenario does not pass a reserve file (`35-64`). Focused pytest could not start in this read-only environment because Python cannot create a temporary directory.

Substitution/view specifics: the base confidence predicate correctly requires `state='valid'` and `confidence >= min_confidence` (`fill.py:85-89`); substituted rows are excluded from the view (`schema_p6.sql:182`); and a firm cannot simultaneously have `met` and `no_confident_email` because `status` is one field (`schema_p6.sql:140`), with the latter excluded from the view (`175`).
