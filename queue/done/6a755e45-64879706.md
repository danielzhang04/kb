\## Defect 1 — repository path confinement

Root cause: `resolveWithin()` used host-native `path.isAbsolute()`. On POSIX, Node does not recognize Windows drive paths, backslash-rooted paths, or UNC paths as absolute, so `C:\Windows\System32` reached filesystem lookup as a relative path.

Files changed:

- [browser.ts](C:/Users/danie/kb-worktrees/boss-cloud-migration/dashboard/server/kb/browser.ts)
- [browser.test.ts](C:/Users/danie/kb-worktrees/boss-cloud-migration/dashboard/server/kb/browser.test.ts)

The shared guard now rejects a path when either native `isAbsolute()` or `win32.isAbsolute()` matches. Coverage includes drive-backslash, drive-slash, backslash-rooted, and UNC forms. This fixes the shared confinement boundary rather than special-casing `listTree()` or one test.

\## Defect 2 — activation construction

Root cause: `buildActivatedExecution()` bypassed `ActivationDeps` when constructing paid-action state. `buildPaidActionExecution()` eagerly creates two atomic-document directories under `<stateRoot>/control`; tests supply `/state`, so Linux non-root received `EACCES`. The latch caught that exception and returned `{ ok: false }`, causing the 31-test cascade. Windows masked the defect because `C:\state` was writable/already present.

Files changed:

- [activation.ts](C:/Users/danie/kb-worktrees/boss-cloud-migration/dashboard/server/control/activation.ts)
- [activation.test.ts](C:/Users/danie/kb-worktrees/boss-cloud-migration/dashboard/server/control/activation.test.ts)

Attempt-I/O and paid-action construction now go through `ActivationDeps`, with real production factories retained as defaults. Tests provide hermetic factories and verify the wiring uses them. `koffi` is incidental: it is lazily loaded only by Windows no-reparse handling. No package or deployment change is required.

\## Defect 3 — embedded Python invocation

Root cause: the embedded script compiles unchanged; Python 3.14, CRLF, and quoting were not implicated. Three subprocess calls in the reconciliation suite directly invoked `python`, bypassing the Wave-1b resolver. Ubuntu has `python3` but no guaranteed `python` alias, so `spawnSync()` returned no successful status and the fixture converted that into exit code 1.

File changed:

- [authorizedFailedRunReconciliation.test.ts](C:/Users/danie/kb-worktrees/boss-cloud-migration/dashboard/server/control/authorizedFailedRunReconciliation.test.ts)

All subprocess execution now uses the shared `pythonInvocation()` result: `KB_PYTHON`, otherwise `py -3` on Windows or `python3` on POSIX. This removes the independent platform assumption instead of changing the Python script or skipping assertions.

\## Defect 4 — PID liveness tests
