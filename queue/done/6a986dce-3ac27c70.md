\## The defect (live on the VM, 2026-09-02 18:26 UTC, run-fa45349f)
`dashboard/server/control/execution.ts:2124` mints the attempt operation key as
`automatic-attempt:<attemptRef>` (or `iteration-turn:<requestRef>`). It flows unchanged:
`workers.begin` → `claudeWorkerAdapter.ts:539` / `codexExecAdapter.ts:28` (`buildApprovedAttemptDeclaration`)
→ `attemptSessionAdapter.ts` (`pendingRecord`, `readRecord`, `begin`, cancel) → the PTY layer, where
`sessionRecord.ts:165 OPERATION_KEY = /^op-[0-9a-f]{64}$/` refuses it in `writeOperation`
(`attempt operation key is invalid`) and `readOperation` returns null for it. The same regex lives in
`sessionPersistence.ts:49`, `brokerProtocol.ts:19` and `windowsSessionHost.ts:110`. Result: every
claude/codex attempt on a real host fails in ~1 s with `claude attempt session start refused
(invalid-request): attempt operation key is invalid`; only fake session ports in tests ever passed.

\## Required design (do this, not a regex relaxation)
Map the control-plane key to a host key ONCE, deterministically, at the control→PTY boundary:
`hostOperationKey = 'op-' + sha256Hex(controlOperationKey)` (use `dashboard/server/shared/hashing.ts`
`sha256Hex`). Deterministic so a retried `begin` for the same control key re-attaches/replays exactly as
today (the host dedupes by operationKey; receipts are keyed by it). The control plane keeps using its own
key everywhere else (attempt map, boundaries, canonical results, cancellation API) — only calls INTO the
`bindings`/host port carry the mapped key, and records coming back are matched by the mapped key.
Put the mapping in ONE place — `attemptSessionAdapter.ts` (a small `hostKey(input.operationKey)` helper
used at every `bindings.readOperation / writeOperation / cancel` call and for the host `create`
request), or a translating wrapper around `options.bindings` created inside `createAttemptSessionAdapter`
— your call; explain why. Records persisted in the PTY store then carry the `op-` key; the
`attemptRef` field on the record is what ties it back. Do NOT change the four regexes, the broker
protocol, or `execution.ts`.
