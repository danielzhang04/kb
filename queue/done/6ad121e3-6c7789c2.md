\## Per-entry pre-copy validation

For every entry:

- Safe normalized relative path, earlier directory parent, ordinal uniqueness, and case-insensitive uniqueness while all case flags are zero.
- All metadata-query statuses are successful or explicitly `N/A`.
- EA size is zero.
- No named streams. The unnamed `::$DATA` stream is permitted only where the completed scan confirms its observed representation.
- Owner is the current user and group equals the stage-probe group.
- Raw descriptor, SDDL and protection flag agree.
- `Get-DaclPlan` accepts the DACL.
- Attribute bits agree with kind and the supported mask.
- Credential-store names are refused before content is opened.

Additionally:

- Directory: case flags exactly zero for the minimal route.
- Regular file: link count one, within 4 MiB, hash present.
- LX leaf: link count one, native length zero, tag exactly `0xA000001D`, version exactly 2, and raw buffer valid.
- Any other reparse tag or node kind stops the generation before source copying begins.

\### Raw LX length validation

Both capture and restore must require:

1. Returned raw byte count is within the bounded buffer and at least 13 bytes for a nonempty target.
2. Header tag equals `0xA000001D`.
3. `ReparseDataLength == rawLength - 8`.
4. Reserved field is zero.
5. Version is exactly 2.
6. Bytes from offset 12 through the exact returned length decode as strict UTF-8, contain no NUL, and are nonempty.
7. Manifest length equals decoded base64 length.
8. Manifest SHA-256 equals the exact decoded raw bytes.
9. After `FSCTL_SET_REPARSE_POINT`, `FSCTL_GET_REPARSE_POINT` returns the same byte count and byte sequence.

The restorer authors from `rawReparseBase64`, never from `decodedTarget`.

\## Metadata and DACL ordering

Use this order:

- Directory: create → establish/validate DACL → create descendants → bottom-up times/attributes.
- Regular file: create/write/flush → explicit or protected DACL if needed → times/attributes → inspect and compare.
- LX leaf: create empty → set raw reparse buffer → exact raw readback → explicit or protected DACL if needed → times/attributes through a no-follow handle → inspect and compare.

Attributes are last so a captured read-only bit cannot interfere with payload, security or reparse writes.

For `inherited` mode, do not call a DACL setter. Exact inheritance is part of verification.

\## Inherited ACL envelope and links

The current envelope model remains applicable to links:

- The recovery/restore envelope is created empty and receives the projected parent DACL before the AIT25 root exists.
- A link begins as a create-new empty file under its restored parent. Converting that same object into an LX reparse point does not deliberately replace its DACL.
- An `inherited` link must therefore acquire its DACL solely through normal file inheritance; its final owner/group/DACL bytes must equal the manifest.
- An unprotected `explicit` link receives only its recorded explicit ACEs through the no-follow handle; Windows supplies inherited ACEs from the already-finalized parent. Exact final bytes are then checked.
- A `protected` link receives its explicit protected DACL, with no inherited ACEs.

The existing security-shape gate remains unchanged for links: allow/deny ACEs only, supported inheritance flags only, explicit ACEs before inherited ACEs, no inherited ACEs in a protected DACL, no creator/owner placeholder SIDs, and a non-inherit-only current-user Full Access ACE. Owner/group incompatibility or any rejected DACL shape stops before source copying.

\## Directory-size comparison semantics

Use two explicit profiles:

- `same-object`: includes object ID and native directory size. Apply to S0→copy-time source reopen, S0→S1, and recovery-before→recovery-after.
- `fidelity-copy`: excludes object ID and excludes native directory size for directories. Apply to S0→R, manifest→recovery, manifest→restore and R→D.

Regular-file sizes and LX zero length remain mandatory in both profiles. This carries forward the accepted cold-test correction without weakening same-object drift detection.

\## Decision boundary after the full scan

Routine patches within this engine, if the scan is otherwise clean:

- Increased bounds/timeouts.
- Class-18 IDs and structured stream records.
- Raw LX GET/SET and strict buffer validation.
- Handle-based DACL setter.
- Expanded manifest/parser/comparison profiles.
- Zero-valued EA/case/named-stream recording.
- A separately tested class-23 setter if nonzero case flags occur without case-colliding paths.

A different preservation engine or separately reviewed subsystem is required for:

- Any nonzero EA: exact `NtQueryEaFile`/`NtSetEaFile` serialization.
- Any named stream: bounded stream-content capture/restoration.
- Hardlinks: topology manifest plus hardlink creation.
- Non-LX or mixed-version reparses.
- Owner/group reassignment or DACL forms outside the current gate.
- Case-colliding paths or case-sensitive-directory semantics beyond a proven simple setter.
- A manifest too large for the bounded PowerShell JSON path, requiring streaming serialization/parsing.
- Any feature whose metadata query remains unknown.

Persistent S0/S1 drift blocks a generation but does not require another engine. SACL remains deliberately unknown and prevents a claim of complete auditing-policy preservation.
