\## Root cause (established by the boss with a live reproduction; do not re-investigate)

Symptom: opening Atlas shows the window, then within ~20 s Windows marks the window "not responding"
(IsHungAppWindow = True on the desktop python process); the worker child is healthy; stderr shows one line
`[pywebview] Error while processing window.native.AccessibilityObject.Bounds.Empty.Empty.Empty...` (RecursionError).

Cause: pywebview 6.2.1 `webview/util.py:inject_pywebview.get_functions()` walks `dir()` of the `js_api` object
recursively for EVERY public, non-callable attribute that has `__module__`, using `id()` to de-duplicate. Commit
7bde3fb (frameless title bar) gave `WindowApi` a public attribute `window` and `run()` sets
`window_api.window = window` BEFORE `start()`. So the injection walk descends `window` -> `window.native`
(WinForms Form, via pythonnet) -> `AccessibilityObject` -> `Bounds` -> `Empty` -> `Empty` ... : every CLR struct
access boxes a fresh object (new id), so the de-dup never trips and the walk recurses to RecursionError, then keeps
enumerating the whole CLR object graph on the GUI thread. The window hangs.

Only public attributes are walked (`name.startswith('_')` is skipped; `_serializable = False` is also honored).
