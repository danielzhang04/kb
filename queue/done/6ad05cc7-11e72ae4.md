\### Exact rollback contract

Rollback should require the writer freeze to remain active and then:

1. Determine rename state from source/destination presence plus the pinned root volume/file ID.
2. Refuse if the old path is occupied, both paths exist, both are absent, the destination root identity changed, or either path contains a reparse point.
3. Capture all destination changes since the frozen checkpoint into a new retained recovery generation.
4. Restore editor preimages only by compare-and-swap against the exact postimage and original file identity.
5. If any editor file or other existing object has unknown changes, stop with the destination in place; do not overwrite or reverse-rename.
6. If only safe states remain, rename the whole destination root back without replacement. Added files move back with it and are therefore preserved.
7. Verify root identity, complete tree, security descriptors, restored editor hashes, old-path availability, and destination absence. Never restore the older backup over the live tree.

\### Indispensable synthetic negatives

- Destination collision and old-path rollback collision.

- Newer editor bytes or changed file identity after lease loss; rollback must preserve and stop.
- Source addition/modification between final capture and rename; abort before rename.
- Different source/destination parent DACL/SACL fixture: prove same-volume rename preserves the root descriptor and identity, then prove ordinary future-child inheritance/access without ACL normalization.

Recovery manifest traversal/tamper coverage, the peg oracle, and the old `.NET` ACE-order failure do not need another full rerun.
