\## Defects (reviewer numbering)
1. HIGH — run session records never leave `live`: `observeExit` (sessionRecord.ts:309) is called only
   from the registry's own manual paths; the attempt adapter owns its sink (`:909`) and calls
   `options.recorder.exit` + `host.close` (`:1290`) without telling the registry. Consequences:
   retention (`sessionPersistence.ts:358`) can evict only exited/abandoned rows → after
   MAX_RETAINED_SESSIONS=500 attempt sessions EVERY pty mutate throws `capacity` (bricks attempts AND
   browser terminals); `projectAttemptSessions` shows finished attempts as live/claimable. Fix: add
   `recordExit(sessionId, exit, epochId)` (or similar) to `SessionRecordRegistry` delegating to
   `observeExit`; call it from the adapter's `sink.exit` and after `closeAttempt` resolves, guarded by
   `sessionRecordPersisted` (buffer an exit that arrives before persistence and apply it after the
   flush). Test: after the fake host's exit, the row is `exited` with the exit code; retention can
   evict it; projection shows it not live.
2. HIGH — restart retirement unreachable: `retireable` (sessionRecord.ts:799-820) needs prior rows
   `abandoned`/`exited`; (a) rows never exit (fix 1); (b) `abandonEpoch`/`applyEpochAbandonment` have
   ZERO production callers — only the integration test hand-calls it. Fix: on daemon boot, when the
   broker's `ready.epochId` (or the boot-time capability's epoch) differs from the epoch persisted in
   the pty document, call `abandonEpoch(previousEpochId, 'daemon-restart')` BEFORE any attempt can
   begin; wire it in `http/surface.ts` (or wherever the registry + capability meet at boot) and persist
   the current epoch in the document if it is not already. Test: a persistence document from a prior
   epoch + a fresh surface/adapter boot → rows abandoned automatically, then a replayed `begin` retires
   and succeeds WITHOUT the test calling `applyEpochAbandonment` itself. Keep the direct-call test too.
3. HIGH — early-frame flush race (`attemptSessionAdapter.ts:1146-1152`): `sessionRecordPersisted = true`
   is set BEFORE the `await`-ing flush loop, so a live frame during the flush jumps the queue, advances
   `lastSequence`, and every remaining buffered frame is dropped while `retention.append` already wrote
   the live bytes → `.raw` and the cursor diverge. Fix: keep buffering until the flush loop drains
   (`while (earlyFrames.length) await recordData(earlyFrames.shift())`), set the flag after, and make
   `recordData` for live frames go through the same ordered queue. Test: a frame injected DURING the
   flush (use a deferred inside the fake recorder/persistence) still lands in order; `.raw` bytes ==
   concatenation of all frames; cursor == last sequence.
4. MED — retirement orphans the pre-restart transcript: deleting the retired binding removes the only
   join (`runProjection.ts:94`, `runPtyRoutes.ts:108`). Fix: keep a retired binding marked
   `retired: true` (or a separate `retiredBindings` list — pick the smaller change to the document
   validator) so the projection can still list the old session as history and the raw route can serve
   its `.raw`; adjust the uniqueness invariant accordingly. Test: after retirement the old session is
   still listed for the run with state `abandoned` and its transcript readable.
5. MED — legacy cancel: `execution.ts:1017` throws when `attemptOperationKey` is null (sessions created
   before this release); the throw is swallowed and the worker keeps running. Fix: fallback
   `input.attemptOperationKey ?? workerAttemptOperationKey(...)` using the SAME derivation helper
   (still single-sourced). Test: a stored session with null key cancels the live attempt.
6. MED — display name truncated but not sanitized: `boundedText(name,80)` rejects `UNSAFE_TEXT_RE`
   chars (tab/newline/DEL/bidi) and empty; proposal titles allow them. Fix: replace UNSAFE_TEXT_RE
   matches with spaces, collapse, trim, fall back to the launcher name if empty, then byte-truncate.
   Test: a title with tab + bidi mark + 200 chars round-trips.
7. LOW — `store.ts:4933-4936 transitionSession` mutates before validating and a key-only backfill
   returns `invalid`. Fix: validate first, assign after, return ok for a same-state key backfill.
8. LOW — session `operationKey` uniqueness now applies to non-terminal rows only while
   `sessionRecord.ts:431,463` manual replay uses `find` (oldest wins). Fix: prefer the non-terminal row,
   else the newest terminal one; comment why.
9. LOW — `UNKNOWN_SESSION_ID` (`pty-000…`) is passed to `observedExitFailure` where callers might act
   on it. Fix: make the failure shape carry `sessionId: null` where the contract allows, else keep the
   sentinel but assert no caller acts on it (grep and cite).
