\## Literal-rewrite hazards

The harness must explicitly guard against:

- Replacing a matching string in a comment or embedded C# block unintentionally.
- Multiple source-root occurrences with different semantic purposes.
- Changing the capture’s forbidden-source guard without moving it to the synthetic source ancestor.
- Breaking regex escaping or generation/provenance binding.
- BOM or newline normalization changing candidate bytes.
- PowerShell’s case-insensitive variable names, especially `N/n` and `Id/ID`.
- Loading two native classes with the same name in one process.
- A synthetic root long enough to invalidate otherwise-correct production paths.
- Failing to redirect the capture’s restore-script binding, causing it to hash or invoke the production child.
- Treating a successful adapted clone as proof of production fixed-source behavior without the separate production AST checks.

\## Contract issues to settle before code freeze

1. “Manifest last” should explicitly mean the final write under `recovery\`. The external digest, logs, restore subtree, and child report necessarily occur later elsewhere in the generation.

2. The final report/check names and failure categories are not fixed by the contract. The integration oracle should be written against the finalized schema, not guessed while the new files are incomplete.

3. The contract requires strict fixed-source behavior but does not explicitly prohibit `$args`, environment variables, or indirect configuration overrides. The final code and review should make that prohibition explicit; the proposed AST checks enforce it.

4. The manifest-over-4-MiB acceptance needs an actual serialized-size assertion. Merely raising the parser limit or choosing more than 500 entries does not prove the old hashing/readback ceiling was removed.

5. Every negative generation must be separate and create-new. Reusing or mutating a successful generation would conflict with the immutability/no-overwrite requirements and could mask occupied-report behavior.
