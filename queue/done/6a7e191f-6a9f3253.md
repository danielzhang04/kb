\## The defect (observed in production, task-14 of this arc)

`asset_verdict_skeleton` (build_review_artifact.py:391-409) emits a row for EVERY pending asset with
blank verdicts (`""`) and a default `reviewer="fresh-eyes"`, never reading the existing review store.
`--assets <paths>` does not restrict the boarded set to the named assets — every asset the video still
owes a ruling on is boarded too. Consequence: an operator who fills verdicts only for the assets they
named and feeds the skeleton to `stamp_review.py --figures` merges BLANK rows over existing store
records. This actually happened: two documented PARKED-on-pose STEP-1 card records (FAIL verdicts,
provenance prose) were overwritten with blank rows and had to be hand-repaired
(see `.superpowers/sdd/2026-08-11-bricks-taste-forensics/task-14-report.md`, "A defect I introduced
here, and the repair").
