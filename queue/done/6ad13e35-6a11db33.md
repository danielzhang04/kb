\## New restore findings

1. **HIGH — Lexical guards do not guarantee generation confinement against intermediate reparse races.** Native `Open` adds `FILE_FLAG_OPEN_REPARSE_POINT`, but that protects only the final component ([restore.ps1:180-193](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:180)). `Assert-Chain` is a one-time check, while subsequent recovery reads and restore writes use absolute pathnames ([restore.ps1:533-555](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:533), [restore.ps1:1042-1082](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:1042)). A same-user process can replace an already-validated intermediate directory with a junction between checks, causing a recovery read—or worse, a `CREATE_NEW` write—to land outside the generation. `W()` only rechecks the lexical string ([restore.ps1:401-408](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:401)).

   Minimal fix: anchor traversal to retained directory handles and perform component-by-component, handle-relative, no-reparse opens/creates with pinned identities. Rechecking path strings or only final-leaf attributes is insufficient for race-free confinement.

2. **MEDIUM — Recovery identities are never proven distinct from captured source identities.** `$CopyFields` deliberately excludes `sourceId` ([restore.ps1:67-70](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:67)), so manifest-to-recovery comparison cannot detect overlap ([restore.ps1:1037-1040](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:1037)). The final identity check only proves restored identities differ from the union of source and recovery identities ([restore.ps1:1105-1109](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:1105)). A re-pinned manifest whose `sourceId` values equal actual recovery IDs can therefore pass, contrary to the required source/recovery/restore separation.

   Minimal fix: require unique manifest source IDs; require unique recovery IDs; explicitly reject `sourceIds ∩ recoveryIds`; then retain the existing restored-versus-union check.

3. **MEDIUM — `stage-probe.txt` content and stream shape are read but never validated.** Pre-output validation compares only its descriptor ([restore.ps1:1035-1036](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:1035)). Post-write verification likewise checks only security ([restore.ps1:1050-1053](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:1050)). A probe with changed bytes, an unexpected named stream, attributes, or length can pass; the child then writes the built-in constant and can report successful complete-recovery verification.

   Minimal fix: before output, require a plain, single-link file with exactly `::$DATA`, exact `$ProbeBytes` length/content, supported attributes, and no named streams. Perform the same exact readback after writing.

4. **MEDIUM — Unsupported envelope/probe ownership and access can be discovered only after restore output begins.** Manifest validation checks descriptor syntax and selected cross-fields but does not require the envelope and probe owners/groups to equal `$Me`/`$GroupSid`, nor require `$accessSddl` to grant the restoring user effective Full Access ([restore.ps1:901-913](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:901)). Those incompatibilities are detected only after `restore\` and its envelope have been created and the DACL applied ([restore.ps1:1045-1053](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:1045)). Thus a manifest/recovery pair can pass “entire recovery validated” and then leave partial output.

   Minimal fix: preflight the envelope and probe raw descriptors for exact owner, group, protection flags, DACL relationship, and current-user effective access before line 1045. Bind `accessSddl` to the access portion of `freshParentSddl`, not merely to `envelopeAccessSddl`.

5. **MEDIUM — Exact key validation happens after a JSON parser that loses duplicate-property evidence.** `ConvertFrom-Json` runs first ([restore.ps1:875-876](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:875)); `Assert-Keys` then sees only the resulting object ([restore.ps1:778-783](C:/Users/danie/Projects/Filesystem-Cleanup/reports/v1-retained-ait25-provisional-restore.ps1:778)).    Minimal fix: use a bounded duplicate-aware JSON tokenizer/parser before object materialization, rejecting every repeated property name ordinally at every object depth.
