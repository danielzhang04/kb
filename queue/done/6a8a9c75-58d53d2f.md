## Result

Verdict: **REWORK**

\### Blockers

- **The 8-per-principal ceiling is disabled by default.** `principalKey` is optional and omitted sessions become `principal = null`, bypassing principal accounting: `dashboard/server/pty/windowsSessionHost.ts:63,169-174,315-318`. `SessionHostRequest` contains no principal: `dashboard/server/pty/contracts.ts:82-83`. Make principal identity mandatory and server-owned; test the non-injected production path.
- **File identity is checked only after execution begins.** Spawn occurs at `windowsSessionHost.ts:383-393`; `pinned.recheck()` occurs at `403`. A mismatched executable can run before refusal. Recheck immediately before spawn, retain pins across spawn, and assert a mismatch leaves spawn count zero.
- **Process-tree close can hang or orphan descendants.** `taskkill` resolves regardless of exit code at `windowsSessionHost.ts:127-139`; thrown failures fall back to direct `child.kill()` at `279-282`, and post-spawn failure cleanup also kills only the direct child at `421-427`. Reject nonzero `taskkill`, use the tree closer on every failure path, and test with a grandchild.
- **The public probe can advertise an unusable host.** Launcher probing checks only path accessibility at `dashboard/server/pty/probe.ts:33-48`; root validation is optional at `73`; the host supplies none at `windowsSessionHost.ts:289`. Unsafe ACLs, reparse roots, or bad shim identities can still return `pty:true`. Probe using the same root/ACL/file-ID policy as launch.

\### Majors

- **Safe roots are caller-controlled absolute strings.** `windowsSessionHost.ts:52,267,294` and `launcherProfiles.ts:84-89,210-217` accept UNC/device roots and 8.3 aliases; only relative cwd syntax is constrained. Pin roots to approved local canonical paths and reject UNC, device namespace, and short-name aliases.
- **Backpressure is not measured at the sink.** Bytes are decremented before synchronous `sink.data()` at `windowsSessionHost.ts:248-259`. A slow downstream sink can buffer without limit, while a slow transcript can incorrectly detach every otherwise-fast sink. Add per-sink completion-aware queues.
- **Post-spawn exits are sometimes fabricated.** Cancellation and error paths call `finalize(..., null, null)` at `windowsSessionHost.ts:394-400,421-428`, resolve the exit promise, and suppress the later real `node-pty` exit. After spawn, terminal state must come from the observed process exit.
- **Exited sessions retain resources indefinitely.** `sessions`, `operations`, child references, listeners, and attachment sinks are retained after `finalize`: `windowsSessionHost.ts:208-223,226-263,351-352`. Dispose listeners and release heavy references while retaining only required idempotency metadata.
- **The tree-kill helper inherits the full dashboard environment.** `spawnChildProcess` has no explicit `env` at `windowsSessionHost.ts:127-139`. Pass a fresh minimal helper environment.
- **The required environment suite is absent.** `dashboard/server/control/childEnv.test.ts` does not exist despite `docs/plans/2026-08-22-dv3-p3-plan.md:325`. The checkpoint silently ran four files. The only new coverage checks two names at `launcherProfiles.test.ts:46-55`; add deny-fragment and allowlist-backstop coverage and make the gate fail on missing files.

\### Minors

- `HostStartReceipt` is imported but redeclared inline at `windowsSessionHost.ts:8,354-357`; use the W0 type directly.
- Probe callback exceptions are misreported as `node-pty-unavailable`: `probe.ts:90-91`.
- The real PTY test has a timeout but no `finally` cleanup if an assertion/regression leaves the child alive: `windowsSessionHost.test.ts:59-78`.
