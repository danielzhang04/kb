\## Why (architecture review verdict)
Four review rounds each found three new defects because the attempt-start vertical has two writers of
one durable truth (`sessions`/`attemptBindings`/`attemptOperations`/`operationReceipts`) written in two
phases with an ordering contract between them, two cursor semantics (hosts count frames, the transcript
API expects byte offsets), and exit observed in the adapter but recorded in the registry. This round
removes those three tensions by construction. Behaviour the reviewers already confirmed (identity
replay, retirement, op-key token, name sanitizer, legacy cancel fallback, lazy epoch activation, boot
never touching the host) must be preserved — move it, do not re-derive it.

\## Changes (do all)
S1. **The registry owns the start.** Add to `SessionRecordRegistry` (`pty/sessionRecord.ts`,
    contract in `pty/contracts.ts`):
    `startRunSession(input: { declaration identity (operator, runRef, attemptRef, managedSessionRef),
    hostOperationKey, requestHash, recipe, rootId, relativeCwd, size, displayName, sink }) →
    PortResult<{ sessionId, epochId, outputCursor, replayed, documentRevision }>`.
    It performs `host.create` with the registry's OWN sink wrapper (so every data/exit frame passes
    through the registry first — see S2/S3), then in ONE `mutate` writes the session row, the binding,
    the receipt, and the `attemptOperations` transition from `pending` to `bound` (today the adapter CASes
    that separately — fold it in; keep the write-ahead `pending` CAS BEFORE the host call as the
    idempotency guard, it is correct). Identity replay, epoch activation (`activateEpoch` on the receipt's
    epochId), retirement of prior abandoned/exited rows, and the live-collision refusal all move inside
    this method unchanged in behaviour. On any failure after `host.create` succeeded, the registry itself
    closes the host session and records a terminal exit BEFORE returning the refusal (no rollback ladder
    in the adapter).
    In `control/attemptSessionAdapter.ts`: `begin` now = fingerprint → write-ahead `pending` CAS →
    `sessionRecords.startRunSession(...)` → prompts → result. Delete the adapter's `persistRunSession`
    call, the `bind` call, the early-frame buffer (S2 makes it unnecessary), `sessionRecordPersisted`,
    and the rollback ladder for the start phase. Delete `bind()` from the attempt path; keep it only if
    another production caller exists (grep; if none, remove it and its contract entry, and adjust tests
    as CONTRACT CHANGES, saying so).
S2. **One cursor space, minted once.** The registry's sink wrapper converts host frames to byte offsets
    (`inCursorSpace`) at the single entry point for BOTH manual and run sessions; no consumer downstream
    re-interprets `sequence`. Because the registry installs its sink before the host receipt resolves,
    early frames are recorded in order without an adapter-side buffer (verify: if `host.create`'s
    receipt can resolve after frames start flowing, the registry must queue them itself until the row
    exists inside the same start call — implement that queue in the registry, bounded, with the same
    overflow log). Rename `HostStartReceipt.revision` → `outputSequence` (`contracts.ts`,
    `linuxBrokerClient.ts`, `windowsSessionHost.ts`, all readers) so a frame counter can never be handed
    to a document CAS again.
S3. **One exit recorder.** The registry sink records every exit (host exit frame, close ack, refused
    close → terminal non-abandoned reason with detail, broker disconnect → abandoned via epoch/abandon
    path). The adapter observes exits only through the receipt/promise the registry hands back
    (`HostLaunch.exit` equivalent) and never calls `recordExit` itself. `applyObservedSessionExit` keeps
    rejecting `reason:'abandoned'` for run rows; abandonment flows only through epoch activation.
S4. **Leak fix:** `linuxBrokerClient.ts:136-142` — when `create` succeeded but the follow-up `attach`
    fails, close the created session on the broker before resolving the failure (else it counts toward
    the 16-session cap forever).
S5. **Tests:** update `attemptVertical.integration.test.ts` and `attemptSessionAdapter.test.ts` for the
    new shape (classify every edit contract-change/restoration/repoint in the report); both fake hosts
    count frames (`outputSequence += 1`); add a registry-level test for `startRunSession` covering
